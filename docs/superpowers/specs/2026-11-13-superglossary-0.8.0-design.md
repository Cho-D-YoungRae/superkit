# superglossary 0.8.0 설계

상태: 대화에서 항목별 합의 후 구현 요청됨. Claude 원본과 Codex 전환본을 함께 개선한다.

## 목적과 범위

실사용에서 드러난 문맥별 다의어, 큰 용어집의 전체 읽기, 사전 변경의 기존 코드 영향 누락을 보완한다. Markdown 직접 관리와 두 스킬(glossary/check), 생성용 scanner 구조를 유지한다. 버전은 두 패키지 모두 0.8.0이다.

구버전 호환·자동 마이그레이션은 제공하지 않는다. 설치·게시·태그·사용 프로젝트 수정은 이번 구현에 포함하지 않는다. 사용자는 버전 업데이트 후 이 세션에서 사용 프로젝트에 반영할 예정이다.

## 검토한 접근과 결정

- 문맥 전용 열을 추가하는 방법과 설명 열을 쓰는 방법 중, 기존 `한글 | 영문 | 축약 | 금지 | 설명`을 유지하고 필요한 의미·용도·예외만 설명에 짧게 적는다.
- 도메인 분리를 먼저 강제하는 방법과 검색 우선 읽기 중, 원문 검색 후 관련 행을 읽는다. 300개 초과 분리는 사용자에게 제안만 한다. Markdown 파서·영속 색인·런타임 스크립트는 추가하지 않는다.
- 커밋 당시 사전을 재현하는 방법은 채택하지 않는다. 코드 범위와 무관하게 현재 작업 트리 사전을 기준으로 검사하며 사전 변경에 따른 기존 코드도 검토한다.
- 약어 자체를 영문에 넣는 방법은 채택하지 않는다. 기본 영문과 허용 축약을 각 열에 구분한다.
- 평가는 `evals/superglossary/`에 두며 양쪽 설치 패키지에 포함하거나 런타임에서 참조하지 않는다.

## 업무 규칙

### 의미와 충돌

같은 의미는 기존 항목을 재사용한다. 표기가 겹쳐도 의미가 다르거나 용도별 표준이 이미 명시되어 있으면 별도로 등록할 수 있다. 경로·모듈이 다르다는 사실만으로 개념을 나누지 않는다. 같은 의미·적용 범위의 다른 표기, 적용 범위가 겹치는 표준/금지 결정은 충돌이다. 기존 지침으로 구분할 수 없으면 확인 필요로 남기며 임의로 금지 예외를 만들지 않는다.

금지는 해당 행의 의미·용도에만 적용한다. 예: 토큰 발급 grant의 금지 issue는 issueToken에 적용하고, 증권 발행 issue에는 적용하지 않는다. issuedAt처럼 이미 합의된 예외는 설명에 명시한다. scanner도 같은 의미·용도인 경우에만 혼용으로 묶는다.

### 영문과 축약

영문은 기본 표기, 축약은 허용된 줄임말이다. 예: investorRelations/ir, chiefExecutiveOfficer/ceo. 양쪽 모두 허용하되 특정 이름에서의 선호·제한이 있으면 설명을 따른다. 약어가 있다는 이유만으로 모든 이름에 약어를 강제하지 않는다. 표준 약어가 있는 합성 개념은 한 항목으로 등록할 수 있지만 풀어 쓴 영문과 축약은 구분한다.

### 읽기

규칙·도메인 인덱스를 먼저 읽고, 작업 대상 이름·개념을 정한 뒤 사전 전체를 검색한다. 한글 의미, 영문·축약·금지, 활용형·문맥상 대체 표기를 함께 고려한다. 검색된 행은 설명까지 확인하며, 충분히 출력된 행을 다시 읽을 필요는 없다. 검색 0건만으로 미등록을 확정하지 않고 관련 구간/도메인으로 확장한다. 잘린 결과는 이어 읽고, 실패·불명확한 부분은 미검토/확인 필요로 보고한다. 전체 정리·분리는 구간별로 전체를 확인한다.

### check 범위

항상 현재 작업 트리 사전·인덱스·도메인 파일을 사용한다. 기본 검사는 staged/unstaged/untracked를 합치되 양쪽 diff를 각각 보존한다. 경로 인자는 현재 파일 전체, 커밋 범위는 해당 diff 및 종료 리비전의 코드를 대상으로 한다. 잘못된 범위를 기본 범위로 바꾸지 않는다.

사전의 표준·축약·금지·의미/용도/명시적 예외가 바뀌면 이전/현재 행에서 관련 표기를 찾아 현재 프로젝트의 기존 코드까지 영향을 검사한다. 작업 트리의 사전 변경은 인자 종류와 무관하게 확인하고, 커밋 범위에서는 그 범위의 사전 변경도 함께 고려한다. 코드는 지정 범위 밖이어도 영향을 받으면 보고하되 현재 사전으로 판정한다. 기존 관례가 명시적인 사전 표준이나 금지 결정을 무효화하지 않는다. 문법·서식만 바뀐 사전 diff는 의미 변경으로 취급하지 않는다.

사전 전체 삭제·자료 부재·이전 버전 읽기 실패를 정상 결과로 숨기지 않는다. 사전만 바뀌었을 때도 검사할 변경이 없다고 조기 종료하지 않는다. 삭제된 항목의 옛 표기는 현재 남은 규칙에 따라 판단하며 삭제만으로 위반을 만들지 않는다. 검사 결과는 위반, 추가 후보, 확인 필요, 미검토를 구별하고 실제 검토한 코드/사전 기준을 짧게 보고한다. check는 코드·사전을 수정하지 않는다.

## 배포와 검증

Claude 원본 변경도 Codex CI를 실행한다. 업무 규칙·버전은 두 패키지에 함께 반영하고 Codex 고유의 리소스 해석·scanner 위임·읽기 전용 지침은 보존한다. 변경 전 기준 상태를 비교하고, 검증 및 독립 리뷰 후 전환 상태를 갱신한다.

평가 사례는 의미 중복, 문맥별 금지, 영문/축약, 현재 사전과 기존 코드 영향, 큰 사전 선택 읽기, 잘림/읽기 실패를 포함한다. 파일의 문구 존재 검사만으로 행동 평가를 대체하지 않는다. 도구 추적과 실제 결과를 남기고 Claude/Codex 네이티브 실행 여부와 대리 하네스 검증을 구별한다.

## 구현자 결정

예제 프로젝트 언어·평가 실행 명령과 기록 형식, 지침의 세부 배치는 기존 구조에 맞춰 정한다. 새로운 서비스·의존성·설정 형식은 도입하지 않는다. 기존 사용자 데이터의 정리는 후속 프로젝트 반영 시 별도로 수행한다.
