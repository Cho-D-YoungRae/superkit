# 용어 사전 관리

`docs/superglossary/`의 md 표에 이름에 쓰는 단어를 모은다. 사람과 Codex가 같은 단어로 이름을 짓게 하는 것이 목적이다. 같은 개념이 claim·billing·charge처럼 매번 다르게 번역되는 일을 막는다.

형식, 등록 규칙, 분리 절차는 [glossary-guide.md](glossary-guide.md)에 있다. 처음 쓰거나, 사전을 만들거나 나누거나, 합성어를 한 항목으로 둘지 판단할 때 읽는다.

입력은 사용자의 용어 또는 요청이다. 별도 인자가 없으면 현재 이름 짓기 작업에서 필요한 용어를 대상으로 한다. 플랫폼 전용 인자 변수의 자동 치환을 기대하지 않는다. 패키지 리소스는 현재 제공된 이 SKILL.md의 실제 위치를 기준으로 찾는다. 사용자 확인이 필요한 단계는 세션의 질문 도구나 대화로 답을 받은 뒤 진행한다.

## 1. 찾기

기준 디렉터리는 git 루트다(`git rev-parse --show-toplevel`). git 저장소가 아니면 현재 디렉터리를 기준으로 삼는다.

- `docs/superglossary/glossary.md`를 읽는다. 없으면, 사용자가 용어집을 만들어 달라고 했을 때는 4. 생성으로 간다. 이름을 짓다가 불린 것이면 만들기 전에 이 프로젝트에 용어 사전을 둘지 묻는다 — 사전을 쓰지 않는 프로젝트에 파일이 말없이 생기지 않게 하기 위해서다.
- `## 도메인` 표(index)가 있으면 분리된 사전이다. 지금 다루는 파일 경로가 맞는 `코드 범위`의 도메인 파일과 `## 공통 용어`를 함께 읽는다.

## 2. 추가

1. **분해**: 필요한 이름을 단어로 나눈다. 나누는 기준은 영문이다 — 합성어의 영문이 부분 영문의 조합과 같으면 나누고, 다르면(업계 용어·표준 약어·영문 한 단어) 합성어를 한 항목으로 둔다. 예: 체결수량 → 체결 + 수량, 매도호가 → ask.
2. **재사용**: 사전에 이미 있는 단어는 다시 넣지 않고 조합해 쓴다. 모두 있으면 아무것도 추가하지 않는다.
3. **충돌 확인**: 한글·영문·축약이 기존 항목과 겹치거나 다른 항목의 금지 단어와 겹치면 등록하지 않고 기존 항목을 보여 준다. 분리된 사전이면 `docs/superglossary/` 전체에서 찾는다.
4. **확정**: 단어별 등록은 바로 한다. 합성어를 한 항목으로 두는 예외는 근거를 들어 사용자 확인을 받은 뒤 등록한다.
5. **쓰기**: 맞는 파일의 표에 한글 가나다순 위치로 행을 넣는다. 분리된 사전이면 코드 범위가 맞는 도메인 파일에, 여러 도메인이 쓸 단어면 공통 용어에 넣는다.
6. **알림**: 작업 중에 스스로 추가했으면, 작업을 이어 가기 전에 한 줄로 알린다 — `용어 등록: 체결 → execution, 수량 → quantity`.
7. **분리 제안**: 추가한 뒤 용어가 300개를 넘으면 도메인별 분리를 제안한다. 사용자가 동의할 때만 guide의 분리 절차를 따른다.

## 3. 수정·삭제

사용자가 요청할 때만 한다. 영문을 바꾸면 옛 영문을 금지 열에 넣을지 묻는다 — 기존 코드에 옛 이름이 남아 있어 check가 찾아낼 수 있게 하기 위해서다. 바꾼 뒤에도 충돌 확인을 한다.

## 4. 생성

1. guide의 "분리 전" 템플릿으로 `docs/superglossary/glossary.md`를 만든다.
2. 코드가 이미 있으면 기존 이름에서 용어를 찾아볼지 묻는다. 동의하면 [스캐너 실행 계약](references/scanner-dispatch.md)에 따라 [glossary-scanner](references/glossary-scanner.md)를 새 컨텍스트의 서브에이전트로 실행한다. 역할·기준 문서의 절대 경로와 프로젝트 루트·용어집 경로만 전달하고 세션 대화는 넘기지 않는다. 모델은 현재 Codex 세션 설정을 상속한다. 자동 등록된 custom agent 이름처럼 호출하지 않는다. 스캐너를 실행할 수 없거나 일부 자료를 읽지 못하면 범위와 이유를 알리고 미완료로 남긴다. 빈 결과나 메인 세션의 자기 검토를 성공한 스캔으로 대신하지 않는다.

3. scanner가 돌려준 후보와 혼용 리포트를 보여 주고, 사용자가 고른 것을 등록한다. 혼용 건은 사용자가 표준 하나를 고르고, 나머지 변형은 그 행의 금지 열에 둔다.
4. 지침 파일에 아래 포인터 줄이 없으면 넣을지 묻고, 동의하면 넣는다.

   ```
   - 용어 사전: docs/superglossary/glossary.md (이름을 짓기 전에 읽는다. 없는 단어는 $superglossary:glossary로 추가한다)
   ```

   대상은 프로젝트 루트의 `AGENTS.md`다. 먼저 프로젝트 지침과 기존 `CLAUDE.md`·`.claude/CLAUDE.md`·`CLAUDE.local.md`도 확인한다. 저장소의 지침 파일 정책에 따라 기존 CLAUDE 계열 파일이 있으면 그 파일을 사용한다. 후보가 여러 개여서 대상이 불명확하면 사용자에게 확인한다. Codex가 CLAUDE 계열 파일을 자동으로 읽는다고 가정하지 말고, 그 파일에 썼다면 다음 세션에서 명시적으로 읽도록 안내한다. CLAUDE 계열 파일을 새로 만들지 않는다. 대상 파일이 없으면 만들지 않고 줄을 제안만 한다. `@import`는 쓰지 않는다.

   같은 용어집을 가리키는 기존 포인터는 Claude 호출 표기여도 중복 추가하지 않는다. Codex 호출 표기로 바꾸려면 그 변경도 먼저 확인받는다.

## 하지 않는 것

- 코드의 기존 이름을 바꾸지 않는다. 사전과 다른 이름은 check가 보고하고, 바꿀지는 사용자가 정한다.
- 사용자 확인 없이 사전을 새로 만들거나, 지침 파일을 고치거나, 사전을 나누지 않는다.
