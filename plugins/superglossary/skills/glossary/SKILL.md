# 용어 사전 관리

`docs/superglossary/`의 md 표에 이름에 쓰는 단어를 모은다. 사람과 Claude가 같은 단어로 이름을 짓게 하는 것이 목적이다. 같은 개념이 claim·billing·charge처럼 매번 다르게 번역되는 일을 막는다.

형식, 필요한 부분 읽기, 등록 규칙, 분리 절차는 `${CLAUDE_SKILL_DIR}/glossary-guide.md`에 있다. 이 세션에서 처음 사용할 때 읽고 이후에도 판단에 필요한 절을 참고한다.

## 1. 찾기

기준 디렉터리는 git 루트다(`git rev-parse --show-toplevel`). git 저장소가 아니면 현재 디렉터리를 기준으로 삼는다.

- `docs/superglossary/glossary.md`가 없으면, 사용자가 용어집을 만들어 달라고 했을 때는 4. 생성으로 간다. 이름을 짓다가 불린 것이면 만들기 전에 이 프로젝트에 용어 사전을 둘지 묻는다.
- guide의 "필요한 부분 읽기"를 따른다. 머리말·규칙·도메인 인덱스를 먼저 읽고 필요한 개념을 사전 전체에서 Grep으로 검색한다. 관련 행의 설명까지 확인하고, 부족하면 구간별 Read로 넓힌다. 검색 0건·잘린 결과를 미등록의 근거로 삼지 않는다. 별도 Markdown 파서·색인은 만들지 않는다.

## 2. 추가

1. **분해**: 필요한 이름을 단어로 나눈다. 영문이 부분 영문의 조합과 다르거나 전체 개념의 통용 약어가 있으면 한 항목 예외 후보로 본다. 예: 체결수량 → 체결 + 수량, 매도호가 → ask. 기본 영문과 허용 약어는 각각 영문·축약 열에 적는다.
2. **재사용**: 같은 의미의 기존 항목을 조합해 쓴다. 같은 표기라도 다른 의미인지 설명을 확인한다. 경로가 다르다는 이유만으로 항목을 늘리지 않는다.
3. **충돌 확인**: guide의 충돌 표에 따라 사전 전체의 한글·영문·축약·금지와 설명을 대조한다. 표기 중복만으로 거부하지 않는다. 같은 의미·용도의 다른 표기나 적용 범위가 겹치는 표준/금지 결정이면 보류하고 기존 항목을 보여 준다. 의미나 범위가 불명확하면 확인받는다.
4. **확정**: 단어별 등록은 바로 한다. 합성어를 한 항목으로 두는 예외는 근거를 들어 사용자 확인을 받은 뒤 등록한다.
5. **쓰기**: 맞는 파일의 표에 한글 가나다순 위치로 행을 넣는다. 분리된 사전이면 코드 범위가 맞는 도메인 파일에, 여러 도메인이 쓸 단어면 공통 용어에 넣는다.
6. **알림**: 작업 중에 스스로 추가했으면, 작업을 이어 가기 전에 한 줄로 알린다 — `용어 등록: 체결 → execution, 수량 → quantity`.
7. **분리 제안**: 추가한 뒤 용어가 300개를 넘으면 도메인별 분리를 제안한다. 사용자가 동의할 때만 guide의 분리 절차를 따른다.

## 3. 수정·삭제

사용자가 요청할 때만 한다. 변경안을 먼저 충돌 검사하고 승인된 내용을 쓴 뒤 결과를 확인한다. 영문을 바꾸면 옛 영문을 해당 의미의 금지 열에 넣을지 묻는다. 이미 정한 내용은 다시 묻지 않는다. 표준·축약·금지 또는 설명의 의미·용도·예외가 바뀌면 이전/현재 표기와 범위를 짧게 알리고 `/superglossary:check`로 기존 코드의 영향도 확인하도록 안내한다. 기존 이름을 자동으로 바꾸지 않는다.

## 4. 생성

1. guide의 "분리 전" 템플릿으로 `docs/superglossary/glossary.md`를 만든다.
2. 코드가 이미 있으면 기존 이름에서 용어를 찾아볼지 묻는다. 동의하면 Agent 도구로 `superglossary:glossary-scanner`를 부른다. `model`은 지정하지 않는다(에이전트 파일에 정해져 있다). 세션 대화는 넘기지 않고 아래만 넘긴다.

   ```
   프로젝트 루트: <절대 경로>
   용어집: <절대 경로>/docs/superglossary/glossary.md
   기준 문서: ${CLAUDE_SKILL_DIR}/glossary-guide.md
   ```

3. scanner가 돌려준 후보와 혼용 리포트를 보여 주고, 사용자가 고른 것을 등록한다. 같은 의미·용도의 혼용에만 표준 하나를 고르고 나머지 변형을 그 행의 금지 열에 둔다. 다른 의미는 설명으로 구분하고, 금지 적용이 불명확하면 확인받는다.
4. 지침 파일에 아래 포인터 줄이 없으면 넣을지 묻고, 동의하면 넣는다.

   ```
   - 용어 사전: docs/superglossary/glossary.md (이름을 짓기 전에 읽는다. 없는 단어는 /superglossary:glossary로 추가한다)
   ```

   대상은 프로젝트 루트의 `AGENTS.md`다. 루트에 `CLAUDE.md`·`.claude/CLAUDE.md`·`CLAUDE.local.md` 중 하나라도 있으면 그 파일이다(그때 Claude Code는 `AGENTS.md`를 읽지 않는다). 대상 파일이 없으면 만들지 않고 줄을 제안만 한다. `@import`는 쓰지 않는다 — 매 세션 사전 전체를 불러오기 때문이다.

## 하지 않는 것

- 코드의 기존 이름을 바꾸지 않는다. 사전과 다른 이름은 check가 보고하고, 바꿀지는 사용자가 정한다.
- 사용자 확인 없이 사전을 새로 만들거나, 지침 파일을 고치거나, 사전을 나누지 않는다.
