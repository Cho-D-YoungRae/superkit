# 용어 사전 기준

용어 사전의 형식, 등록 규칙, 분리 절차다. `glossary` 스킬과 `check` 스킬, `glossary-scanner`가 같은 기준을 읽는다.

## 1. 형식

용어 사전은 사용자 프로젝트의 `docs/superglossary/`에 있다. 사람과 Claude가 같은 파일을 읽고 고치므로 생성물이나 중간 형식(JSON 등)을 두지 않는다.

### 분리 전 — `glossary.md` 한 파일

처음 만들 때는 아래를 그대로 쓴다. 표의 세 용어가 기본 용어다.

```markdown
# 용어 사전

이름(클래스·변수·함수·컬럼·테이블·API 필드)에 쓰는 단어 목록이다. /superglossary:glossary가 관리한다.

- 단어별로 등록하고 조합해 쓴다 (체결수량 → 체결 execution + 수량 quantity → execution_quantity).
- 축약어는 축약 열에 있는 것만 쓴다. 금지 열의 단어는 쓰지 않고 영문 열의 표준을 쓴다.
- 기존 모듈을 고칠 때는 그 모듈의 기존 이름을 따르고, 임의로 이름을 바꾸지 않는다.

| 한글 | 영문 | 축약 | 금지 | 설명 |
| --- | --- | --- | --- | --- |
| 식별자 | identifier | id |  | 데이터를 고유하게 식별하는 값. {엔티티}_id 형식 |
| 이름 | name |  |  | 대상을 지칭하는 명칭 |
| 일시 | datetime | at |  | 날짜와 시각. created_at처럼 _at 접미사로 쓴다 |
```

- 행은 한글 가나다순으로 둔다. 찾기 쉽고, 같은 위치에 넣으므로 diff가 작다.
- 금지 열은 쉼표로 구분한 단어들이다. 설명은 한두 구절로 쓴다 — 이름을 지을 때마다 읽는 파일이라 길면 그만큼 컨텍스트를 쓴다.
- 셀 안에 `|`를 쓸 때는 `\|`로 쓴다. 그대로 쓰면 표의 열이 어긋난다.

### 분리 후 — `glossary.md` + 도메인 파일

```
docs/superglossary/
  glossary.md   ← 규칙 + 도메인 index + 공통 용어 표
  <도메인>.md    ← 같은 열의 표, 그 도메인 용어만
```

`glossary.md`는 규칙 → `## 도메인` → `## 공통 용어` 순서다.

```markdown
# 용어 사전

(분리 전과 같은 머리말과 규칙)

## 도메인

| 도메인 | 파일 | 코드 범위 | 설명 |
| --- | --- | --- | --- |
| 주문 | order.md | src/order/** | 주문·결제 요청 |

## 공통 용어

| 한글 | 영문 | 축약 | 금지 | 설명 |
| --- | --- | --- | --- | --- |
| 식별자 | identifier | id |  | 데이터를 고유하게 식별하는 값. {엔티티}_id 형식 |
```

도메인 파일:

```markdown
# 주문 용어

| 한글 | 영문 | 축약 | 금지 | 설명 |
| --- | --- | --- | --- | --- |
| 주문 | order |  |  | 구매 요청 |
```

- **코드 범위**는 지금 다루는 파일 경로로 어느 도메인 파일을 읽을지 고르는 데 쓴다. 경로가 어느 범위에도 맞지 않으면 공통 용어와 함께 관련 있어 보이는 도메인 파일을 읽는다.
- 여러 도메인이 함께 쓰는 단어는 공통 용어에 둔다. 한 용어는 정확히 한 파일에만 둔다 — 두 곳에 있으면 한쪽만 고쳐져 어긋난다.
- 규칙은 `glossary.md`에만 적는다.

## 2. 등록 규칙

**단어별로 등록한다.** `매도호가체결`을 한 행으로 두지 않고 단어마다 한 행을 둔다. 이미 있는 단어는 다시 넣지 않고 조합해 쓴다. 합성어를 통째로 등록하면 사전이 금방 커지고, 같은 단어가 합성어마다 다르게 번역되기 쉽다.

**나누는 기준은 영문이다.** 합성어의 영문이 부분 영문을 이어 붙인 것과 같으면 나눈다. 다르면 합성어를 한 항목으로 등록한다. 한국어 형태소대로 나누면 업계 표기와 다른 이름이 나올 수 있기 때문이다.

| 예 | 처리 | 이유 |
|---|---|---|
| 체결수량 → 체결 + 수량 | 나눈다 | execution + quantity |
| 매도호가 → ask | 한 항목 | 업계 용어(매수호가는 bid). 나누면 sell_quote가 된다 |
| 국제증권식별번호 → isin | 한 항목 | 표준 약어 |
| 재시도 → retry | 한 항목 | 영문이 한 단어 |

**누가 확정하나.**

- 단어별 등록은 Claude가 스스로 하고 한 줄로 알린다.
- 합성어를 한 항목으로 두는 예외는 도메인 지식이 걸린 판단이다. 근거(업계 용어, 표준, 영문 한 단어)를 들어 사용자 확인을 받은 뒤 등록한다.
- 영문을 고를 때는 그 분야에서 실제로 쓰는 표기를 따른다. 확신이 없으면 후보와 근거를 보여 주고 묻는다.

**충돌.** 다음이면 등록하지 않고 기존 항목을 보여 준다. 분리된 뒤에는 `docs/superglossary/` 전체에서 찾는다.

- 한글·영문·축약이 기존 항목과 겹친다(영문·축약은 대소문자를 가리지 않는다).
- 영문·축약이 다른 항목의 금지 단어다 — 그 항목의 표준을 쓰라고 안내한다.
- 새 금지 단어가 다른 항목의 영문·축약이다.

**축약어**는 축약 열에 등록한 것만 쓴다. 새 축약어가 필요하면 그 단어의 축약 열에 넣는다.

**금지 단어**는 단어 단위로 적는다(`cust_no`가 아니라 `cust`). 이름을 단어로 나눠 대조하므로 여러 단어짜리는 맞춰 볼 수 없다.

## 3. 분리 절차

용어가 300개를 넘으면 분리를 제안한다. 사용자가 동의할 때만 아래를 한다.

1. **도메인 후보 제안**: 프로젝트에 도메인 정의 문서(예: `docs/superdomain/DOMAIN.md`)가 있으면 그 도메인 이름과 코드 위치를 따른다. 없으면 모듈·패키지 구조에서 후보를 뽑는다. 후보마다 코드 범위와 옮겨 갈 용어 수를 보여 준다.
2. **확인**: 도메인 목록과 코드 범위를 사용자에게 확인받는다.
3. **공통 용어 판정**: 여러 도메인의 코드에서 쓰이는 단어와 기본 용어(식별자·이름·일시)는 공통 용어로 둔다. 판정이 애매한 단어는 목록으로 보여 주고 묻는다.
4. **파일 생성**: 도메인마다 `<도메인>.md`를 만들고 해당 행을 옮긴다. 파일 이름은 영문 소문자 kebab-case다.
5. **index 작성**: `glossary.md`에 `## 도메인` 표를 쓰고, 남은 행을 `## 공통 용어` 표로 둔다.
6. **확인**: 옮기기 전과 후의 전체 행 수가 같은지, 한 용어가 두 파일에 있지 않은지 확인하고 결과를 보고한다.
