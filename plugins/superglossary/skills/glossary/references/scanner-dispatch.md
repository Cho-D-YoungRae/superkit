# 스캐너 실행 계약 — Agent 도구가 없는 런타임

glossary 스킬의 생성 단계에서, 사용자가 기존 코드 스캔에 동의했고 Agent 도구가 없을 때(Codex 등) 호출자와 스캐너가 함께 따르는 계약이다. Claude Code에서는 이 문서를 쓰지 않는다 — Agent 도구로 `superglossary:glossary-scanner`를 부르면 에이전트 정의 머리의 `model`·`tools`가 적용된다.

스캐너 역할 문서는 그 에이전트 정의 파일 [glossary-scanner.md](../../../agents/glossary-scanner.md) 자체다. Claude Code 밖에서는 머리의 `model`·`tools`가 적용되지 않으므로 아래 지시로 대신한다. 이 파일은 자동 등록된 custom agent가 아니라 서브에이전트에게 읽힐 패키지 안의 문서다.

## 호출자

1. 현재 세션에서 실제 제공되는 서브에이전트 도구와 새 컨텍스트 옵션을 확인한다. `collaboration.spawn_agent`가 제공되면 `fork_turns: "none"`과 고유한 `task_name`을 사용한다. 다른 도구면 그 도구의 실제 스키마를 따른다. 역할 이름을 존재하지 않는 `agent_type`으로 호출하거나 앱의 새 채팅 만들기로 대신하지 않는다.
2. `model`과 reasoning 설정은 지정하지 않는다. 에이전트 정의의 `sonnet`은 Claude 모델 별칭이라 옮길 수 없으므로, 세션 설정을 그대로 물려받는다.
3. 호출한 SKILL.md의 실제 위치에서 역할 문서·기준 문서·이 계약을 찾아 절대 경로로 넘긴다. 파일이 없으면 스캔 미완료를 알린다. 작성 대화나 예상 후보는 넘기지 않고 아래만 넘긴다.

   ```text
   역할 문서: <패키지의 agents/glossary-scanner.md 절대 경로>
   실행 계약: <이 문서의 절대 경로>
   프로젝트 루트: <절대 경로>
   용어집: <절대 경로>/docs/superglossary/glossary.md
   기준 문서: <패키지의 skills/glossary/glossary-guide.md 절대 경로>
   제한: 읽기·검색만 수행. 파일·설정·Git 상태 변경, 외부 작업, 추가 위임 금지.
   출력: 단어 후보, 혼용 리포트, 한 항목 예외 후보. 근거 위치·빈도 집계 기준·검토 범위·미검토 이유 포함.
   ```

4. 완료를 기다린 뒤 후보와 혼용 리포트를 사용자에게 보여 준다. 그 뒤는 glossary 스킬의 생성 단계를 따른다. 스캐너가 표준을 확정하거나 사전에 직접 쓰지 않는다.
5. 도구 미지원·실행 실패·자료 부족이면 범위와 이유를 알리고 스캔을 미완료로 남긴다. 실행하지 않은 스캔을 완료나 후보 없음으로 보고하지 않고, 메인 세션의 자기 검토로 대신하지 않는다. 이미 만든 기본 용어집은 유지하고, 다음 진행은 사용자와 정한다.

## 스캐너

- 역할 문서의 지시와 함께 아래를 지킨다. 역할 문서 머리의 `tools`(읽기·검색)만 쓴다고 보면 된다.
- 파일 읽기와 파일명·본문 검색만 한다. 셸을 쓸 때도 읽기 전용 검색(`rg` 등)만 한다. 빌드·테스트·설치·네트워크·MCP 작업을 하지 않고, 파일·설정·Git 상태를 바꾸지 않는다.
- 다른 에이전트·채팅을 만들거나 작업을 재위임하지 않는다. 범위가 크면 직접 나눠 읽고 읽은 범위와 미검토 범위를 보고한다.
- 결과는 호출자에게 반환하며 파일로 저장하지 않는다.

이 제한은 **행동 지침**이다. 이 문서는 편집 도구를 제거하거나 별도 샌드박스를 만들지 않는다. 실제 권한은 실행 세션의 정책을 따른다. Claude Code의 `tools: Read, Grep, Glob` 같은 도구 차단은 Claude Code에서만 적용된다.
