# 용어 사전 검토

지정된 코드와 사전 변경의 영향을 **현재 작업 트리의 사전**으로 검토한다. 코드·사전·지침·Git 상태를 수정하지 않는다. 판정은 이 세션에서 직접 한다.

기준 문서는 `${CLAUDE_SKILL_DIR}/../glossary/glossary-guide.md`다. 판정 전에 필요한 부분 읽기와 등록 규칙을 읽는다.

## 1. 기준 확인

git 루트(`git rev-parse --show-toplevel`)를 기준 디렉터리로 삼는다. Git이 아니면 현재 디렉터리를 쓰고, 경로 인자가 없으면 검사할 경로를 안내받는다.

인자 종류와 무관하게 현재 `docs/superglossary/glossary.md`와 그 도메인 파일을 사용한다. 커밋 범위의 옛 사전은 변경 내용을 찾는 자료이며 판정 기준이 아니다. 현재 사전이 없으면 그 사실과 검사 불가 범위를 알리고 `/superglossary:glossary`로 만들자고 제안한다. 옛 사전이나 옛 JSON 형식으로 대체하지 않는다.

## 2. 코드와 사전의 변경 범위

`<프로젝트 루트>`는 실제 경로로 대체한다. 인자·경로를 안전하게 인용하고 NUL 구분 목록의 공백 있는 파일명을 보존한다.

- **인자 없음**: 다음 셋을 합친다. 삭제된 파일은 뺀다.
  - unstaged: `git -C "<프로젝트 루트>" diff --name-only --diff-filter=d -z`
  - staged: `git -C "<프로젝트 루트>" diff --cached --name-only --diff-filter=d -z`
  - untracked: `git -C "<프로젝트 루트>" ls-files --others --exclude-standard -z`
- **경로**: 현재 해당 파일·디렉터리 전체를 본다. 없는 경로·읽기 실패는 미검토로 보고한다.
- **커밋 범위**: 리비전의 유효성을 먼저 확인하고 `git -C "<프로젝트 루트>" diff <범위> --`를 본다. 잘못된 범위를 인자 없는 검사로 바꾸지 않는다. 코드 문맥은 `git -C "<프로젝트 루트>" show <종료 리비전>:<저장소 상대 경로>`로 읽는다. 종료 리비전 코드를 현재 파일로 대신하지 않는다.

staged·unstaged diff는 각각 읽는다. 같은 경로가 양쪽에 있어도 어느 한쪽을 버리거나 현재 파일 전체로 staged 내용을 대체하지 않는다.

**사전 변경은 코드 대상과 별도로 확인한다.** Git 저장소에서는 인자 종류와 무관하게 아래 두 diff와 untracked 사전 파일을 확인한다. 커밋 범위가 주어졌으면 세 번째 diff도 확인한다.

```bash
git -C "<프로젝트 루트>" diff -- docs/superglossary/
git -C "<프로젝트 루트>" diff --cached -- docs/superglossary/
git -C "<프로젝트 루트>" diff <범위> -- docs/superglossary/
```

사전 파일 자체는 코드 이름 검사에서 제외하지만 그 변경을 버리지 않는다. 락 파일·생성물·의존성 디렉터리·Git 내부는 코드 검사에서 제외한다. **3절의 사전 영향까지 확인한 뒤** 코드 대상과 의미 있는 사전 변경이 모두 없을 때만 "검사할 변경이 없습니다"로 끝낸다.

## 3. 사전 변경의 기존 코드 영향

표준·축약·금지, 설명의 의미·용도·명시적 예외, 도메인 적용 안내가 바뀐 항목을 찾는다. 행 이동·정렬·문장 다듬기만으로 의미가 바뀌지 않았다면 영향 검사 대상에 넣지 않는다.

- 이전/현재 행의 한글·영문·축약·금지와 활용형을 검색어로 만든다. 사전이 새로 생겼으면 새 항목을 대상으로 한다. 삭제된 항목의 옛 표기도 살피되 삭제만으로 위반을 만들지 않고 현재 남은 규칙으로 판단한다.
- 현재 프로젝트 전체의 기존 코드에서 해당 표기를 검색한다. 처음 지정한 경로·diff 밖의 사용도 포함하고, 2절의 코드 제외 기준을 적용한다. 결과의 식별자·주변 코드를 읽어 같은 의미·용도인지 확인한다.
- 이 영향 검사는 **현재 코드와 현재 사전**을 대조한다. 커밋 범위의 코드 검토와 구분해 보고한다. 변경 항목의 현재 표준과 금지는 기존 관례보다 우선한다.
- Git 밖에서는 사용자가 준 변경 전후 내용이나 이번 대화에서 실제 수정한 항목으로 영향을 확인한다. 비교 자료가 없으면 지정 경로의 현재 기준 검사는 진행하고, 사전 변경 영향은 미검토라고 알린다. 이전 자료 읽기 실패도 숨기지 않는다.

## 4. 사전 검색과 판정

먼저 추가·변경된 줄의 식별자와 사전 영향으로 찾은 이름을 추린다. untracked·경로 대상은 파일 전체를 본다. guide의 필요한 부분 읽기에 따라 머리말·규칙·인덱스를 읽고, 관련 한글 의미·표기·활용형을 **사전 전체**에서 Grep으로 찾는다. 관련 행의 다섯 열과 설명까지 확인하고, 부족하면 Read로 관련 구간을 넓힌다.

코드의 의미·용도와 일치하는 항목을 기준으로 다음을 판정한다. 합성 개념은 전체 식별자의 뜻도 본다. camelCase·snake_case와 활용형을 고려하되 설명의 예외를 단어 분해로 지우지 않는다.

1. **금지 단어**: 해당 의미·용도에서 금지된 표기를 사용했다 → 위반. 다른 의미의 금지를 전역 적용하지 않는다.
2. **다른 표기**: 같은 의미에 사전의 영문·등록 축약과 다른 표기를 썼거나 설명의 명시적 용도별 표기를 어겼다 → 위반.
3. **미등록 축약어**: 그 개념의 축약 열에 없는 줄임말을 썼다 → 위반. 기본 영문과 등록 축약은 모두 허용하며 축약을 항상 강제하지 않는다.
4. **추가 후보**: 사전에 없지만 프로젝트의 개념이고 반복해서 쓰이는 단어 → 후보. 검색 0건만으로 미등록을 확정하지 않는다.

현재 사전에 명시한 표준·금지·예외를 기존 관례라는 이유로 면제하지 않는다. 사전에 정하지 않은 사항은 기존 관례를 참고한다. 일반 영어·언어 키워드·라이브러리 식별자는 제외한다.

여러 항목이 적용되는데 표준/금지가 충돌하거나 의미·예외를 결정할 근거가 부족하면 **확인 필요**다. 다른 행에 같은 영문이 있다는 이유만으로 허용하지 않는다. 읽기 실패·결과 잘림·깨진 표로 확인하지 못한 것은 **미검토**다. 끝까지 읽거나 범위를 나누어 확인하고, 끝내 확인하지 못한 이유를 남긴다.

## 5. 보고

코드 검사 범위와 현재 작업 트리 사전 기준을 한 줄로 알린다. 사전 영향으로 범위 밖 현재 코드를 살폈다면 그 범위도 밝힌다. 해당하는 표만 출력한다.

```text
위반: 파일:줄 | 이름 | 사전 표준 | 사유(의미·용도·사전 근거)
추가 후보: 한글(추정) | 영문 | 근거
확인 필요: 파일:줄·항목 | 가능한 해석 | 필요한 판단
미검토: 파일·범위 | 이유
```

요청 범위와 사전 영향 검사를 모두 마쳤고 네 분류 모두 비었을 때만 "이상 없음"이라고 보고한다. 파일은 고치지 않는다. 추가 후보는 `/superglossary:glossary`로 등록할지 묻고, 현재 표준의 위반은 수정 대상으로 알린다. 기존 코드에 많다는 이유만으로 사전의 결정을 완화하지 않는다.
