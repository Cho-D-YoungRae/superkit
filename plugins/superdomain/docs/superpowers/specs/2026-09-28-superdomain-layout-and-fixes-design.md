- 날짜: 2026-09-28

## 1. 배경

두 가지 요구가 한 번에 들어왔다.

1. **산출물 배치.** 지금 superdomain은 대상 프로젝트 루트(`DOMAIN.md`)와 `docs/` 여러 곳
   (`docs/domain-summary.md`, `docs/domain/`, `docs/domain.md`, `docs/decisions/`, `docs/conventions/`)에
   파일을 흩어 놓는다. 플러그인이 만든 것과 팀이 만든 것이 섞이고, 어느 파일이 superdomain 소유인지
   경로만으로는 알 수 없다. 전부 `docs/superdomain/` 한 디렉터리 아래로 모은다.
2. **리뷰 반영.** 2026-09-26 전수 리뷰(스크립트·테스트 / 스킬·에이전트·플러그인 규약 / 문서↔코드
   정합성)가 약 30건을 찾았다. 그중 재현으로 확인된 결함 — BOM 소스의 격리 위반 누락, 코드 펜스 속
   라벨의 선언 오염, 스킬 간 라우팅 모순, 버전 미갱신으로 인한 변경 미전달 — 은 "침묵하지 않는다"는
   제1 원칙을 실제로 깨고 있다.

두 요구가 스킬 8개·정본 5종·스크립트 5개를 대부분 공유하므로 스펙은 하나로 쓰고 구현은 단계로 나눈다.

## 3. 산출물 배치

### 3.1 트리

```
docs/superdomain/
├── DOMAIN.md            # 도메인 SSOT
├── summary.md           # SessionStart 훅이 주입하는 요약(30줄 이하)
├── contexts/
│   └── <컨텍스트>.md     # 불변식·애그리거트·값 객체·도메인 이벤트·도메인 서비스·열린 질문
├── adr/
│   └── yyyy-MM-dd-slug.md
├── conventions/
│   └── <key>.md         # 선언에 자리가 없는 팀 규약
└── state/
    ├── baseline.jsonl   # 동결된 격리 위반
    └── review-log.jsonl # 리뷰 판정 이력
```

`adr/`은 평탄하다(하위 디렉터리 없음). `contexts/`에는 선언된 컨텍스트의 문서만 둔다 — 요약이
`contexts/` 밖에 있으므로 "요약 파일이 컨텍스트 문서로 오인된다"는 옛 제약(domain-doc-template §2)은
사라진다.

### 3.2 옛 경로 → 새 경로

| 옛 경로 (0.2.x) | 새 경로 (0.3.0) |
|---|---|
| `DOMAIN.md` | `docs/superdomain/DOMAIN.md` |
| `docs/domain-summary.md` | `docs/superdomain/summary.md` |
| `docs/domain/<컨텍스트>.md` | `docs/superdomain/contexts/<컨텍스트>.md` |
| `docs/domain.md` | `docs/superdomain/contexts/<유일한 컨텍스트 이름>.md` |
| `docs/domain/baseline.jsonl` | `docs/superdomain/state/baseline.jsonl` |
| `docs/domain/review-log.jsonl` | `docs/superdomain/state/review-log.jsonl` |
| `docs/decisions/*.md` | `docs/superdomain/adr/*.md` |
| `docs/conventions/<key>.md` | `docs/superdomain/conventions/<key>.md` |

**파일 내용은 바뀌지 않는다.** `DOMAIN.md`의 `- 경로:`, 리포트의 표시 경로, `baseline.jsonl`의
`path` 필드는 전부 **프로젝트 루트 기준**으로 유지된다. 이행은 옮기기와 문서 간 링크 치환뿐이다.

### 3.3 `scripts/layout.py` — 경로 지식의 유일한 자리

새 모듈이다. 다른 스크립트는 산출물 경로 문자열을 직접 갖지 않고 여기서만 받는다.

```python
DOMAIN_DIR = PurePosixPath("docs/superdomain")

@dataclass(frozen=True)
class Layout:
    root: Path                      # 프로젝트 루트
    # 파생 경로(프로퍼티): domain, summary, contexts_dir, adr_dir,
    #                      conventions_dir, state_dir, baseline, review_log
    def display(self, path) -> str  # root 기준 POSIX 상대경로(리포트용)

class LayoutError(Exception):       # 메시지는 사용자에게 그대로 보인다
    ...

def from_domain_path(path) -> Layout
def legacy_leftovers(root) -> list[tuple[str, str]]   # (옛 경로, 새 경로) — 실제로 있는 것만
```

**`from_domain_path` 계약**

1. `path`를 resolve한다. 파일명이 `DOMAIN.md`이고 부모가 `…/docs/superdomain`이면 `root = path.parents[2]`.
2. 그 모양이 아니면 `LayoutError`. 단, 그 경로가 **옛 배치의 루트 `DOMAIN.md`**(파일 안에
   `<!-- superdomain:template` 마커가 있음)이면 일반 사용법 오류가 아니라 **이행 안내**를 담는다.
3. 모양은 맞는데 파일이 없고, `root/DOMAIN.md`(마커 있음)가 있으면 역시 이행 안내.
4. 모양이 맞고 파일도 있더라도 `legacy_leftovers(root)`가 비어 있지 않으면 `LayoutError`
   ("이행이 끝나지 않았습니다") — 옛 자리에 남은 컨텍스트 문서를 조용히 무시하면 `check_invariants`가
   `confirmed` 불변식을 놓친다.

**`legacy_leftovers` 판정 대상**은 superdomain 소유가 확실한 것만이다.

1. 마커가 있는 루트 `DOMAIN.md`(확실한 옛 배치)가 있으면 그 아래 있는 건 전부 잔여물로 본다.
2. 없으면 소유 신호가 있는 것만 넣는다: `docs/domain-summary.md`는 생성 헤더
   (`GENERATED by superdomain`)가 있을 때만, `docs/domain.md`와 `docs/domain/*.md`는
   `## 불변식` 제목이 있을 때만. `docs/domain/baseline.jsonl`·`review-log.jsonl`은 이름
   자체가 specific하므로 신호 없이 항상 넣는다. 이렇게 해야 팀이 같은 이름으로 두는 자기
   문서(`docs/domain/team-notes.md` 같은)를 이행 대상으로 몰지 않는다.

`docs/decisions/`와 `docs/conventions/`는 팀이 따로 쓰는 폴더일 수 있으므로 **루트 `DOMAIN.md`가
옛 배치로 판정된 경우에만**(위 1) 이행 목록에 넣고, 단독으로는 잔여물로 보지 않는다.

**이행 안내의 형식.** 실제로 존재하는 항목만 골라 실행 가능한 명령으로 출력한다.

```
옛 배치(superdomain 0.2.x)입니다 — 0.3.0부터 산출물은 docs/superdomain/ 아래에 있습니다.
다음을 실행한 뒤 문서 간 링크를 고치고 파서를 다시 돌리세요(절차: <플러그인>/CHANGELOG.md 0.3.0).
  mkdir -p docs/superdomain/contexts docs/superdomain/state
  git mv DOMAIN.md docs/superdomain/DOMAIN.md
  git mv docs/domain-summary.md docs/superdomain/summary.md
  ...
```

`<플러그인>`은 스크립트가 자기 위치(`Path(__file__).parents[1]`)에서 계산한 절대경로로 채운다.
`docs/domain.md`의 목적지는 파싱 없이는 컨텍스트 이름을 알 수 없으므로
`docs/superdomain/contexts/<컨텍스트 이름>.md`라는 자리표시로 출력한다.

### 3.4 스크립트별 변경

라이브러리 함수(`parse_domain(path)`, `check(domain_path)` 등)와 CLI를 구분한다.

| 스크립트 | 변경 |
|---|---|
| `parse_domain.py` | 라이브러리 함수는 **배치를 모른다**(임의 경로의 픽스처를 파싱할 수 있어야 한다). CLI만 `from_domain_path`로 검증하고, `LayoutError`는 exit 2 |
| `check_imports.py` | `base = Layout.root`. `BASELINE_RELATIVE` 상수를 제거하고 `layout.baseline`을 쓴다. `LayoutError`는 exit 2 |
| `check_invariants.py` | 컨텍스트 문서는 `layout.contexts_dir`의 `*.md`만 읽는다. `CONSOLIDATED_DOC`와 통합 배치 분기 삭제. `contexts/`에 선언되지 않은 이름의 문서가 있으면 지금처럼 `stray-doc` 경고 |
| `collect_signals.py` | `REVIEW_LOG`·`BASELINE` 상수를 layout으로 대체. **baseline 추이(⑤)는 pathspec에 새 경로와 옛 경로(`docs/domain/baseline.jsonl`)를 함께 준다** — `--no-renames`를 유지하므로 이동 커밋은 −N/+N으로 상쇄되어 누적 줄 수가 끊기지 않는다. 옛 경로를 아는 것은 layout 모듈의 상수로만 |
| `build_index.py` | 배치와 무관(플러그인 저장소의 `references/`만 본다) |

JSON 출력의 `path`·표시 경로는 전부 `Layout.display`를 거친다(지금과 같은 루트 기준).

### 3.5 SessionStart 훅

`scripts/session_summary.sh`:

1. cwd에서 git 루트(또는 `/`)까지 올라가며 `docs/superdomain/summary.md`를 찾으면 출력하고 exit 0.
2. 찾지 못한 채 탐색이 끝났고, 탐색 중 `docs/domain-summary.md` 또는 마커 있는 `DOMAIN.md`를 본
   디렉터리가 있으면 **한 줄 안내**를 출력한다:
   `[superdomain] 이 프로젝트는 옛 배치(0.2.x)입니다 — 스크립트가 exit 2로 멈춥니다. 이행 절차: ${CLAUDE_PLUGIN_ROOT}/CHANGELOG.md`
3. 파일을 읽지 못하면(권한 등) 출력 없이 exit 0 — `set -e` 아래에서 `cat` 실패가 훅 실패로 번지지
   않게 `|| exit 0`으로 감싼다.
4. `hooks/hooks.json`의 명령 경로를 따옴표로 감싼다(`"\"${CLAUDE_PLUGIN_ROOT}/scripts/session_summary.sh\""`).

### 3.6 옛 배치 감지 — 세 자리

| 자리 | 동작 |
|---|---|
| 스크립트 CLI | `LayoutError` → exit 2와 이행 안내(§3.3) |
| 훅 | 한 줄 안내(§3.5) |
| 스킬 | 공통 초기화 게이트(§6.1)가 `docs/superdomain/DOMAIN.md` 부재 시 옛 배치 여부를 먼저 본다. 옛 배치면 `init`으로 보내지 않고 이행 절차를 안내하고 멈춘다 |

### 3.7 이행 절차 (CHANGELOG 0.3.0에 싣는 내용)

1. 스크립트 하나(예: `parse_domain.py DOMAIN.md`)를 돌려 이행 안내의 명령 목록을 받는다.
2. 목록대로 `mkdir -p`와 `git mv`를 실행한다. `docs/domain.md`는 유일한 컨텍스트 이름으로 목적지를 정한다.
3. 옮긴 문서 안의 경로 참조를 치환한다 — `docs/decisions/` → `docs/superdomain/adr/`,
   `docs/domain/` → `docs/superdomain/contexts/`, `docs/domain-summary.md` → `docs/superdomain/summary.md`,
   루트 `DOMAIN.md`를 가리키는 링크. 같은 디렉터리 안의 상대 링크(ADR끼리)는 그대로 둔다.
   `DOMAIN.md`에서 ADR을 가리키는 상대 링크는 기준 디렉터리가 바뀌었으므로 `adr/…`로 고친다.
4. `python3 <플러그인>/scripts/parse_domain.py docs/superdomain/DOMAIN.md` → `OK:` 줄의 프로젝트·컨텍스트
   개수가 이행 전과 같은지 확인한다. `check_imports.py`·`check_invariants.py`의 위반 건수도 이행 전과 같아야 한다.
5. 한 커밋으로 남긴다(`git mv`만으로 이루어진 커밋 + 링크 치환 커밋으로 나누면 이력 추적이 쉽다).

## 4. 스크립트 수정 (배치와 무관)

모두 **실패하는 테스트를 먼저 쓰고** 고친다.

### 4.1 소스 인코딩 — BOM

- `check_imports.py`의 소스 읽기(:240)와 `check_invariants.py`의 테스트 소스 읽기(:401)를
  `encoding="utf-8-sig"`로 바꾼다. 같은 결함(선두 U+FEFF가 `^\s*`·`json.loads`를 깨뜨림)이
  `DOMAIN.md` 첫 줄 마커, `baseline.jsonl`, `review-log.jsonl`에도 있으므로 **모든 텍스트 입력**을
  같은 인코딩으로 읽는다(구현 계획 Task 2).
- 재현(2026-09-26): 첫 줄에 BOM이 있는 `Leaky.kt`는 `package`가 매칭되지 않아 귀속 불가 →
  `claim → admin` 위반이 누락되고 exit 0. 같은 컨텍스트에 BOM 없는 파일이 하나라도 있으면
  `[0건 경고]`도 뜨지 않는다.
- 테스트: BOM 소스의 위반이 잡힌다. CRLF 소스의 `package`·`import`·위반 줄 번호가 정확하다.

### 4.2 `DOMAIN.md` 라벨 위치 규칙과 코드 펜스

- **라벨 자리** = 문서 머리(첫 `##` 전) 또는 `##` 섹션 헤딩 다음부터 그 섹션의 첫 `###` 전까지.
  `###` 아래의 라벨 모양 줄은 자유 서술로 보고 무시한다. `### 관계` 아래의 **표**는 지금처럼 읽는다.
- **코드 펜스**(```` ``` ````·`~~~`, 정보 문자열 허용) 안은 어디서든 라벨·표·헤딩으로 해석하지 않는다.
  닫히지 않은 펜스는 `ParseError`("닫히지 않은 코드 펜스") — 그 뒤의 선언이 조용히 사라지면 안 된다.
- **퇴역 라벨 6종**은 라벨 자리 전체에서 거부한다(지금은 알려진 섹션 안에서만 거부해, 문서 머리나
  모르는 `##` 섹션 머리의 `- 스타일:`이 조용히 무시된다). `###` 아래와 펜스 안은 자유 서술이므로 거부하지 않는다.
  문서 머리와 모르는 `##` 섹션에는 라벨을 적용할 대상이 없으므로, 그 자리를 라벨 자리로 보는 효과는
  퇴역 라벨 거부 하나뿐이다(그 밖의 라벨 모양 줄은 지금처럼 무시된다).
- 재현(2026-09-26): `### 근거` 아래 펜스에 `- 패키지: com.legacy.claim`을 넣으면 `OK` / exit 0인 채

### 4.3 지식 문서 성숙 판정 — `build_index.py`

- `_is_mature`가 `## 적용 기준`과 `## 규칙` 각각 **아래에 비어 있지 않은 본문**을 요구한다. 본문이란
  그 헤딩 다음부터 다음 `##` 헤딩 전까지, `#`으로 시작하지 않는 공백 아닌 줄 1개 이상이다(`###` 하위 절의
  내용은 본문에 포함되고, 하위 헤딩 줄만 있는 경우는 본문이 아니다).
- 재현: 두 헤딩만 있고 본문이 빈 문서가 `draft=False`로 등재된다. knowledge-doc-template §8과 study
  스킬은 "비워 두면 draft"라고 안내하므로 "draft는 판정 근거 불가" 장치가 우회된다.
- knowledge-doc-template §8의 템플릿에서 자리표시 위키링크 `[[다른-문서-key]]`를 없앤다(그대로 복사하면
  "존재하지 않는 문서" 오류로 빌드가 실패한다). 템플릿의 다른 자리표시(`- (언제 쓰는가)` 등)도 한 줄
  HTML 주석으로 바꾸고, **주석만 있는 줄은 본문으로 세지 않는다** — 그래야 템플릿을 그대로 복사한
  문서가 draft로 색인된다.
- 현행 지식 12종이 새 판정에서도 전부 성숙인지 확인한다(INDEX의 draft 열이 비어 있어야 한다).

### 4.4 `read_when` 검증 — `build_index.py`

## 9. noguesstoday 이행

`~/Projects/noguesstoday`는 옛 배치를 쓰는 실제 대상 프로젝트다(루트 `DOMAIN.md`, `docs/domain-summary.md`,
`docs/decisions/`의 ADR 6건). 0.3.0 PR이 준비된 뒤:

1. 이행 전에 `main` 브랜치(0.2.0 동작)의 스크립트 — 스크래치에 만든 `main` worktree — 로
   `parse_domain`·`check_imports`·`check_invariants` 결과를 기록한다.
2. noguesstoday에 브랜치를 만들고 §3.7 절차를 그대로 적용한다. 절차 문서 자체의 검증을 겸한다 —
   절차대로 했는데 막히면 절차를 고친다.
3. 새 스크립트로 같은 세 검사를 돌려 OK 줄과 위반 건수가 1과 같은지 비교한다.
4. 커밋 전에 사용자 확인을 받는다. `.worktrees/` 아래 다른 브랜치들은 각자 병합·리베이스 때 이행한다
   (이번 범위 밖).
