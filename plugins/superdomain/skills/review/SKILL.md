# 도메인·컨벤션 리뷰

> **런타임 메모** — 이 스킬은 Claude Code와 Codex가 함께 쓴다. Claude Code는 읽기 전에 본문의 `$` 자리표시자를 치환한다. 치환되지 않은 채 보이면(Codex 등) `CLAUDE_PLUGIN_ROOT`는 플러그인 루트(이 SKILL.md가 있는 `skills/<스킬>/`의 두 단계 위), `CLAUDE_SKILL_DIR`는 이 SKILL.md가 있는 디렉터리, `ARGUMENTS`는 사용자가 이 스킬을 부르며 함께 준 인자로 읽고, 경로는 절대 경로로 바꿔 쓴다. Read·Grep·Glob·Agent 같은 도구 이름과 `/superdomain:<스킬>` 호출 표기도 Claude Code 기준이다 — 그 런타임의 같은 수단으로 바꿔 쓴다.

변경을 두 관점에서 본다. 도메인 경계는 `superdomain:domain-reviewer`가, 코딩 컨벤션은 `superdomain:convention-reviewer`가 맡는다. 이 스킬은 대상을 정하고, 두 리뷰어를 동시에 띄우고, 결과를 한 리포트로 합친다.

**핵심 원칙:** 판정은 리뷰어가 한다. 이 스킬이 diff를 직접 읽고 판정하지 않는다. 코드는 사용자가 요청할 때만 고친다.

## 1. 대상 결정

작업 기준은 git 루트다(`git rev-parse --show-toplevel`). 아래 git 명령은 모두 git 루트에서 실행하고, 경로는 git 루트 기준으로 쓴다.

인자(`$ARGUMENTS`)는 앞에서부터 읽는다.

- 첫 토큰이 정확히 `domain`이나 `code`면 관점이다(2절). 나머지가 대상이다. 공백이 있는 경로는 하나의 대상으로 둔다.
- 대상이 `전체`면 전체 점검이고, `..`가 들어 있으면 커밋 범위, 그 밖은 경로다. 없는 경로면 사용자에게 묻는다.

| 대상 | 모드 | 보는 것 |
|---|---|---|
| 없음 | 변경 검토 | 기준 브랜치와의 merge-base 이후의 모든 변경(커밋된 것 + 커밋하지 않은 것 + 새 파일) |
| 경로 | 변경 검토 | 위 변경 중 그 경로 아래의 것 |
| 커밋 범위(`A..B`) | 변경 검토 | 그 범위의 커밋 변경(작업 트리 변경과 새 파일은 넣지 않는다) |
| `전체` | 전체 점검 | 프로젝트 전체 |

변경 목록은 이렇게 구한다. 경로가 있으면 `diff`·`ls-files` 명령 끝에 `-- <경로>`를 붙인다. 커밋 범위면 기준 브랜치와 BASE는 구하지 않고, `<BASE>` 대신 `A..B`를 쓰며, 새 파일 목록은 만들지 않는다.

```bash
git symbolic-ref --quiet --short refs/remotes/origin/HEAD   # 기준 브랜치 (예: origin/main)
git merge-base HEAD <기준 브랜치>                            # BASE
git diff --name-status <BASE>                                # 추적 중인 파일의 변경과 상태 (A·M·D·R)
git ls-files --others --exclude-standard                     # 아직 추적하지 않는 새 파일
```

- 대상이 없거나 경로일 때 `origin/HEAD`가 없으면 기준 브랜치를 추측하지 말고 사용자에게 묻는다(커밋 범위·`전체`에는 기준 브랜치가 필요 없다).
- `전체`가 아닌데 변경이 없으면 알리고 끝낸다.

경로·ref를 셸 명령에 넣을 때 각각 따옴표로 감싸고, 경로 앞에는 `--`를 둔다. 사용자 입력을 셸 코드로 이어 붙이지 않는다.

**커밋 범위의 자료:** `A..B`는 두 끝점을 커밋 해시로 확인해 고정한다. DOMAIN.md가 있는지와 그 내용, 프로젝트 지침, 대상 파일의 문맥은 모두 끝점 B의 `git show <B>:<경로>`로 읽는다. 현재 작업 트리의 파일이나 같은 이름의 미추적 파일을 섞지 않는다. 삭제된 파일은 필요하면 A에서 읽는다. 리뷰어에게도 두 해시를 `자료 버전`으로 넘긴다.

## 2. 관점 결정

- 관점이 `domain`이면 도메인만, `code`면 컨벤션만, 없으면 둘 다 본다.
- `docs/superdomain/DOMAIN.md`가 없으면 도메인 리뷰를 건너뛰고 `/superdomain:domain`을 안내한다.
- 대상에 삭제되지 않은 `.kt`·`.java` 파일이 없으면 컨벤션 리뷰를 건너뛰고 그 사실을 알린다.
- 두 관점이 모두 건너뛰어지면 이유를 알리고 끝낸다.

## 3. 리뷰어 호출

두 리뷰어를 **한 메시지에서 동시에** Agent 도구로 호출한다. `model`은 지정하지 않는다(에이전트 파일에 정해져 있다). 건너뛴 관점의 리뷰어는 부르지 않는다. 세션 대화는 넘기지 않고 아래만 넘긴다.

Agent 도구가 없는 런타임(Codex 등)에서는 [리뷰어 실행 계약](references/dispatch.md)을 읽고, 관점마다 새 컨텍스트의 서브에이전트를 동시에 띄워 [domain-reviewer](../../agents/domain-reviewer.md)·[convention-reviewer](../../agents/convention-reviewer.md)를 역할 문서로 넘긴다. 넘기는 입력은 아래와 같다.

`대상`에는 리뷰어가 직접 실행할 수 있는 명령만 넣는다. 리뷰어는 git을 `diff`·`log`·`show`로만 쓴다(커밋 범위에서 B 안의 파일을 찾거나 검색할 때는 `ls-tree`·`grep`도 쓴다).

- 변경을 보는 명령: 대상이 없거나 경로면 `git -C <프로젝트 루트> diff <BASE>`(경로가 있으면 `-- <경로>`), 커밋 범위면 `git -C <프로젝트 루트> diff A..B`. 리뷰어는 세션의 현재 디렉터리에서 실행하므로 `-C`로 git 루트를 고정한다.
- 파일 목록에는 상태를 붙인다. 추적하지 않는 새 파일은 `새 파일 — 파일 전체가 변경`으로, 삭제된 파일은 `삭제됨`으로 적는다.
- convention-reviewer에게는 삭제된 파일을 빼고 `.kt`·`.java` 파일만 넘긴다.

`superdomain:domain-reviewer`:

```
모드: 변경 검토 | 전체 점검
프로젝트 루트: <절대 경로>
DOMAIN.md: <절대 경로; 커밋 범위면 저장소 상대 경로 — B에서 읽는다>
기준 문서: ${CLAUDE_PLUGIN_ROOT}/skills/domain/domain-guide.md
대상: <변경을 보는 git 명령과 상태를 붙인 파일 목록, 또는 "프로젝트 전체">
자료 버전: <작업 트리 | 커밋 범위 A·B의 해시 — 문맥은 B의 git show로 읽는다>
```

`superdomain:convention-reviewer`:

```
모드: 변경 검토 | 전체 점검
프로젝트 루트: <절대 경로>
DOMAIN.md: <절대 경로 | 없음; 커밋 범위면 저장소 상대 경로 — B에서 읽는다>
기준 문서: ${CLAUDE_PLUGIN_ROOT}/skills/conventions/conventions.md
대상: <변경을 보는 git 명령과 상태를 붙인 .kt·.java 파일 목록, 또는 "프로젝트 전체">
자료 버전: <작업 트리 | 커밋 범위 A·B의 해시 — 문맥은 B의 git show로 읽는다>
```

리뷰어를 띄울 수 없거나 리뷰어가 실패·중단되면 그 관점은 **미검토**로 보고한다. 지적 없음으로 처리하지 않고, 이 스킬이 직접 판정해 대신하지 않는다.

## 4. 합치기

- 심각도 순(Critical → Important → Minor)으로 모은다.
- 같은 위치의 같은 문제는 하나로 합치고 기준을 둘 다 적는다.
- 두 리뷰어의 판단이 충돌하면 둘 다 보여 준다.
- 위치나 기준이 없는 지적은 빼고, 뺐다는 사실을 적는다.

## 5. 보고와 후속

```markdown
## 리뷰 결과 — <대상 요약>
### Critical
### Important
### Minor
- [도메인|컨벤션] `경로:줄` 문제 — 기준 — 제안
### 질문
### 검토 범위
(건너뛴 관점과 그 이유를 포함한다)
```

- 코드 수정은 사용자가 요청할 때만 한다. 요청받으면 Critical부터 고친다.
- 지적된 위치의 코드를 확인해 리뷰어의 지적이 틀렸다고 보이면 근거와 함께 그렇게 말하고, 그대로 따르지 않는다. 이 스킬이 새 지적을 더하지는 않는다.
- DOMAIN.md를 고쳐야 하면 `/superdomain:domain`을, 결정을 남겨야 하면 `/superdomain:adr`을 안내한다.

## 하지 않는 것

- 자동으로 코드를 고치지 않는다.
- 리뷰 결과를 파일로 저장하지 않는다.
- 리뷰어의 모델을 지정하거나 덮어쓰지 않는다(Claude Code는 에이전트 파일, 다른 런타임은 실행 계약을 따른다).
