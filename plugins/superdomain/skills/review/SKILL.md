# 변경분 도메인 검토

이 스킬은 판정하지 않는다. **판정은 이미 세 곳에서 끝나 있다** — 결정적 검사(check_imports·
check_invariants)가 컨텍스트 격리와 confirmed 불변식의 태그 존재를, 전달받은 지식 문서의
`## 규칙`이 의미론을, `DOMAIN.md`가 무엇을 어디에 적용할지를 정한다. 이 스킬이 하는 일은
그 셋을 올바른 순서로 돌리고 결과를 한 리포트로 합치는 것이다. 그래서 불변이 셋이다.

1. **결정적으로 판정되는 것을 LLM 판단으로 대체하지 않는다.** 관계 표에 없는 쌍의 컨텍스트 간
   참조와 confirmed 불변식의 테스트 태그 **존재**는 스크립트의 몫이다. 그것들을 "읽어 보고
   판단"하는 순간 이 플러그인은 결정성을 잃고, 같은 코드에 대해 세션마다 다른 답을 낸다.
2. **자동으로 고치지 않는다.** 수정은 제안까지다. 리뷰어가 코드를 고치기 시작하면 리뷰 결과가
   무엇에 대한 것인지 아무도 모르게 된다. 이 스킬이 쓰는 파일은 `review-log.jsonl`과 domain
   문서의 `## 열린 질문` 두 곳뿐이다.
3. **삼키지 않는다.** `[0건 경고]`·한계 푸터·생략 사유·`검사 불능`·`귀속 불신`·변경 밖의 기존
   위반·draft라서 판정하지 못한 주제 — 전부 리포트에 남는다. "위반 없음"과 "아무것도 검사하지
   않음"은 다른 상태이고, 그 둘을 구별해 주는 것이 이 리포트의 값이다.

## 0. 위치와 초기화 게이트

`${CLAUDE_PLUGIN_ROOT}/references/governance/skill-protocol.md` §3(초기화 게이트)을 따른다 — git
루트로 올라가 `parse_domain.py docs/superdomain/DOMAIN.md`로 배치를 확인하고, 배치 오류(옛 배치·
이행 미완, exit 2)면 출력을 보여 주고, 선언이 없으면 `/superdomain:init`을 안내하고 **중단**한다.

통과하면 `docs/superdomain/DOMAIN.md`를 읽는다. 프로젝트 섹션(`- 경로:`·`- 기본 패키지:`)과
컨텍스트별 `- 분류:`·`- 패턴:`·`- 패키지:`, 그리고 `### 관계` 표가 이 스킬의 입력 전부다.

## 1. 대상 결정

### 1-a. 기본은 작업 트리 전체 변경

```bash
git diff --name-only HEAD                    # staged + 작업 트리
git ls-files --others --exclude-standard     # 아직 추적되지 않는 새 파일
```

인자가 오면 그것을 쓴다.

| 인자 | 대상 |
|---|---|
| 없음 | 위 두 명령의 합집합 |
| 경로(파일·디렉터리) | 그 경로 아래 파일 전체 — diff가 아니라 현재 내용이 대상이다 |
| 브랜치·커밋 범위(`main..HEAD`, `<sha>..<sha>`) | `git diff --name-only <범위>` |

- **대상이 비면 "변경 없음"으로 종료한다.** 검사도 위임도 하지 않고, `review-log.jsonl`에도
  아무것도 쓰지 않는다.
- 삭제된 파일은 읽을 수 없으므로 판정 대상에서 빼고 목록에만 남긴다.
- 선언된 프로젝트 경로 **밖**의 파일(미선언 프런트엔드 등)은 판정 대상이 아니다. 숨기지 말고
  "범위 밖"으로 목록에 남긴다.
- `DOMAIN.md`나 domain 문서가 대상에 들어 있으면 그 사실을 리포트 맨 위에 적는다 — 이번 검사
  결과는 **바뀐 선언 기준**이다. 선언과 코드의 대조 자체는 이 스킬이 아니라 sync의 일이다.

### 1-b. 컨텍스트 귀속

3단계의 지식 선별과 6단계의 domain 문서 선택이 여기에 달려 있다. **귀속은 패키지가 정한다 —
디렉터리가 아니다.**

1. 대상 파일이 `.kt`·`.java`이면 첫 `package` 선언을 읽어 컨텍스트의 `- 패키지:` 접두 패턴에
   **세그먼트 경계에서 접두 최장 일치**시킨다. `- 패키지:` 라벨이 없는 컨텍스트의 패턴은
   귀속 프로젝트의 `기본 패키지`로 만든 `<기본 패키지>.<컨텍스트>..`다. **이것이
   `check_imports.py`의 귀속 규칙 그대로다** — 두 규칙이 갈리면 결정적 위반이 붙은 컨텍스트와
   이 스킬이 고른 지식·domain 문서가 서로 다른 컨텍스트를 가리키게 된다.
2. 소스가 아닌 파일과 어느 패턴에도 걸리지 않는 소스는 **미귀속**이다. 지어내지 않는다 —
   4단계 위임 목록에는 넣되 "컨텍스트 미귀속"으로 표시하고 리포트에도 그대로 적는다.

**2-a가 `귀속 불신`으로 지목한 파일은 귀속을 믿지 않는다.** `package` 선언이 둘 이상이라 첫
선언으로 귀속된 파일이고, 결정적 판정도 이 스킬의 귀속도 같은 이유로 흔들린다. 그 목록에 오른
대상 파일은 리포트의 항목마다 그 사실을 붙인다(5-a).

## 2. 결정적 검사 먼저

의미론 위임보다 **반드시 먼저** 돈다. 순서가 뒤집히면 domain-reviewer가 이미 결정적으로 잡힌
위반을 다시 보고하고, 리포트에 같은 지적이 두 번 오른다.

**둘 다 돌린다 — 고르는 것이 아니다.** 결정적 검사는 이 둘뿐이고 서로 겹치는 규칙이 없다.
2-a가 보는 것은 컨텍스트 경계를 넘는 import이고, 2-b가 보는 것은 confirmed 불변식의 테스트 태그
존재다. 어느 하나가 다른 하나를 대신하지 않으므로, 하나만 돈 실행은 절반만 검사한 실행이고
그 사실이 리포트에 적혀야 한다. **한쪽이 exit 2로 멈춰도 다른 쪽은 돈다** — 둘은 서로의
전제가 아니다(각각의 exit 2 갈래에 그렇게 적혀 있다).

### 2-a. check_imports — 컨텍스트 격리

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_imports.py" docs/superdomain/DOMAIN.md
```

- exit **0** 클린 / **1** 위반 있음 / **2** 해석 불가·사용법 오류.
- **대상을 좁히는 옵션은 없다.** 인자는 `DOMAIN.md` 경로 하나뿐이고 검사는 선언된 프로젝트
  전체를 돈다(`--paths` 같은 것은 사용법 오류). diff로 좁히는 일은 **5단계의 병합**에서 한다.
- **`--json`을 기본으로 쓰지 않는다.** 한계(검사 범위) 줄은 텍스트에만 있다(skill-protocol §6).
  위반이 많아 기계적 분류가 필요하면 한 번 더 돌리되, **푸터는 텍스트 실행분에서 가져온다.**
- exit 2면 컨텍스트 격리 검사가 통째로 없는 상태다. stderr의 `경로:라인: 메시지` 줄을
  **그대로** 보여주고 멈춘다. 고치는 것은 이 스킬의 일이 아니다. 사용자가 그래도 진행하기를
  원하면 리포트 맨 위에 "컨텍스트 격리는 이번에 검사되지 않았다"를 박고 진행하되,
  **2-b는 그대로 돌린다.** 2-a가 exit 2를 내는 사유는 사용법 오류를 빼면 셋이다(사용법 오류는
  위 명령을 그대로 적으면 나지 않고, 나더라도 2-b와 무관하다) — `DOMAIN.md` 해석 실패,
  `docs/superdomain/state/baseline.jsonl`의 깨진 줄, 그리고 `- 패키지:`도 귀속 프로젝트의 `기본 패키지`도
  없어 컨텍스트의 패키지 패턴을 정하지 못하는 것. **뒤의 둘은 2-b를 조금도 막지 않는다** —
  2-b는 baseline을 읽지 않고 패키지 패턴도 쓰지 않는다(태그를 찾는 범위는 프로젝트 경로 아래
  테스트 디렉터리다). 앞의 하나는 2-b도 같은 이유로 멈추므로 2-b 자신의 exit 2 갈래가 받는다.
  여기서 2-b까지 함께 건너뛰면 confirmed 불변식의 태그 누락이 통째로 무판정으로 남는다.

출력 다섯 갈래를 **전부** 받아 둔다. 5단계에서 갈 곳이 서로 다르다. 채널의 뜻은
`skill-protocol.md` §6이다. 이 스킬에서의 처리만 적는다.

| 갈래 | 5단계에서의 처리 |
|---|---|
| 위반 | diff 소속 / 변경 밖으로 나눈다 |
| 기존 부채 | **구역 2에 `warn`으로.** 대상 파일 안이어도 올리지 않는다 |
| 0건 경고 | 그대로 승계 |
| 귀속 불신 | **그대로 승계** + 목록의 경로가 대상에 있으면 그 파일 항목에 표시 |
| 푸터(검사·생략 건수, `생략:` 사유, 읽지 못한 소스, `한계:` 줄) | 그대로 승계 |

**`귀속 불신` 파일은 승계 구역에 싣는 것으로 끝내지 않는다** — 5-b의 중복 제거에서도 그 파일을
예외로 둔다.

### 2-b. check_invariants — confirmed 불변식에 대응 테스트 태그가 있는가

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_invariants.py" docs/superdomain/DOMAIN.md
```

- exit **0** 클린 / **1** 위반 있음 / **2** 해석 불가·사용법 오류 — check_imports와 같은 의미다.
  다만 **1이 두 상태를 겸한다**: 위반 발견과 `검사 불능`(테스트 소스 0건)이다. 둘을 가르는 것은
  exit가 아니라 출력이므로, exit 1을 보고 "위반 N건"이라고 적기 전에 아래 표의 `검사 불능` 갈래가
  비었는지 확인한다.
- **대상을 좁히는 옵션은 `--context <이름>` 하나다.** 그것도 수집 코퍼스만 좁히고 배치 오류·미선언
  문서 경고는 좁히지 않는다. diff로 좁히는 일은 실행이 아니라 **5단계의 병합**에서 한다.
- `--json`도 있고, 이쪽은 `limitation`까지 담는다(check_imports의 JSON에는 없다). 그래도 푸터는
  텍스트 실행분에서 가져온다 — 두 검사의 승계 절차를 갈라 두지 않는다.
- exit 2면 문서 코퍼스를 신뢰할 수 없는 상태다(표·ID 형식, 중복 ID, 읽지 못한 문서). stderr의
  `경로:라인: 메시지` 줄을 **그대로** 보여주고 멈춘다. 고치는 것은 이 스킬의 일이 아니다.
  **2-a는 그대로 돌린다** — 그 사유들은 domain 문서 코퍼스의 문제이고 2-a는 그 문서를 읽지
  않는다(실행 순서상 이미 돌아 있는 것이 보통이다). 나머지 한 사유인 `DOMAIN.md` 해석 실패는
  2-a도 같은 이유로 멈추게 하므로 그때는 결정적 검사가 둘 다 없는 실행이고, 그 사실을 리포트
  맨 위에 박는다.
- **domain 문서가 하나도 없어도 돌린다.** 고아 태그(문서에 없는 ID를 가리키는 태그)는 그 상태에서도
  나오고, 그것이야말로 드리프트다. 불변식이 0건이면 그 사실이 고지로 나온다.

출력 갈래를 **전부** 받아 둔다. 2-a와 마찬가지로 5단계에서 갈 곳이 서로 다르다.

| 갈래 | 모양 | 5단계에서의 처리 |
|---|---|---|
| 위반 | `<문서>:<줄>: [INV-...] …` (confirmed인데 태그 없음) | **경로가 코드가 아니라 domain 문서다.** 대상 파일 기준으로 가르지 말고 **1-b가 귀속한 컨텍스트** 기준으로 가른다 |
| 경고 | `<경로>:<줄>: 경고: …` (고아 태그·확정 전 구현·미선언 문서) | 그대로 승계 |
| 고지 | `고지: …: '## 불변식' 표가 없습니다 — 불변식 0건` 등 | 그대로 승계 |
| 검사 불능 | **두 줄이다** — `검사 불능: 테스트 소스가 없습니다 — …`와 `수집한 불변식 N건(confirmed X · proposed Y) — 대조하지 못했습니다` | 둘 다 승계. **이 줄이 있으면 클린이 아니다** |
| 푸터 | 집계 줄(`대조한 불변식 N건 …` — `검사 불능`이면 위의 `수집한 …` 줄이 그 자리를 대신한다), 읽지 못한 테스트 소스, `한계: …` | 그대로 승계 |

**이 검사가 보는 것은 존재뿐이다.** 리터럴 `@Tag("INV-...")`만 읽으므로 태그만 달린 빈 테스트나
불변식 서술과 다른 검증은 잡지 못한다(한계 줄이 그렇게 고지한다). **그 사각을 덮는 것은
domain-reviewer의 C4 (2)뿐이다** — 위임을 돌리지 못한 실행에서는 아무도 보지 않으므로, 그때는
§8-6에 그 사실을 적는다. 반대로 **대응 태그가 아예 없는 것은 이 검사가 판정하므로, 같은 지적을
에이전트가 다시 올렸다면 5-b에서 중복으로 정리한다.**

### 2-c. 필수 domain 문서가 없는 컨텍스트 — 가르는 것은 `- 분류:`다

2-b의 `고지: 컨텍스트 '<이름>'의 도메인 문서가 없습니다(docs/superdomain/contexts/<이름>.md) — 불변식 0건`은
`core`에서도 `generic`에서도 **같은 문면이다** — 그 검사는 분류를 읽지 않는다. 가를 재료는 이미 둘
다 있다: §0에서 읽은 `- 분류:`와 방금 받은 고지의 컨텍스트 이름이다. 셀 하나를 대조한다.
**새 스크립트가 아니라 2-b 출력과 선언의 대조이므로 「결정적 검사는 이 둘뿐」(§2 머리)은 그대로다.**

- 정본은 `governance/domain-doc-template.md` §1이다 — `core`·`supporting`에 domain 문서는
  **필수**이고 `generic`은 선택이다.
- 위 고지 중 **분류가 `core`·`supporting`인 것**을 갈라 리포트에 「필수 문서 없음」으로 싣는다.
  `generic`인 것은 정상 상태이므로 고지 그대로 승계 구역에 둔다(5-a 구역 3).
- **결정적으로 판정되는 사실이라 domain-reviewer에게 넘기지 않는다.** 에이전트의 범주는 다섯이고
  이 항은 그 안에 없다 — 새 범주를 만들지 않는다.
- 항목이 아니라 **고지**다. `rule` 칸에 넣을 형태가 없으므로 `review-log.jsonl`에는 쓰지 않는다.
  처분은 사람이 한다 — 문서를 만드는 것은 `/superdomain:model`, 분류를 다시 보는 것은
  `/superdomain:adr`이다.
- **2-b를 돌리지 못했으면 이 대조도 없다**(입력이 그 고지 목록이다). 그 사실을 §8-6에 적는다.

### 2-d. 용어 검증은 이 스킬의 일이 아니다

사용 가능한 스킬·커맨드 목록에 `superglossary:` 네임스페이스가 있으면 superglossary가 설치된 것이다.

- 설치돼 있으면 용어 검증을 **중복하지 않는다.** 그쪽 검증 커맨드를 이 스킬이 대신 실행하지
  말고, 목록에서 검증에 해당하는 커맨드를 찾아 리포트에 안내한다.
- 설치돼 있지 않으면 "용어 일관성은 이번 리뷰가 판정하지 않았다"를 리포트에 남긴다. 용어집은
  이 플러그인이 만들지 않는다. **C2(유비쿼터스 언어 불일치)는 그 대체물이 아니다** — 저쪽은
  도메인 문서의 용어와 코드 명명의 어긋남만 보는 의미론 관측이다.

## 3. 지식 선별 — domain-reviewer의 어휘를 여기서 정한다

지금 `${CLAUDE_PLUGIN_ROOT}/references/INDEX.md`를 읽는다. `knowledge/`를 통째로 또는 디렉터리
단위로 읽는 것은 금지다. INDEX의 `key`·`topic`으로 경로가 정해진다 —
`${CLAUDE_PLUGIN_ROOT}/references/knowledge/<topic>/<key>.md`. `topic`은 `strategic`·`tactical`·
`patterns` 셋이다.

**후보를 모은다.**

| | 후보 |
|---|---|
| (a) | 대상 컨텍스트가 `- 패턴:`으로 선언한 문서(`cqrs`·`outbox`·`event-sourcing`) |
| (b) | INDEX의 `read_when`에 `review`가 있는 문서 |
| (c) | 대상 프로젝트의 `docs/superdomain/conventions/` 문서 |
| (d) | 선언이 없어도 **diff에 패턴 징후가 보이는** patterns 문서 |

(d)의 징후 — 선언(`- 패턴:`)은 코드보다 늦게 따라오는 일이 흔하고, `cqrs.md`는 R1·R2를 "선언
여부와 무관하게 적용한다"고 명시한다(`## 규칙` 머리).

| 문서 | diff에서 보이는 징후 |
|---|---|
| `cqrs` | `*Command`·`*Query`·`*CommandHandler` 타입, `.command.`·`.query.` 패키지 세그먼트, 커맨드 메서드가 조회 결과를 반환 |
| `outbox` | outbox 테이블·엔티티·리포지토리, 트랜잭션 안의 이벤트 저장, 릴레이·퍼블리셔 |
| `event-sourcing` | 이벤트 스토어 append, 리플레이, 스냅샷, 이벤트 테이블 마이그레이션 |

**가지치기 — 후보에서 뺀다.**

1. **draft 문서.** INDEX의 `draft` 칸으로 판정한다. draft는 판정 근거가 아니므로 목록에 넣지
   않는다. 뺀 문서와 사유를 리포트에 남긴다 — 그 주제를 이번 리뷰가 판정하지 않았다는 뜻이다.
2. **diff에 해당 주제의 코드가 없는 문서.** 컨텍스트 간 참조·통합 코드가 diff에 없으면
   `context-mapping`은 넣지 않고, 영속 코드가 없으면 `persistence`는 넣지 않는다. 같은 기준을
   (b)의 나머지에도 적용한다 — `read_when`에 review가 있다는 것은 후보 자격이지 근거 자격이 아니다.

**(d)로 들어온 문서의 지위.** 선언 없이 들어온 patterns 문서는 기본적으로 **근거가 아니라
안건**이다 — 그 규칙에 걸리는 관측은 "선언되지 않은 패턴이 코드에 들어와 있다"는 사실과 함께
`discussion`으로 낸다. 예외는 문서가 선언 무관 적용을 스스로 명시한 조항뿐이다(`cqrs` R1·R2).

**로컬 우선.** (c)와 (a)·(b)가 같은 주제를 다루면 대상 프로젝트 문서가 이긴다. 위임 프롬프트에
그 사실을 한 줄로 적어 넘긴다.

**해결되지 않는 패턴 key는 리포트에 남긴다.** (a)의 `- 패턴:` 값이 INDEX에 없어 아무 문서도 열지
못했으면 그 key를 사실로 적는다(`- 패턴: saga` → 지식 문서 0건). 파서가 이 값을 검증하지 않으므로
(`governance/domain-template.md` 라벨 사전) 아무도 말하지 않으면 그 선언은 조용히 무효다.
**판정하지 않는다** — 오타인지 아직 없는 문서인지는 사용자가 가른다.

최종 목록은 리포트에 그대로 싣는다. 무엇을 근거로 판정했는지는 판정 결과의 일부다.

## 4. domain-reviewer 위임

`agents/domain-reviewer.md`가 인터페이스의 정본이다. Agent 도구로 `superdomain:domain-reviewer`
서브에이전트(`subagent_type: superdomain:domain-reviewer`)를 불러 아래 다섯을 전달한다. **없는
것을 채워 보내지 않는다** — 없으면 없다고 적어 보낸다.

| 입력 | 형태 |
|---|---|
| `docs/superdomain/summary.md` | 경로가 아니라 **파일 내용**을 넣는다 |
| 대상 컨텍스트의 `### 관계` 표 | 행을 그대로(상대·유형·계약). C1·C5의 유일한 근거다. 행이 없으면 **"관계 0건 — 이 컨텍스트에 대해 모든 쌍이 닫혀 있다"**로 적어 보낸다. "표를 못 찾았다"와 다른 사실이고, C1은 그 상태에서 오히려 더 세게 돈다 |
| 검토 대상 파일·diff 목록 | 저장소 루트 기준 상대 경로 목록. 컨텍스트 귀속과 "미귀속" 표시를 함께 |
| 선별 지식 문서 | **경로 목록**. 절대 경로여야 한다 |
| domain 문서 | `docs/superdomain/contexts/<컨텍스트>.md`가 있으면 경로 |

선택 입력 둘 — **2단계의 결정적 검사 결과**(2-a 위반의 `rule id`와 `path` 목록, 2-b가 낸 불변식
위반의 `INV-` id 목록)와 **2-a의 `귀속 불신` 경로 목록**. 앞의 것은 에이전트가 중복 제거에 쓰고,
뒤의 것은 그 중복 제거를 **풀어야 할 파일**의 목록이다. 2-b를 돌리지 못했거나 `검사 불능`으로
끝났으면 **그 사실을 적어 보낸다** — 목록이 비어 온 것과 검사가 없었던 것을 에이전트가 구별해야
`missing` 판정이 정직해진다. 실행하지 못했으면 "결정적 검사 미실행"이라고 적어 보낸다.

지켜야 할 것:

- **지식 문서 경로는 전개된 절대 경로로 적는다**(skill-protocol §2).
- **대상 컨텍스트가 둘 이상이면 컨텍스트마다 따로 위임한다.** 패턴·관계·domain 문서가
  컨텍스트마다 다르므로 한 번에 섞으면 엉뚱한 계약으로 판정한다. 미귀속 파일은 마지막 위임에
  묶고 미귀속임을 명시한다.
- 에이전트는 읽기 전용(Read·Grep·Glob)이다. 파일을 고치라고 지시하지 않는다.

**출력 수용.** 마지막 응답이 JSON 배열 하나다. 코드펜스가 붙어 있으면 벗겨서 파싱한다. 파싱할 수
없으면 **지어내서 채우지 않는다** — 원문을 리포트에 그대로 붙이고 "구조화 실패"로 표시한다.
`[]`은 정상적인 결과다.

배열 항목의 `related_rule`은 비어 있거나 `semantic.*` 범주 태그이고, `path`는 `(input)` 센티널일
수 있다. 둘 다 그대로 5·7단계로 흘려보낸다 — 자세한 것은 5단계의 `rule` 칸 표에 있다.

## 5. 리포트

### 5-a. 순서 — diff 안이 먼저, 밖은 뒤, 승계는 언제나

check_imports는 선언된 프로젝트 전체를 검사하므로 이번 변경과 무관한 위반도 함께 나온다.
**숨기지 않는다.** 세 구역으로 나눠 싣는다.

1. **이번 변경의 항목** — 대상에 속한 결정적 위반과 의미론 항목. 결정적 → 의미론 순,
   같은 갈래 안에서는 심각도 내림차순.
2. **변경 밖 기존 위반** — 대상 밖의 항목(2-a 위반은 파일 축, 2-b·의미론 항목은 아래
   이원 축이다)과 baseline 동결분. 별도 절로 구분하고, 이번 변경이 만든 것이 아님을 한 줄로 밝힌다.
3. **승계 — 두 검사 공용 구역이다.** 2-a에서는 `[0건 경고]` 줄들, `귀속 불신` 줄, 푸터(검사·
   생략 건수, 생략 사유, 읽지 못한 소스, 한계 고지). 2-b에서는 경고 3종(고아 태그·확정 전 구현·
   미선언 문서), 고지(`불변식 0건` 등), `검사 불능` 2줄, 푸터(집계 줄, 읽지 못한 테스트 소스,
   한계 고지). **diff와 무관하므로 필터링 대상이 아니다.** 문면을 고치지 말고 그대로 옮기되
   **어느 검사에서 온 승계인지 밝힌다.** 돌리지 못한 검사가 있으면 그 자리를 비우지 말고
   없다고 적는다.

**2-b 위반은 안/밖의 축이 다르다.** 경로가 domain 문서라 "대상 파일 안"이 성립하지 않는다. **1-b가
귀속한 컨텍스트가 검토 대상에 들어 있으면 구역 1**, 아니면 구역 2다. 파일 축으로 가르면 domain
문서는 diff에 거의 들어오지 않아 모든 불변식 위반이 "변경 밖"으로 밀려난다. **의미론 항목도 같은
이원 축을 쓴다** — 1-b 귀속이 서면 컨텍스트 축(domain 문서는 그 문서의 컨텍스트다), 서지 않으면
파일 축이다. 두 축 다 서지 않으면(`(input)` 등) **구역 2에 두고 그 사유를 적는다.**

**`귀속 불신` 목록에 오른 파일의 항목에는 그 사실을 한 줄로 붙인다** — 구역 1이든 2든, 결정적
항목이든 의미론 항목이든. 그 파일에 대해서는 "결정적 위반 0건"이 근거로 쓰이지 못한다.

### 5-b. 중복 제거 — 같은 **사실**만 합친다

같은 `path`에서 같은 사실이 두 경로로 올라오면 **결정적 항목만 남긴다.** 판단 기준은 "주제가
결정적 규칙에 속하는가"가 **아니라** "결정적 검사가 그것을 실제로 볼 수 있는가"다. 둘을 혼동하면
검사가 원리적으로 못 보는 지적까지 지워지고, 그건 불변 3의 위반이다.

| 의미론 항목이 | 처리 |
|---|---|
| 결정적 검사가 같은 파일에서 낸 위반과 **같은 사실** | 뺀다. 건수는 집계에 남긴다 |
| 컨텍스트 격리나 **불변식 태그 존재**가 판정하는 것과 같은 사실인데 **검사에는 안 나왔다** | **그 규칙이 이번 실행에서 실제로 검사됐고**(`[0건 경고]`에도 `생략:` 목록에도 없고) 통과했을 때만 뺀다 — 그때만 "안 나옴 = 통과"다. 그 밖에는 남긴다 |
| 그 검사가 **원리적으로 못 보는 것** — 판별 단서는 **두 검사의 한계 푸터**다(§8-6과 같은 목록) | **남긴다** |

2행의 전제("안 나옴 = 통과")가 깨지는 경우가 다섯이다. 그 규칙에 `[0건 경고]`가 붙은 경우(패턴은
있는데 매칭 파일이 0건이라 아무것도 검사하지 않았다), 푸터의 `생략:` 목록에 오른 경우,
2-a가 exit 2로 끝나 컨텍스트 격리를 검사하지 못한 경우, 2-b가 `검사 불능`으로 끝나 태그를 하나도 대조하지 못한
경우, 그리고 **그 파일이 2-a의 `귀속 불신` 목록에 있는 경우**(첫 `package` 선언으로 귀속됐으므로
그 파일에 대한 판정 자체를 검사가 스스로 부인했다). **전부 "검사가 통과시킨 것"이 아니라 "검사한
적이 없는 것"이므로 항목을 남긴다.** 2단계의 승계를 여기서 다시 보는 이유가 이것이다.

원리적으로 못 보는 것의 판별 단서는 둘이다 — **두 검사의 한계 푸터**가 열거하는 것(check_imports는
같은 패키지 안의 참조와 import 없는 FQN 사용, check_invariants는 상수로 간접 참조한 태그와
완전 수식 애너테이션, 그리고 태그가 달렸다는 것이 그 테스트가 불변식을 검증한다는 뜻은 아니라는 것),
그리고 `rationale`이 "기계 검사가 이것을 보지 못한다"를 근거로 들고 있는 것. 예: 컨텍스트 격리는
`import` 문만 보므로 **완전 수식 이름으로 남의 컨텍스트 타입을 쓴 코드**는 검사 대상 밖이다 —
주제가 경계라는 이유로 지우면 안 된다.

에이전트는 §3에서 이미 "의심되면 보고하지 않는다"로 걸러 보낸다. 여기까지 올라온 항목을 주제만
보고 한 번 더 지우면 같은 필터를 두 번 거는 것이다. **애매하면 남긴다** — 중복 한 줄은 읽는
사람이 지울 수 있지만, 지워진 지적은 아무도 되살리지 못한다.

### 5-c. 항목의 칸

`rule` · `분류` · `심각도` · `경로:라인` · `관측` · `근거` · `수정 제안`.

**`rule` 칸이 수용하는 세 형태와 센티널** — 어느 것도 다른 것으로 바꾸지 않는다. 이 셋이 곧
`review-log.jsonl`의 `rule` 어휘 전부이고, evolve가 그 형태로 축을 가른다(`skills/evolve/SKILL.md` 4단계).

| 형태 | 예 | 출처 |
|---|---|---|
| 파생 규칙 id | `derived.context-isolation` | 결정적 검사(2-a) |
| 불변식 ID | `INV-CLAIM-001` | 결정적 검사(2-b) |
| `semantic.*` 범주 태그 | `semantic.boundary-leak` | domain-reviewer |

에이전트가 근거로 삼은 문서의 규칙 절(`cqrs R1`)은 `rule` 칸이 아니라 **근거 칸**으로 간다 —
집계 키가 되는 자리에 소비자가 해석하지 못하는 형태를 넣지 않는다.
`path`가 `(input)`이면 파일을 지목할 수 없는 항목이라는 뜻이다. **그럴듯한 경로로 바꾸지 않는다.**

**분류** — `violation`→위반 · `missing`→누락 · `drift`→드리프트 · `discussion`→추가 논의.
결정적 검사의 위반은 전부 `위반`이다.

**심각도** — 의미론 항목은 domain-reviewer가 준 값을 **그대로** 쓴다. 구역과 무관하게 올리지도
낮추지도 않는다. 결정적 위반은 선언을 어긴 것이 확정된 상태이므로 대상 파일 안이면 `blocker`,
변경 밖 기존 위반이면 `warn`으로 낮춘다(이번 변경이 만든 것이 아니다). **2-b의 불변식 위반은
5-a의 컨텍스트 축을 그대로 쓴다** — 구역 1이면 `blocker`, 구역 2면 `warn`이다. 파일 축을
적용하지 않는다.

> **baseline이 먼저 가른다.** 2-a가 `[기존 부채]`로 낸 줄은 동결된 부채이므로 대상 파일 안이어도
> `warn`이고 구역 2로 간다. 매칭 키가 (규칙 id, 경로)뿐이라 같은 파일·같은 규칙의 **새 위반도
> 부채로 흡수되므로**(푸터가 그 한계를 낸다) 그때는 의미론 항목이 마지막 방어선이다.

**관측·근거 — 의미론 항목은 `rationale`이 여기에 착지한다.** domain-reviewer의 `rationale`은 규약상
**관측 한 문장 + 근거 한 문장**이고 "둘을 섞지 말고 둘 다 적는다"가 그 필드의 계약이다(에이전트
§7). 그 둘을 갈라 관측은 관측 칸에, 근거는 근거 칸에 싣는다. **요약해 버리거나 흘리지 않는다** —
rule id와 심각도만 남기면 왜 그것이 문제인지가 통째로 사라져 리포트가 판정의 근거를 잃는다.
결정적 항목의 관측은 검사 출력 메시지 원문이고, 근거는 규칙이 유래한 절이다(컨텍스트 격리는
`context-mapping.md ## 규칙 R1`). domain-reviewer가 `related_adr`·`related_invariant`를 주면 근거에
함께 싣는다. **읽지 않은 문서를 근거로 적지 않는다.**

**수정 제안** — 문장으로만. 에이전트는 수정 제안을 rationale 안에 문장으로 쓰므로(에이전트
"하지 말 것" 1항) 그 문장을 옮긴다. rationale에 없으면 지어내지 말고 비운다. 이 스킬은 코드를
고치지 않는다.

## 6. "추가 논의"는 domain 문서로 간다

분류가 `discussion`(추가 논의)인 항목을 귀속 컨텍스트의 `docs/superdomain/contexts/<컨텍스트>.md`
`## 열린 질문`에 올린다. `skill-protocol.md` §8을 따른다. 출처 표기는 `review`다. domain-reviewer가
질문 형태로 써 주므로 그 문장을 그대로 쓰고, 뒤에 관측 위치를 단다.

```
- [ ] [<YYYY-MM-DD> review] 승인 이후의 금액 변경을 누가 막는가? (관측: <경로:라인>)
```

## 7. `review-log.jsonl`에 append

경로는 git 루트의 `docs/superdomain/state/review-log.jsonl`이다. **append only** — 기존 줄을 고치거나
지우거나 정렬하지 않는다. 파일이 없으면 새로 만들고, 마지막 줄에 개행이 없으면 개행부터 넣는다.

한 항목당 **한 줄 JSON**, 키는 다섯이다.

```json
{"date": "2026-08-17", "rule": "derived.context-isolation", "path": "backend/src/main/kotlin/com/acme/claim/ClaimService.kt", "severity": "blocker", "note": "관계 표에 없는 billing 컨텍스트의 타입을 직접 import한다"}
```

| 키 | 값 |
|---|---|
| `date` | `date +%F`의 출력 |
| `rule` | 5-c의 세 형태 중 하나 |
| `path` | 항목의 경로. `(input)` 센티널도 그대로 |
| `severity` | `blocker` · `warn` · `info` |
| `note` | 항목의 한 줄 요약 — 의미론 항목은 **`rationale`의 관측 문장을 줄인 것**, 결정적 항목은 검사 메시지를 줄인 것. **줄바꿈·탭 금지**(한 줄이 한 레코드다) |

- `related_rule`이 비어서 온 의미론 항목은 `rule`에 `semantic.unspecified`를 넣고, **범주 태그
  없이 왔다는 사실을 리포트에 적는다.** 범주를 대신 지어내지 않는다.
- **변경 밖 기존 항목은 기록하지 않는다.** 매 리뷰마다 다시 관측되는 상수라서, 기록하면 evolve의
  반복 위반 신호(`evolution-signals.md` 신호 2·5)가 실제 반복이 아니라 리뷰 횟수를 세게 된다.
  신호 2의 "서로 다른 리뷰 2건"이라는 분모를 지키는 규약이다. 리포트에는 남고 로그에는 안 간다.
- **`check_invariants` 위반의 안/밖은 파일 경로가 아니라 귀속 컨텍스트로 가른다**(5-a). 구역 1의
  것은 `rule`에 `INV-` id를 담아 **기록하고**, 구역 2의 것은 구분 표기만 하고 기록하지 않는다.
  파일 축으로 가르면 경로가 domain 문서라 전부 "변경 밖"이 되어 한 건도 기록되지 않는다.
- 항목이 0건이면 아무것도 쓰지 않는다. 빈 리뷰 기록을 남기지 않는다.
- 쓴 뒤 전 줄이 파싱되는지 확인한다.
  ```bash
  python3 -c "import json,sys;[json.loads(l) for l in open('docs/superdomain/state/review-log.jsonl') if l.strip()]" && echo OK
  ```

## 8. 마무리 보고

1. **대상** — 파일 수, 컨텍스트별 분포, 범위 밖·미귀속·`귀속 불신`·삭제 파일.
2. **실행한 결정적 검사와 실행하지 못한 것** — 명령과 결과. 2-a는 푸터의 "검사한 컨텍스트 N개 /
   생략 M개" 줄을 그대로 인용한다. 2-b는 집계 줄(`대조한 불변식 N건 …`)을 그대로 인용하되
   `검사 불능`으로 끝났으면 그 **두 줄**(`검사 불능: …`과 `수집한 불변식 N건 … — 대조하지
   못했습니다`)을 대신 싣는다. 둘 중 하나라도 실행하지 못했으면 **이유와 함께 "절반만 검사한
   실행"임을 적는다.**
3. **선별한 지식 문서 목록**과 뺀 문서·사유(draft, 주제 무관).
4. **항목 집계** — 분류 × 심각도. 중복 제거로 뺀 건수도.
5. **쓴 것** — `review-log.jsonl` 추가 줄 수, domain 문서에 append한 열린 질문 수.
6. **이번 리뷰가 판정하지 않은 것** — 용어 일관성(2-d), 2-b를 돌리지 못해 성립하지 않은 필수
   domain 문서 대조(2-c), 두 검사의 한계 푸터가 말하는 것 중
   **의미론 위임도 덮지 못하는 것**(같은 패키지 안의 참조·FQN 사용, 상수로 간접 참조한 불변식
   태그·완전 수식 애너테이션), `귀속 불신` 파일의 판정, draft라서 뺀 주제. 푸터의 마지막 항목
   (태그와 실제 검증의 일치)은 C4 (2)가 판정하므로 여기가 아니라 항목으로 나온다 — **위임을
   돌리지 못했으면 그것도 이 절로 온다.** **이 절을 비우지 않는다.**
7. **커밋은 사용자가 한다.** 실제로 쓴 파일만 넣어 명령을 제안한다.
   ```bash
   git add docs/superdomain/state/review-log.jsonl              # + append한 domain 문서가 있으면 함께
   git commit -m "chore: 도메인 리뷰 결과 기록"
   ```

## 하지 말 것

- **코드를 고치는 것.** 수정 제안은 문장으로만 낸다. 이 스킬이 쓰는 파일은 `review-log.jsonl`과
  domain 문서의 `## 열린 질문` 둘뿐이다.
- **`DOMAIN.md`·domain 문서의 선언 부분·파생물을 고치는 것.** 결정적 검사가 exit 2로 멈추면
  어디를 고쳐야 하는지 알리고 멈춘다. 통과시키려고 선언을 고치지 않는다.
- **결정적으로 판정되는 것을 읽어 보고 판단하는 것.** 컨텍스트 격리와 confirmed 불변식의 태그
  존재는 스크립트의 몫이다. 검사를 돌리지 못했으면 "검사하지 못했다"고 적는다 — 대신 판단하지
  않는다.
- **`[0건 경고]`·`귀속 불신`·한계 푸터·생략 사유를 리포트에서 빼는 것.** diff와 무관하니 필터
  대상이 아니다.
- **변경 밖 기존 위반을 숨기는 것.** 구분해 표기하되 지우지 않는다.
- **draft 문서를 판정 근거로 인용하는 것.** INDEX의 `draft` 칸이 판정 기준이다.
- **`review-log.jsonl`의 기존 줄을 고치거나 파일을 다시 쓰는 것.** append only다.
- **domain 문서를 통째로 재생성하거나 생성물 헤더를 붙이는 것.** SSOT 문서다.
- **domain-reviewer가 준 severity를 올리는 것**, 비어 있는 `related_rule`을 그럴듯한 범주로 채우는 것,
  `(input)` 센티널을 지어낸 경로로 바꾸는 것.
- **`rationale`을 rule id와 심각도로 압축해 버리는 것.** 관측과 근거는 각각 칸이 있다(5-c).
- **결정적 검사가 원리적으로 못 보는 지적을 "주제가 격리니까" 지우는 것.** 5-b의 기준은 주제가
  아니라 그 검사가 그것을 볼 수 있는가다.
- **없는 것을 실행한 척하는 것** — `check_imports.py`의 대상 한정 옵션, superglossary의 검증 커맨드.
- **`검사 불능`으로 끝난 2-b를 "불변식 위반 없음"으로 적는 것.** 대조하지 못한 것과 통과한 것은
  다른 상태다.
- **`knowledge/`를 통째로 또는 디렉터리 단위로 읽는 것.** 언제나 INDEX 경유 선별 로드다.
