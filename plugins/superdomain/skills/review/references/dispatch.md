# 리뷰어 실행 계약 — Agent 도구가 없는 런타임

review·domain 스킬이 Agent 도구 없이(Codex 등) 리뷰어를 띄울 때 호출자와 리뷰어가 함께 따르는 계약이다. Claude Code에서는 이 문서를 쓰지 않는다 — Agent 도구로 `agents/`의 에이전트를 부르면 그 머리의 `model`·`tools`·`disallowedTools`가 적용된다.

리뷰어 역할 문서는 그 에이전트 정의 파일 자체다. Claude Code 밖에서는 머리의 `model`·`tools`·`disallowedTools`가 적용되지 않으므로, 아래 지시로 대신한다. 역할 파일은 자동 등록된 custom agent가 아니라 서브에이전트에게 읽힐 패키지 안의 문서다.

## 호출자

1. 현재 세션에서 실제 제공되는 서브에이전트 도구와 새 컨텍스트 옵션을 확인한다. `collaboration.spawn_agent`가 제공되면 `fork_turns: "none"`과 고유한 `task_name`을 사용한다. 다른 도구면 해당 스키마의 동등한 옵션을 사용한다. 문서의 역할 이름을 존재하지 않는 `agent_type`으로 호출하거나 앱의 새 채팅 만들기로 대체하지 않는다.
2. 도메인 관점은 [domain-reviewer.md](../../../agents/domain-reviewer.md), 컨벤션 관점은 [convention-reviewer.md](../../../agents/convention-reviewer.md)를 쓴다. 호출한 스킬의 실제 위치에서 역할·기준 문서를 찾아 절대 경로로 전달한다. 파일이 없으면 리뷰 미완료를 보고한다.
3. `model`은 지정하지 않는다 — 에이전트 정의의 `opus`·`sonnet`은 Claude 모델 별칭이라 옮길 수 없다. 서브에이전트 도구가 `reasoning_effort`를 받으면 domain-reviewer에 `high`, convention-reviewer에 `medium`을 준다(에이전트 정의가 domain-reviewer에 더 무거운 모델을 쓰는 의도를 옮긴다). 받지 않으면 세션 설정을 물려받는다.
4. 작성 대화·예상 지적·다른 리뷰어의 결과를 전달하지 않는다. 아래 입력만 제공하고, 역할 문서와 이 계약을 직접 읽도록 지시한다.

   ```text
   역할 문서: <패키지 안 역할 문서의 절대 경로>
   실행 계약: <이 문서의 절대 경로>
   모드: <정의 검토 | 변경 검토 | 전체 점검>
   프로젝트 루트: <절대 경로>
   DOMAIN.md: <절대 경로 | 없음; 커밋 범위면 저장소 상대 경로와 읽을 해시>
   기준 문서: <패키지 안 가이드의 절대 경로>
   대상: <git -C로 고정한 읽기 명령과 상태별 파일 목록 | 프로젝트 전체>
   자료 버전: <작업 트리 | 커밋 범위 A와 B의 실제 해시; B의 git show로 문맥 읽기>
   제한: 읽기·검색만 수행. 파일/코드/설정 수정, 외부 작업, 추가 위임 금지.
   출력: 역할 문서의 지적·질문·검토 범위 형식. 못 읽은 자료는 미검토로 표시.
   ```

5. 두 관점이 활성화되면 두 작업을 시작한 뒤 결과를 기다린다. 한 리뷰어가 다른 리뷰어를 만들거나 상대 결과를 읽지 않는다. 동시에 실행할 자원이 없으면 그 제한을 알리고 자원이 확보된 뒤 진행한다. 독립 리뷰를 자기 검토로 바꾸지 않는다.
6. 실패·중단·자료 부족을 지적 없음으로 합치지 않는다. 실행하지 못한 관점과 이유를 최종 검토 범위에 적고, 전체 리뷰를 완료했다고 보고하지 않는다.

## 리뷰어

- 역할 문서의 「지키는 것」과 함께 아래를 지킨다. 역할 문서 머리의 `tools`에 적힌 것(읽기·검색·셸)만 쓴다고 보면 된다.
- 파일 읽기, 파일명·본문 검색, 글자 수 세기(파일을 읽기만 하는 한 줄 명령으로 세고 파일을 쓰지 않는다), `git diff`·`git log`·`git show`만 사용한다. 커밋 범위에서 B 안의 파일을 찾거나 검색할 때는 `git ls-tree`·`git grep`도 쓴다. 셸을 쓸 때도 이 읽기 작업만 한다. 파일 생성·편집·삭제, 테스트/빌드 실행, 패키지 설치, 네트워크·MCP·외부 서비스 작업을 하지 않는다. 작업 트리·인덱스·브랜치·설정을 바꾸지 않는다.
- 다른 에이전트·채팅을 만들거나 작업을 재위임하지 않는다. 범위가 크면 직접 나눠 읽고 읽은 범위와 미검토 범위를 보고한다.
- 변경 검토에서 새 파일은 전체를 변경으로 보고, 삭제 파일은 diff/이전 리비전에서만 읽는다. 컨벤션 관점은 삭제된 파일을 제외한다.
- 결과는 호출자에게 반환하며 파일로 저장하지 않는다.

이 제한은 **행동 지침**이다. 역할 문서가 편집·위임 도구를 제거하거나 별도의 읽기 전용 샌드박스를 설정하지는 않는다. 실제 권한은 부모 세션의 정책을 따른다. 강제 격리가 필요한 사용자는 프로젝트 custom agent와 샌드박스를 별도로 설정·검증해야 하며, 이 패키지가 그 설정을 자동 설치했다고 가정하지 않는다.
