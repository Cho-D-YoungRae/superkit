# 선언과 현실의 드리프트 대조

이 스킬은 두 개의 사실을 나란히 놓는다 — `DOMAIN.md`가 말하는 도메인 경계와 디스크에 실제로 있는
패키지. 어긋난 자리를 찾는 것이 이 스킬의 일이고, **어느 쪽이 맞는지 정하는 것은 이 스킬의 일이
아니다.** 없는 패키지는 "아직 안 만든 것"일 수도 "선언이 낡은 것"일 수도 있고, 그 둘은 처방이
정반대다. 그래서 불변이 셋이다.

1. **드리프트의 방향을 확인 없이 확정하지 않는다.** 각 항목에 [패키지 생성 / 코드 수정 /
   문서 수정 / 무시]를 제시하고 사용자가 고른다. 이것은 판단을 아끼라는 뜻이 **아니다** — 관측을
   근거로 어느 쪽이 맞아 보이는지 **한 줄로 권고하는 것이 이 스킬의 일**이고, 근거 없는 중립은
   친절이 아니라 판단 유기다. 금지는 확인 없는 **확정** 하나뿐이다(정본: `skills/init/SKILL.md`
   불변 1). "알아서 해주세요"는 확정 권한의 위임이 아니라 진행 속도의 요청이므로, 항목별 순회를
   **빠르게** 돌되 값과 근거를 보여주고 답을 받는다.
2. **대조하지 못한 것을 삼키지 않는다.** 파일이 없어서, 해석이 실패해서, 검사가 서지 않아서 보지
   못한 축은 **생략이 아니라 고지**다. "드리프트 없음"과 "대조하지 않음"은 다른 상태이고, 그 둘을
   구별해 주는 것이 이 리포트의 값이다.
3. **기존 코드를 고치지 않는다.** 이 스킬이 쓰는 파일은 셋뿐이다 — 확정받은 `DOMAIN.md` 편집,
   파생물(`docs/superdomain/summary.md`·생성 구역), 그리고 3-a의 처분으로 확정받은 **새 패키지
   디렉터리와 최소 스텁**(5-b). 있는 파일을 옮기거나 지우거나 내용을 바꾸지 않는다 — 동결된 격리
   위반을 갚는 것은 migrate, 지우는 것은 사용자, 결정을 기록하는 것은 adr이다. **SSOT를 고쳤으면**
   마지막 편집 뒤 받은 `OK:` 출력이 완료 조건이다.

이 스킬은 `references/knowledge/`를 읽지 않는다 — 대조의 재료는 선언, 검사기 출력, 디스크 관측
셋뿐이다. 형식의 정본은 `${CLAUDE_PLUGIN_ROOT}/references/governance/domain-template.md`이고
**아래의 `정본`은 전부 이 문서를 가리킨다.** 그 내용을 여기 복제하지 않는다 — 각 단계가 지시하는
시점에 그 절을 읽는다.

## 0. 위치와 초기화 게이트

```bash
git rev-parse --show-toplevel
```

그 경로의 `DOMAIN.md`가 대조의 한쪽 항이다. 하위 디렉터리에서 시작했어도 여기로 올라와서
작업한다. 파일이 없으면 아래를 알리고 **중단**한다.

> superdomain이 초기화되지 않았습니다. `/superdomain:init`으로 도메인 경계 선언을 먼저 세우세요.

## 1. 선언을 읽는다 — 두 실행과 문서 직접 읽기

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/parse_domain.py" docs/superdomain/DOMAIN.md
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_imports.py" docs/superdomain/DOMAIN.md --json
```

**앞은 게이트다.** exit **0**이면 `OK: 프로젝트 N, 컨텍스트 M` 한 줄이 나온다 — 이 스크립트는
JSON을 내지 않으므로 값은 전부 `DOMAIN.md`에서 직접 읽는다. exit **1은 해석 오류**다.
**중단하지 않는다** — 해석 실패 자체가 이번 대조의 첫 결과이므로 3-e의 드리프트로 올린다. 다만
이번 실행 전체를 **신뢰 불가**로 표시하고, 선언에 기대는 축(3-a·3-b, 그리고 3-d의 컨텍스트 맵)은
**대조 불능**으로 고지한다. 지어내서 메우지 않는다. exit **2는 사용법 오류**이므로 인자를 고쳐
다시 돌린다.

**뒤에서 읽는 것은 위반 목록이 아니다.** 규칙 위반의 판정은 `/superdomain:review`의 몫이고
여기서 겹쳐 올리면 같은 지적이 두 리포트에 오른다. 이 스킬이 가져가는 것은 **침묵 층위 넷**이며,
이 넷이 3-a·3-b 관측의 신뢰도를 정한다.

| 키 | 뜻 | 이 스킬에서의 쓰임 |
|---|---|---|
| `zero_match[]` | 그 컨텍스트 패키지에 귀속된 소스가 0건이다(`[0건 경고]`) | 3-a의 부재 판정과 대조한다 |
| `skipped[]` | 검사가 아예 서지 않았다(경로 없음 / 경로가 파일 / 소스를 전부 읽지 못함 / 소스 없음) | 그 컨텍스트는 3-a가 **판정하지 않는다**. 사유를 그대로 옮긴다 |
| `unreadable[]` | 읽지 못한 소스 | 2-b 인벤토리의 구멍이다 |
| `ambiguous_package[]` | `package` 선언이 2건 이상이라 귀속을 믿을 수 없는 소스 | 그 파일이 만든 패키지 관측은 근거가 약하다. 3-b 후보에 그 사실을 붙인다 |

exit **2**면 격리 검사가 통째로 없는 상태다. stderr의 `경로:라인: 메시지`를 **그대로** 보여준다.
`DOMAIN.md` 해석 실패가 원인이면 이미 3-e에 올라 있고, `docs/superdomain/state/baseline.jsonl`의 깨진 줄이
원인이면 **처분이 다르다** — 그 파일을 고칠 권한은 migrate에 있으므로 여기서 손대지 않고 넘긴다.
어느 쪽이든 3-a·3-b는 2단계의 직접 관측만으로 진행하되, **침묵 층위 넷을 얻지 못했다는 사실을
고지**한다.

**어느 값을 어디서 읽는가.** 파서가 JSON을 내지 않으므로 전부 문서에서 직접 읽는다.

| 입력 | 출처 |
|---|---|
| 프로젝트 경로·기본 패키지 | `## 프로젝트: <이름>` 절의 `- 경로:`·`- 기본 패키지:` |
| 컨텍스트 패키지 패턴 | `- 패키지:`의 쉼표 목록. **라벨이 없으면 규약 기본값 `<기본 패키지>.<컨텍스트>..`** |
| 분류·적용 패턴 | `- 분류:`·`- 패턴:` |
| 관계가 연 쌍 | `### 관계` 표의 데이터 행(상대·유형·계약) |

문서에서 직접 읽는 값에는 파서의 읽기 규약이 그대로 걸린다: **라벨 값 끝의 괄호 주석은 값이
아니고**(`core (core | supporting)` → `core`), **패키지 값은 후행 점을 떼고 `..`를 붙인 접두
패턴으로 정규화되며**, **표 데이터 행은 헤더가 선언한 칸 수까지만 읽혀 그 뒤 글자는 버려진다.**
파서가 버리는 것을 값으로 읽으면 있지도 않은 드리프트가 나온다.

## 2. 스캔 범위와 관측

### 2-a. 범위는 선언된 프로젝트 경로 안뿐이다

`- 경로:` 아래만 본다. 미선언 프로젝트(frontend 등)는 **오검출 대상이 아니다** — 거버넌스 대상이
아닌 것을 "미선언 패키지"로 올리면 리포트가 매 실행 같은 잡음으로 채워진다. 숨기지도 않는다:
루트에서 관측된 다른 빌드 루트는 **"범위 밖"** 목록에 이름만 남긴다. 거버넌스에 올릴지는 init의
인터뷰가 정한다.

프로젝트 경로가 `.`이면 저장소 루트가 프로젝트 루트다.

### 2-b. 관측 — 프로덕션 패키지 인벤토리

```bash
find "<프로젝트 경로>" -type d \( \
     -name build -o -name out -o -name target -o -name .git -o -name .gradle \
  -o -name .idea -o -name .kotlin -o -name .settings -o -name .venv -o -name node_modules \
  -o -path '*/src/test*' -o -path '*/src/*Test' \) -prune \
  -o \( -name '*.kt' -o -name '*.java' \) -exec grep -hE '^[[:space:]]*package[[:space:]]' {} + \
  | sed -E 's/^[[:space:]]*package[[:space:]]+//; s/[;[:space:]]*$//' | sort -u
```

**가지치기 목록은 `check_imports.py`의 `SKIP_DIRS`와 `src` 아래 테스트 소스셋 규칙을 그대로 옮긴
것이다.** 좁히면 이 관측만 보는 파일이 생겨 3-b가 매 실행 유령 「미선언 패키지」를 올린다 —
Maven의 `target/generated-sources/`와 Android의 `src/androidTest`가 전형이다. 정본이 바뀌면 이
목록도 따라와야 한다.

**패턴 매칭 규약** — 컨텍스트 패키지는 언제나 `..`로 끝나는 접두 패턴이고 "그 패키지와 그 하위
전부"를 뜻한다. 패턴 `x..`에 패키지 `p`가 드는 조건은 **`p == x` 또는 `p`가 `x.`로 시작**하는 것
하나다. 부분 문자열로 맞추지 않는다 — `com.acme.claim`이 `com.acme.claiming`을 삼킨다(귀속
규칙의 정본은 `scripts/check_imports.py`의 `_owning_context`이고, 여기서는 그것을 손으로 재현할
뿐이다). 둘 이상 매칭되면 접두가 가장 긴 컨텍스트가 이기지만, 파서가 컨텍스트 패키지의 접두 겹침을
이미 오류로 막으므로 해석에 성공한 문서에서는 동률이 나오지 않는다.

**이 관측의 한계를 리포트에 남긴다**: 테스트 소스와 `.kt`·`.java`가 아닌 소스는 보지 않는다.
그 자리에 있는 드리프트는 이번 실행이 판정하지 않았다. 1단계의 `skipped`·`unreadable`이 걸린
프로젝트가 있으면 **그 프로젝트의 인벤토리도 온전하지 않다** — 그 사실을 함께 적는다.

## 3. 대조 축 다섯

각 축의 결과는 **항목**이고, 항목마다 축·경로(또는 문서:라인)·관측·권고 한 줄을 갖는다. 0건인
축도 "0건"으로 적는다.

### 3-a. 선언된 컨텍스트의 패키지가 디스크에 없다

| 갈래 | 대조 |
|---|---|
| 프로젝트 | `- 경로:`의 디렉터리가 실재하는가 |
| 컨텍스트 | 그 컨텍스트의 패키지 패턴에 매칭되는 패키지가 2-b 인벤토리에 하나라도 있는가 |

- **`check_imports`의 `zero_match[]`가 같은 사실을 말한다.** 이 축의 목록과 그 목록이 같아야 하고,
  갈리면 손으로 재현한 매칭이 어긋난 것이다. 그 사실을 적고 **검사 쪽을 믿는다** — 귀속 규칙의
  정본이 거기다.
- **`skipped[]`에 오른 컨텍스트는 이 축이 판정하지 않는다.** 경로가 아직 없는 것과 패키지가 어긋난
  것은 고칠 자리가 다르므로 뭉뚱그리지 않는다. 사유 문면을 그대로 옮긴다.
- **컨텍스트가 패키지를 여럿 선언했으면 하나라도 매칭될 때 부재가 아니다.** 나머지 미실현 패턴은
  별도 관측으로 한 줄 남긴다 — 항목을 패턴 수만큼 부풀리지 않는다.
- **1순위는 [패키지 생성]이다.** 선언이 코드보다 먼저 서 있는 상태는 오류가 아니라 정상 플로우의
  중간 단계이고(그린필드·설계 선행), 그 자리를 만드는 것이 5-b다.

### 3-b. 선언 밖 패키지가 컨텍스트 후보로 보인다

2-b 인벤토리 중 어느 컨텍스트 패키지 패턴에도 들지 않는 것. **곧바로 드리프트로 올리지 말고 세
갈래로 가른다.**

| 무매칭 패키지가 | 판정 |
|---|---|
| 선언된 프로젝트 경로 **밖**에 있다 | 범위 밖(2-a) |
| 어느 컨텍스트에도 속하지 않는 조립·설정·인프라 코드다(부트스트랩, 공용 유틸) | 정상이다 — 격리 검사도 이 코드를 도메인 경계 밖으로 보고 무시한다. 목록에만 남긴다 |
| `기본 패키지` 아래에 도메인 코드로 보이는 패키지가 있다 | 드리프트 후보 |

드리프트 후보의 해석은 최소 셋이다 — **새 컨텍스트가 생겼다 / 기존 컨텍스트의 `- 패키지:`가 실제
위치를 덮지 못한다 / 컨텍스트 이름과 패키지 세그먼트가 어긋났다.** 어느 것인지는 사람만 안다.
관측(패키지 이름, 그 아래 파일 수, 어느 프로젝트에 있는지)을 붙여 셋을 나란히 제시하고 권고한다.

- **셋째는 파서도 격리 검사도 잡지 못한다.** 선언이 `order`인데 실제 소스가 `...orders...`인 경우가
  전형이고, 이름은 정규 값이라 게이트를 통과한다 — 어긋난 곳은 이름과 실현 사이다. 그 컨텍스트는
  3-a에 "패키지 없음"으로, 그 패키지는 여기에 "미선언"으로 각각 올라온다. **두 항목이 이름만 다른
  짝이면 한 항목으로 묶어 제시한다** — 고칠 곳은 `- 패키지:`(문서 수정)이거나 패키지
  위치(코드 수정)이고, 어느 쪽인지는 사용자가 정한다.
- **`ambiguous_package[]`에 오른 파일이 만든 패키지에는 그 사실을 붙인다.** 그 파일의 `package`
  선언이 2건 이상이라 첫 선언으로 귀속됐으므로, 인벤토리에 실린 패키지 이름 자체가 주석 처리된 옛
  선언일 수 있다.
- **새 컨텍스트의 등재는 이 스킬이 하지 않는다**(5-a). 경계·분류·패키지를 정하는 인터뷰가
  필요하고 그 정본은 init이다.

### 3-c. 깨진 ADR 참조

```bash
grep -rnE "[0-9]{4}-[0-9]{2}-[0-9]{2}-[a-z0-9-]+" DOMAIN.md docs/
grep -rn "^- 관련:" docs/superdomain/adr/
ls docs/superdomain/adr/
```

**첫 명령 하나가 세 표기를 전부 덮는다.** 머리의 링크도 `- 관련:`도 자유 서술도 같은 파일명을
쓰기 때문이다(정본: `skills/adr/SKILL.md` 7-c의 표). 날짜 뒤에 `-`와 slug 문자가 더 붙어야
걸리므로 `- 날짜: 2026-03-11` 같은 맨 날짜는 히트에 섞이지 않는다.

**둘째 명령이 있는 이유는 날짜를 뗀 표기다.** `- 관련:`이나 자유 서술에 날짜를 빼고 slug만 적으면
(`open-claim-admin-pair`) 그것은 소문자 낱말이라 **어떤 정규식으로도 참조와 산문을 갈라낼 수
없다.** 그래서 `- 관련:` 줄만은 통째로 훑어 **눈으로 대조한다**: 적힌 파일명마다 대응 파일이
있는지 아래 표로 판정한다. 자유 서술의 slug-only 표기는 이 축이 놓칠 수 있고, **그 한계는 0건
보고에 함께 적는다.**

**`docs/superdomain/adr/`가 없으면** 뒤의 두 명령이 `No such file or directory`로 끝난다. 그것은 이 축의
결과가 0건이라는 뜻이 아니라 **결정 기록이 하나도 없다**는 관측이다 — 참조가 있는데 디렉터리가
없으면 그 전부가 깨진 참조다. 디렉터리도 참조도 없으면 "0건(대조할 대상 없음)"으로 적는다. 오류
문면을 삼키지 않는다.

참조마다 대응 파일이 `docs/superdomain/adr/`에 있는지 보고, 있으면 그 문서의 `- 상태:`를 읽는다.

| 관측 | 뜻 |
|---|---|
| 파일 없음 | 깨진 참조 — 근거가 존재하지 않는다 |
| `superseded` | **근거가 폐기된 결정이다.** adr 7-c에서 「보류」로 남겨 둔 항목이 여기로 온다 |
| `proposed` | 근거가 아직 확정 전이다 — 오류는 아니지만 고지한다 |
| `accepted` | 정상 |

- **`### 관계` 표의 `계약` 칸이 가리키는 ADR이 이 축의 중심이다.** 쌍이 열리면 그 두 컨텍스트
  사이의 격리 검사가 영구히 꺼지므로(adr 3-b), 그 근거가 없거나 폐기됐다는 것은 검사가 근거 없이
  꺼져 있다는 뜻이다.
- 처분 세 갈래는 `skills/adr/SKILL.md` 7-c의 표와 같다: **참조 갱신**(새 결정에서도 그 근거가
  유효하다) / **참조 제거**(근거가 사라졌다) / **보류**. 파일·라인·원문을 그대로 보여주고 고르게
  한다. **참조만 갈아 끼우는 자동 처리를 하지 않는다** — 근거가 사라진 참조가 새 ADR의 권위를 입는
  것이 가장 나쁜 결과다.
- **관계 표의 행 자체를 지우거나 더하는 처분은 이 스킬이 하지 않는다.** 그 한 줄이 격리 검사의
  허용 목록이라, 지우면 그때까지 통과하던 참조가 위반으로 돌아선다. 근거가 사라졌다고 판단되면
  그것은 새 결정이므로 `/superdomain:adr`로 보낸다(편집 자리는 그 스킬 8단계가 짚는다).
  여기서 하는 것은 **깨진 참조 표기의 정정**까지다.
- **다른 ADR 본문이 옛 ADR을 인용한 것은 드리프트가 아니다** — 그 문서들도 `accepted`이고 양방향
  링크가 독자를 현재 결정으로 데려간다(adr 7-b). 고치라고 하지 않는다.
- domain 문서의 불변식과 테스트 태그의 대조는 이 스킬이 아니라 `check_invariants.py`·review의
  몫이다. 여기서 다시 보지 않는다.

### 3-d. 파생물이 선언보다 낡았다

**mtime을 쓰지 않는다.** 체크아웃·포맷터가 파일 시각을 올리고, 반대로 손으로 고친 파생물은
mtime이 최신이어도 내용이 틀리다. 판정 근거는 언제나 **내용 대조**다.

| 파생물 | 대조하는 것 |
|---|---|
| `docs/superdomain/summary.md` | 첫 줄의 생성물 헤더, 컨텍스트 표의 행 집합(이름·분류·소속 프로젝트)이 선언과 같은가, 30줄 이하인가 |
| 컨텍스트 맵 생성 구역 | 노드 집합 == 선언된 컨텍스트, 엣지 == `### 관계` 표가 연 쌍 |

- **마커 문자열의 정본은 정본 문서의 「생성 구역 마커」이고, 그 구역을 다루는 규정의 정본은
  `skills/init/SKILL.md` 7-b다.** 두 줄 모두 줄 전체가 정확히 일치해야 하며, 짝 없는 마커의 처분도
  거기가 정한다. 구역 자체가 없으면 그것도 항목이다(생성된 적이 없다).
- **`docs/superdomain/summary.md`의 「전역 핵심 규칙」은 자유 서술이라 기계 대조가 성립하지 않는다.**
  대조하지 않았다고 적는다. 이 파일은 SessionStart 훅이 통째로 주입하는 유일한 산출물이라, 여기
  남은 낡은 문장은 매 세션 사실로 읽힌다 — 사용자에게 직접 확인을 권한다. **동결 건수를 문장에 박아
  둔 경우가 그 전형이다**: migrate가 부채를 줄이면 그 숫자는 즉시 거짓이 되지만 기계는 그것을
  판정하지 못한다.
- **`docs/superdomain/state/baseline.jsonl`은 파생물이 아니다.** 그 파일이 있다는 것은 그 프로젝트가 부채를
  동결했다는 선언이고, 축소하는 권한은 migrate에만 있다(동결은 init). **이 스킬은 그 파일을 읽지도
  쓰지도 않는다.**

### 3-e. 해석 오류 자체가 드리프트다

1단계의 `parse_domain.py`가 exit 1로 낸 `경로:라인: 메시지` 줄을 **그대로** 항목으로 올린다. 필수
라벨 누락, 비정규 값(분류·관계 유형), 없는 프로젝트·컨텍스트를 가리키는 참조, 컨텍스트 패키지의
접두 겹침, 관계 표의 헤더·구분선 이상, 그리고 **구 템플릿에서 넘어온 퇴역 라벨**이 한 목록으로
온다. `check_imports.py`가 exit 2로 끝났고 그 사유가 해석 실패가 아니면(1단계) 그 줄도 여기 함께
싣되 처분은 1단계가 정한 대로다.

이 축의 선택지는 **[문서 수정]과 [무시] 둘뿐이다.** 파싱되지 않는 선언 위에서는 코드와의 대조
자체가 성립하지 않으므로 패키지 생성도 코드 수정도 답이 될 수 없다. **[무시]는 "그대로 두기"이고,
고르더라도 이번 실행이 신뢰 불가였다는 표기는 남는다** — 그 표기를 지우는 것은 선택지가 아니다.
사용자가 지금 고치지 않기로 하면 그 사실을 리포트 맨 위에 박는다.

## 4. 처분 — 네 선택지

**항목마다 넷을 제시하고 고르게 한다.** 축별 1순위와 각 선택지의 뜻은 아래가 전부다.

| 선택지 | 뜻 | 누가 하는가 |
|---|---|---|
| **패키지 생성** | 선언이 맞다 — 없는 자리를 만든다 | **이 스킬**(5-b) |
| **코드 수정** | 선언이 맞다 — 있는 것을 옮기거나 지운다 | **사용자.** `/superdomain:migrate`는 **`docs/superdomain/state/baseline.jsonl`에 동결된 격리 위반일 때만** 갈 곳이다 — 그 파일이 없으면 그 스킬은 입장 즉시 "동결된 부채가 없습니다"로 끝난다. **이 스킬은 기존 코드를 옮기거나 지우지 않는다** |
| **문서 수정** | 현실이 맞다 — 선언을 고친다 | 이 스킬(5-a). 인터뷰가 필요하면 init, 관계 표는 adr |
| **무시** | 지금 판단할 재료가 없거나 의도된 상태다 | 아무도. 리포트에만 남는다 |

| 축 | 1순위 | 근거 |
|---|---|---|
| 3-a 선언된 패키지 부재 | **패키지 생성** | 설계 선행은 오류가 아니라 정상 플로우의 중간 단계다 |
| 3-b 선언 밖 패키지 | 없음 | 새 컨텍스트인지 이름이 어긋난 것인지는 관측으로 갈리지 않는다 |
| 3-c 깨진 ADR 참조 | 문서 수정 | 코드와 무관하다. 갈래는 adr 7-c의 셋 |
| 3-d 낡은 파생물 | 문서 수정(재생성) | 파생물은 언제나 SSOT에서 다시 만든다 |
| 3-e 해석 오류 | 문서 수정 | 나머지가 성립하지 않는다. 남는 갈래는 [무시]뿐이고, 그때도 신뢰 불가 표기는 남는다 |

- **1순위가 있다는 것은 기본값이 있다는 뜻이지 확정됐다는 뜻이 아니다.** 1순위를 포함해 넷을
  보여주고 답을 받는다.
- **1순위가 "없음"인 축에서 침묵하지 않는다.** 관측을 근거로 하나를 권고한다 — 예: "이 패키지는
  최근 3주 안에 생겼고 소스가 12개다 → 새 컨텍스트일 가능성이 크니 init을 권한다". 근거를 함께
  적어, 사용자가 근거를 보고 뒤집을 수 있게 한다.
- **무시는 이번 회차에만 유효하다.** 억제 목록 파일을 만들지 않는다. 다음 실행에 같은 항목이 다시
  올라오는 것이 정상이고, 항구적으로 정당화하려면 `/superdomain:adr`로 결정을 남기는 것이 그
  자리다.

## 5. 반영

**고른 것만 반영한다 — 자동 적용은 없다.** 4단계에서 답을 받지 못한 항목은 리포트에만 남고,
아무것도 고르지 않았으면 아무 파일도 쓰지 않고 리포트로 끝낸다.

### 5-a. 문서 수정 — 확정받은 편집만

- **편집 전에 원문과 변경안을 나란히 보여주고 확정을 받는다.** 표의 한 줄이어도 그렇다.
- **고쳐도 되는 것과 안 되는 것**의 경계는 `skills/init/SKILL.md` 6단계 「고쳐도 되는 것과 안 되는
  것」과 같다: 형식 오류(라벨 오타·표 위치·구분선·마커)는 고치고, **사용자가 결정한 값**(컨텍스트
  이름·분류·패키지·관계)은 게이트를 통과시킬 목적으로 바꾸지 않는다. 같은 오류가 두 번 반복되면
  멈추고 파서 출력 원문을 보여주며 묻는다.
- **인터뷰가 필요한 등재는 이 스킬이 하지 않는다.** 새 컨텍스트·새 프로젝트를 선언에 올리려면
  경계·분류·패키지·관계를 정해야 하고, 그 인터뷰의 정본은 init이다. 그쪽으로 넘긴다.
- **`### 관계` 표에 쌍을 여는 편집도 여기서 하지 않는다.** 새 쌍을 여는 결정은 ADR이
  필수이고(adr 3-b), 편집 자리를 짚는 것은 adr 8단계다.
- 이 스킬이 쓰는 문서 수정은 **이미 결정된 것의 표기를 현실에 맞추는 편집**까지다 — `- 패키지:`
  값의 정정, 깨진 ADR 참조 표기의 정정, 라벨 오타·형식 정정.

### 5-b. 패키지 생성 — 이 스킬이 직접 만든다

3-a에서 [패키지 생성]으로 **확정받은 항목만** 만든다. 만드는 것은 **자리뿐이고, 도메인 코드를
지어내지 않는다.**

- **자리는 선언이 정한다.** 컨텍스트의 패키지 패턴에서 `..`를 떼면 그것이 패키지이고, 디렉터리는
  그 패키지의 점을 `/`로 바꾼 경로다. 손으로 조립하지 않는다.
- **소스 루트 관례는 관측해서 정한다.**

  ```bash
  find "<프로젝트 경로>" -type d -path '*/src/main/kotlin' -o -type d -path '*/src/main/java'
  ```

  관측되지 않으면 **지어내지 않고 묻는다.** 어디에 소스를 두는지는 그 프로젝트의 결정이지 이
  스킬의 기본값이 아니고, 엉뚱한 루트에 만든 패키지는 검사에도 빌드에도 잡히지 않는다.
- **만드는 것은 디렉터리와 최소 스텁 하나까지다.** 빈 디렉터리는 git이 추적하지 않으므로 패키지
  선언 한 줄만 든 파일 하나를 함께 만든다. 그 이상(타입·인터페이스·빌드 스크립트)은 만들지 않는다.

  ```kotlin
  package com.acme.claim
  ```

  파일 이름은 제안하고 확정받는다. **이 파일은 첫 실제 타입이 들어오면 지워질 자리**라는 사실을
  함께 적는다 — 남겨 두면 다음 실행이 그것을 "실현된 패키지"의 근거로 읽는다.
- **있는 디렉터리·파일을 덮지 않는다.** 목표 자리에 이미 무엇이 있으면 3-a의 판정이 틀렸다는
  뜻이므로 멈추고 관측을 다시 보여준다.
- **만든 뒤 `check_imports.py`를 다시 돌린다.** 그 컨텍스트의 `[0건 경고]`가 사라졌으면 자리가
  실제로 인식된 것이고, 남아 있으면 패키지가 선언과 어긋나게 만들어진 것이다 — 그때는 만든 것을
  보여주고 어디가 어긋났는지 함께 본다. **돌리지 않고 "만들었다"로 끝내지 않는다.**
- **빌드 등록은 이 스킬의 일이 아니다.** 패키지는 디렉터리일 뿐이라 등록할 것이 없다. 새 빌드
  단위가 필요하다는 판단이 나오면 그것은 선언 자체를 바꾸는 안건이므로 init으로 보낸다.

### 5-c. 코드 수정으로 고른 항목

**이 스킬은 기존 코드를 옮기거나 지우지 않는다.** 무엇을 어디로 옮기면 선언과 맞는지(대상 경로·
목표 패키지)를 정확히 제시하고 멈춘다. 동결된 격리 위반을 갚는 것은 `/superdomain:migrate`이고,
지우는 것은 사용자다.

### 5-d. 게이트 → 파생물 재생성 → 게이트

`DOMAIN.md`를 한 글자라도 고쳤으면 돌린다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/parse_domain.py" docs/superdomain/DOMAIN.md
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_imports.py" docs/superdomain/DOMAIN.md
```

- 앞은 선언이 여전히 해석되는지, 뒤는 **그 편집으로 위반이 의도한 만큼만 변했는지**다. `- 패키지:`
  를 고치면 컨텍스트의 귀속 범위가 통째로 바뀌어 위반 목록이 뒤집힌다 — 1단계의 수치와 나란히
  놓고 본다. 의도한 적 없는 변화가 보이면 라벨이나 표 구조를 잘못 건드린 것이다.
- 이어서 파생물을 재생성한다. 관례는 `skills/init/SKILL.md` 7-a·7-b가 정본이고 여기서 다시 정하지
  않는다 — `docs/superdomain/summary.md`는 30줄 이하, 생성 구역은 **여는 마커가 이미 있으면 새로 쓰지
  않고 그 쌍 사이만 교체**, 짝이 없는 마커는 갱신하지 않고 오류로 보고.
- **재생성은 파생물의 손 편집을 지운다.** 3-d가 낡음으로 판정한 것이 사실은 누군가 손으로 넣은
  내용일 수 있으므로, 쓰기 전에 diff를 보여주고 확정을 받는다.
- 컨텍스트 맵 생성 구역은 `DOMAIN.md` 안이다 — 고쳤으면 **게이트를 한 번 더** 돌린다. 컨텍스트
  수가 직전 실행과 같아야 하고, **이 실행의 `OK:` 출력이 이 스킬의 완료 조건이다.**
- **들어올 때 이미 깨져 있었고(3-e) 사용자가 고치지 않기로 했으면** 깨진 채로 끝낸다. 그때의
  완료 조건은 `OK:`가 아니라 **그 사실을 리포트에 박는 것**이다 — 남의 실패를 통과시키려고 선언을
  고치지 않는다.

## 6. 마무리 보고

1. **범위** — 대조한 프로젝트와 경로, "범위 밖"으로 남긴 빌드 루트, 2-b 관측의 한계(테스트 소스·
   다른 언어 소스 미대조).
2. **축별 집계** — 다섯 축 각각의 항목 수. **0건도 적는다.**
3. **대조하지 못한 것** — 해석 실패로 건너뛴 축, 1단계가 준 `skipped`·`unreadable`·
   `ambiguous_package` 고지, 기계 대조가 성립하지 않는 것(`docs/superdomain/summary.md`의 전역 핵심
   규칙). **이 절을 비우지 않는다.**
4. **처분** — 항목별로 사용자가 고른 것과 그 결과. 무시한 항목도 남긴다.
5. **쓴 파일** — `DOMAIN.md`의 어느 줄·표, `docs/superdomain/summary.md`, 생성 구역, **만든 패키지
   디렉터리와 스텁 파일**. 게이트의 `OK:` 줄을 1단계 수치와 나란히 인용한다. 아무것도 쓰지
   않았으면 그렇게 적는다.
6. **넘긴 것** — init(경계 등재·새 컨텍스트)·adr(관계 표를 여닫는 결정)·migrate(동결 부채)·
   model(도메인 문서)로 넘긴 항목과 권하는 명령.
7. **커밋은 사용자가 한다.** 실제로 쓴 파일만 넣어 명령을 제안한다.

   ```bash
   git add DOMAIN.md docs/superdomain/summary.md
   git commit -m "docs: 선언과 코드의 드리프트 정정"
   ```

## 하지 말 것

- **드리프트의 방향을 확인 없이 정하는 것.** 없는 패키지를 "선언이 낡았으니" 지우거나, 미선언
  패키지를 묻지 않고 선언에 올리는 것 둘 다다. 권고는 하고 확정은 받는다.
- **권고 없이 선택지만 나열하는 것.** 관측을 근거로 어느 쪽이 맞아 보이는지 한 줄로 적는다 —
  불변 1이 금지하는 것은 확정이지 판단이 아니다.
- **기존 코드를 쓰거나 옮기거나 지우는 것.** 이 스킬이 만드는 것은 확정받은 빈 패키지 자리뿐이고,
  거기에 도메인 코드를 지어 넣지 않는다. 부채 상환은 migrate, 삭제는 사용자다.
- **패키지를 만들고 `check_imports.py`를 다시 돌리지 않는 것**, 소스 루트를 관측 없이 가정하는 것.
- **대조하지 못한 축을 리포트에서 빼는 것.** 해석 실패·검사 생략·읽지 못한 소스·귀속 불신은 전부
  고지한다. "드리프트 없음"과 "대조하지 않음"은 다른 상태다.
- **미선언 프로젝트(frontend 등)를 드리프트로 올리는 것.** 스캔 범위는 선언된 프로젝트 경로
  안뿐이고, 범위 밖은 이름만 남긴다.
- **어느 컨텍스트에도 속하지 않는 조립·설정 코드를 "미선언 패키지"로 올리는 것.** 격리 검사도 그
  코드를 도메인 경계 밖으로 본다.
- **mtime으로 파생물의 신선도를 판정하는 것.** 근거는 내용 대조뿐이다.
- **`### 관계` 표의 행을 이 스킬이 여닫는 것.** 한 줄이 격리 검사를 영구히 끈다 — 근거를 남기는
  자리는 adr이다.
- **깨진 ADR 참조를 확인 없이 갈아 끼우는 것.** 근거가 사라진 참조가 새 파일명을 입는다.
- **다른 ADR 본문이 옛 ADR을 인용한 것을 드리프트로 올리는 것.** 양방향 링크가 그 독자를 현재
  결정으로 데려간다.
- **파생물을 SSOT 대신 고치도록 유도하는 것**, 짝 없는 마커에 닫는 마커를 끼워 넣어 남의 서술을
  생성 구역 안에 가두는 것.
- **`docs/superdomain/state/baseline.jsonl`을 읽거나 쓰는 것.** 동결은 init, 축소는 migrate다.
- **게이트를 통과시키려고 사용자가 결정한 값을 바꾸는 것.** 고쳐도 되는 것은 형식뿐이다.
- **들어올 때 깨져 있던 선언을 사용자 확인 없이 고쳐 놓고 통과했다고 보고하는 것.**
- **무시한 항목을 파일로 억제하는 것.** 캐시를 만들지 않는다 — 다음 실행에 다시 올라오는 것이
  정상이고, 항구적 정당화는 ADR이다.
- **위반을 검사하는 것.** 이 스킬은 규칙 위반을 판정하지 않는다 — 그것은 `check_imports`·
  `check_invariants`·`/superdomain:review`의 몫이고, 여기서 겹쳐 돌리면 같은 지적이 두 리포트에
  오른다. 1단계에서 가져가는 것은 침묵 층위 넷뿐이다.
