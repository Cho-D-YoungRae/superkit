# 동결된 격리 위반을 점진 상환

이 스킬은 **부채를 줄이는 유일한 경로**다. init이 동결하고 `check_imports.py`가 읽기만 하는
`docs/superdomain/state/baseline.jsonl`을 실제로 축소하는 권한은 여기 하나뿐이다. 그 권한이 잘못 쓰이면
래칫이 거꾸로 돌고, 그 순간 이 플러그인의 보장이 통째로 사라진다. 그래서 불변이 넷이다.

1. **한 번에 한 클러스터.** 계획도 하나, 승인도 하나, 수행도 하나다. 빅뱅 리팩터링 계획을 제시하지
   않고, 한 클러스터를 끝냈다고 다음으로 **자동으로 넘어가지 않는다** — 연속해서 두 개를 하려면
   승인도 두 번 받는다. 이것은 판단을 아끼라는 뜻이 아니다: 클러스터 경계와 순서를 근거와 함께
   **적극적으로 제안**하는 것이 이 스킬의 일이고, 금지는 확인 없는 **착수** 하나뿐이다.
2. **줄이는 근거는 실측된 해소 하나뿐이다.** 항목을 지우는 이유가 "고쳤으니 됐을 것"이면 그것은
   축소가 아니라 은폐다. 6단계의 두 실행이 근거이고, 근거가 없으면 항목은 남는다.
   **예외처럼 보이는 갈래가 하나 있다** — `### 관계` 표가 그 쌍을 열어 위반 자체가 사라진 경우다.
   그때도 실측은 그대로 하되, 보고에는 "코드로 갚았다"가 아니라 **"관계를 열어 허용했다"**고
   적는다(2단계). 두 사실을 뭉뚱그리면 다음 사람이 부채 그래프를 잘못 읽는다.
3. **이동은 위반을 옮기는 것이 아니라 없애는 것이다.** 경계를 넘는 참조를 그대로 둔 채 파일만
   상대 컨텍스트로 옮기면 방향만 뒤집힌 같은 위반이 되고, baseline이 덮지 않는 **새 경로의
   신규 위반**이 된다. 그 상태는 진척이 아니라 후퇴다.
4. **`DOMAIN.md`를 고치지 않는다.** 분류·패키지 라벨도, `### 관계` 표의 행도 이 스킬의 편집 범위
   밖이다 — 쌍을 여는 결정은 `/superdomain:adr`이 근거를 남기고 편집 자리를 짚으며, 경계 자체를
   다시 긋는 것은 `/superdomain:init`이다.

## 지식 참조 프로토콜

지식이 필요하면 **먼저 `${CLAUDE_PLUGIN_ROOT}/references/INDEX.md`를 읽고** 필요한 문서만 연다.
`knowledge/`를 통째로 또는 디렉터리 단위로 읽는 것은 금지다. 고르는 기준은 셋이다.

- **경계를 넘는 결합을 어떻게 끊는가**의 정본은 `strategic/context-mapping.md`다 — 관계 유형의
  정의와 안티패턴, 그리고 관계 표가 참조의 allow-list라는 사실이 거기 있다. 이 스킬이 매 클러스터
  읽는 문서는 이것 하나다.
- **이번 클러스터가 실제로 건드리는 주제** — INDEX의 `read_when`에 `migrate`가 붙은 문서가

  컨텍스트가 `- 패턴:`으로 선언한 문서가 있으면 그 key의 문서도.
- 대상 프로젝트의 `docs/superdomain/conventions/` 문서. 같은 주제면 **로컬이 이긴다.**

## 0. 위치·게이트·조기 종료

```bash
git rev-parse --show-toplevel
ls -l docs/superdomain/state/baseline.jsonl
```

git 루트가 작업 기준이다. `DOMAIN.md`가 없으면 아래를 알리고 **중단**한다.

> superdomain이 초기화되지 않았습니다. `/superdomain:init`으로 도메인 경계 선언을 먼저 세우세요.

**`docs/superdomain/state/baseline.jsonl`의 존재가 이 스킬의 입장 조건 전부다.** 선언에는 부채를 가리키는
라벨이 없다 — 파일이 있으면 동결된 부채가 있는 것이고, 없으면 없는 것이다. 세 지점(init의 동결,
`check_imports.py`의 강등, 이 스킬의 축소)이 같은 경로 하나를 본다.

| 상태 | 처분 |
|---|---|
| 파일 없음 | **"동결된 부채가 없습니다"**로 종료. 정상 상태다 — 그 프로젝트는 격리 위반 없이 출발했거나 동결하지 않기로 했다. 지금 위반이 있는지는 `check_imports.py`가 답하고, 동결할지는 `/superdomain:init`이 정한다(**이 스킬은 동결하지 않는다**) |
| 파일 있고 항목 있음 | 1단계로 |
| 파일 있는데 빈 줄뿐 | 갚을 것이 없는데 래칫이 있는 척하는 상태다. **7단계(상환 종료)로 바로 간다** — 이 경로의 완료 ADR은 "갚은 클러스터 0"이므로, 무엇이 왜 0이었는지(동결 시점부터 비어 있었는지, 다른 경로로 해소됐는지)를 사용자에게 확인해 7-b의 재료로 넘긴다 |

- **파일이 없을 때 한 번 더 본다.** 구판에서 넘어온 저장소는 `baseline.jsonl`을 다른 자리에 갖고
  있을 수 있고, 그러면 `check_imports.py`가 그것을 읽지 않아 **동결분이 통째로 신규 위반으로
  올라오는데** 이 스킬은 "부채 없음"으로 끝난다. 두 리포트가 정반대를 말하는 상태다.

  ```bash
  find docs -name baseline.jsonl 2>/dev/null
  ```

  **`2>/dev/null`을 빠뜨리지 않는다** — 이 명령이 도는 조건은 "새 경로에 파일이 없음"이고, 그때
  `docs/` 자체가 없는 것이 흔하다(동결한 적 없는 프로젝트). 그대로 두면 정상 경로에서 오류 문면과
  exit 1이 나와 사용자가 실패로 읽는다.

  히트가 있으면 그 경로를 그대로 보여주고 **위 경로로 옮길지 묻는다.** 파일 이동뿐이지만 래칫의
  근거를 바꾸는 일이므로 확정을 받는다. 옮겼으면 0단계부터 다시 시작한다.

## 1. 입력 — 선언·현재 판정·동결 목록

세 개를 함께 놓아야 "무엇이 아직 살아 있는 부채인가"가 나온다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/parse_domain.py" docs/superdomain/DOMAIN.md
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_imports.py" docs/superdomain/DOMAIN.md --json
cat -n docs/superdomain/state/baseline.jsonl
```

- **`parse_domain.py`가 exit 1이면 멈춘다.** stderr의 `경로:라인: 메시지`를 그대로 보여준다. 깨진
  선언 위에서 코드를 옮기면 무엇이 경계였는지가 사라진다. 고치는 것은 이 스킬의 일이 아니다
  (exit 2는 사용법 오류 — 인자를 고쳐 다시 돌린다). exit 0이면 `DOMAIN.md`를 직접 읽어 컨텍스트
  이름·`- 패키지:`·`### 관계` 표를 손에 쥔다. **컨텍스트 패키지가 2·5단계의 목표 자리를 정한다.**
- **`check_imports.py`의 exit 2는 baseline이 깨졌다는 뜻일 수 있다**(1은 "위반 발견"이라는 정상
  판정이다). stderr가 `docs/superdomain/state/baseline.jsonl:<줄>: …`을 지목하면 **그 줄을 고치는 것이 이번
  세션의 첫 작업**이다(재작성 권한은 이 스킬에 있다). 적용하는 것은 6-b의 **재작성 형식 규율**
  뿐이다 — 한 줄 JSON, (rule, path) 정렬, 남길 줄은 원문 그대로. 6-b의 "지우는 것은 6-a에서 부재를
  확인한 항목뿐"은 여기 걸리지 않는다: 그 문장은 해소를 근거로 한 축소를 규율하고, 여기서 다루는
  것은 읽을 수 없게 된 줄이다. 원문 줄을 그대로 보여주고 무엇이 의도였는지 확인받은 뒤에 고친다.
  **지어내지 않는다** — 한 줄이 깨지면 어느 위반이 동결분인지 전체를 알 수 없다는 것이 exit 2의
  이유다. 판단이 서지 않으면 **그 줄을 지우는 쪽이 안전하다**(항목이 빠지면 그 위반은 신규 위반으로
  올라오므로 래칫은 조여질 뿐 풀리지 않는다). 그것도 사용자 확정 사항이다.
- **살아 있는 부채는 `baseline.demoted[]`다**(각 항목은 `path`·`line`·`rule_id`·`message`).
  `baseline.entries`(동결 항목 수)와 건수가 다른 것은 정상이고, 이유가 둘이다.

| 어긋남 | 뜻 |
|---|---|
| `demoted` 건수 > 매칭 항목 수 | 매칭 키가 (규칙 id, 경로)뿐이라 **한 항목이 같은 파일의 추가 위반까지 덮는다**(푸터의 한계 줄이 그렇게 고지한다) |
| 항목이 `demoted`에 없다 | 해소됐거나, **이번 실행이 그 파일을 판정하지 않았다** |

**미매칭 항목을 "해소됨"으로 단정하지 않는다.** 그것이 이 스킬이 가장 쉽게 저지를 수 있는 거짓
축소다. 판정하지 못한 실행을 가려내는 자리는 같은 JSON 안에 넷이다.

| 채널 | 뜻 |
|---|---|
| `skipped[]` | 검사가 아예 서지 않았다 — 프로젝트 경로 부재·경로가 파일·소스 전부 읽기 실패·소스 0건 |
| `zero_match[]` | 그 컨텍스트 패키지에 귀속된 소스가 0건이다(`[0건 경고]`) |
| `unreadable[]` | 소스를 읽지 못했다(인코딩·권한) |
| `ambiguous_package[]` | `package` 선언이 2건 이상이라 **그 파일의 귀속을 믿을 수 없다** — 검사가 스스로 판정을 부인한 상태다 |

대상이 여기 걸려 있으면 그 실행은 **아무 말도 하지 않은 것**이다. 특히 `ambiguous_package[]`의
경로가 baseline 항목의 `path`와 겹치면 그 항목의 판정은 처음부터 흔들린다 — 클러스터에 넣기 전에
고지하고, 처분은 6-a 4항이 정한다.

**다섯째 갈래는 그 JSON 밖에 있다 — 이 검사가 다루지 않는 규칙 id.** 지금 이 플러그인이 검사하는
규칙은 `derived.context-isolation` 하나뿐이다(정본: `scripts/check_imports.py`의 `RULE_ID`).
baseline 항목의 `rule` 값이 그것이 아니면 **그 항목은 어떤 실행에서도 매칭되지 않고, 코드를 아무리
고쳐도 해소를 실측할 방법이 없다.** 구판에서 넘어온 잔재가 전형이다. 형식만 보면 6-a를 통과하는
것처럼 보이는 착시이므로, **미판정으로 다루어 축소하지 않고 사용자에게 고지한다** — 그 항목이
무엇을 동결한 것이었는지 원문 줄을 그대로 보여주고 처분(그대로 두기 / 지우기)을 받는다.
`check_imports --json`의 `checked`는 **건수뿐이라 규칙 이름을 주지 않으므로** 이 대조는 항목의
`rule` 값을 직접 읽어야만 성립한다.

`violations[]`(= baseline이 덮지 않는 신규 위반)가 이미 차 있으면 그 사실을 먼저 보고한다. 상환보다
신규 위반이 급하고, 6-a의 "새 위반 0" 판정에도 출발 스냅샷이 필요하다.

## 2. 클러스터링 — 컨텍스트 쌍 하나가 클러스터 하나다

부채의 종류는 컨텍스트 격리 위반 하나뿐이므로, 묶는 축도 하나다. **클러스터 = 컨텍스트 쌍(A↔B).**

**방향을 구분하지 않는다.** 관계 표의 허용 단위가 쌍이라 A→B와 B→A는 같은 한 줄로 열리고 같은
한 줄로 닫힌다 — 두 방향을 따로 계획하면 한쪽만 갚은 상태에서 "그 쌍은 끝났다"는 잘못된 판정이
나온다.

쌍은 위반 메시지가 그대로 말해 준다 — `컨텍스트 '<출발>'가 다른 컨텍스트 '<도착>'의 코드를 직접
참조합니다`. `demoted[].message`에서 두 이름을 읽어 **정렬한 순서 없는 쌍**으로 만들고, 두 이름이
1단계에서 읽은 선언 목록에 실재하는지 대조한다. **선언에 없는 이름이 나오면 비슷한 것에 끼워
맞추지 않는다** — 그대로 고지하고 그 항목은 클러스터에 넣지 않는다.

지킬 규율:

- **처방이 둘로 갈린다 — 그것을 먼저 판정한다.** 격리 위반은 코드가 경계를 무시한 것일 수도, 그
  결합이 실제로 필요한데 `### 관계` 표에 없는 것일 수도 있다. 후자라면 할 일은 **갚는 것이 아니라
  여는 것**이고, 그 결정은 ADR이 필수이며(`skills/adr/SKILL.md` 3-b — 쌍이 열리면 그 두 컨텍스트
  사이의 격리 검사가 영구히 꺼진다) 편집 자리는 adr 8단계가 짚는다. **이 스킬은 관계 표를 고치지
  않는다**(불변 4) — 열기로 했으면 그 클러스터를 계획에서 빼고 무엇을 넘기는지 명시해 adr로
  보낸다. 쌍이 열린 뒤 그 항목들이 `demoted[]`에서 사라지면 6단계 절차로 지우되, 8단계에는
  **"관계를 열어 허용했다"**고 적는다(불변 2).
- **클러스터는 프로젝트를 넘지 않는다.** `check_imports.py`는 선언된 전 컨텍스트를 한 목록으로
  놓고 귀속시키므로(`_scopes`) **프로젝트가 서로 다른 두 컨텍스트의 쌍도 실제로 나온다.** 그런
  쌍이 나오면 한 클러스터로 묶지 않는다 — 빌드 명령과 소스 루트가 프로젝트마다 다르고, 5-c의
  `cd "<프로젝트 경로>"`가 어느 쪽인지 정해지지 않아 컴파일 확인 자체가 성립하지 않는다. 그 쌍은
  **경계가 프로젝트를 가로지른다는 관측**으로 보고하고, 처분(어느 쪽으로 코드를 모을지, 관계를
  열지)은 `/superdomain:adr`·`/superdomain:init`으로 넘긴다.
- **한 항목이 여러 쌍에 걸칠 수 있다.** 한 파일이 두 컨텍스트를 각각 참조하면 그 파일의 baseline
  항목 하나가 두 클러스터에 나타난다. **클러스터는 작업 단위이고 항목 삭제 단위는 `(rule, path)`다**
  — 그 파일이 `demoted[]`에서 통째로 사라지기 전에는 이번 쌍을 다 갚았어도 항목을 지우지 않는다.
  그것을 판정하는 자리가 6-a 1항이다.
- **항목 1개 ≠ 위반 1건.** 클러스터 크기는 항목 수가 아니라 `demoted` 건수로 센다(1단계의 흡수 한계).
- **쌍이 커서 한 번에 못 하면 쪼개는 축은 컴파일 단위다.** 함께 옮기지 않으면 컴파일이 서지 않는
  파일들은 한 묶음이다 — 쪼개면 중간 상태가 빨강이라 확인 자체가 불가능하다. 쪼갰으면 **그 쌍은
  아직 끝나지 않았다**는 사실을 계획과 보고에 적는다.
- 클러스터마다 **한 문장 요약**을 붙인다("claim이 billing의 타입을 직접 쓰는 자리를 걷어낸다").
  요약이 한 문장으로 안 나오면 그 묶음은 아직 하나가 아니다.

## 3. 우선순위 — 근거를 붙여 제안한다

두 축을 쓴다: **자주 만지는 곳 먼저**(이득이 크다), **참조가 적은 쌍부터**(안전하다).

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/collect_signals.py" docs/superdomain/DOMAIN.md --json
```

- exit 0이면 `hotspots[]`(`path`·`commits`·`key` — 상위 20)와 `contexts[]`가 온도다. `key`는
  `"<프로젝트>:<컨텍스트>"` 꼴이다. 클러스터의 파일 경로를 `hotspots[].path`와 맞춰 본다. 창을
  좁히려면 `--since <rev|날짜>`.
- **상위 20 밖은 "차갑다"가 아니라 "이 창에서 20위 안에 못 들었다"이다.** `range.files`(창 안에서
  바뀐 전체 파일 수)와 나란히 읽는다.
- exit 1이면 신호를 만들지 못한 것이다(git 부재·비 저장소·창 안 커밋 0건·`DOMAIN.md` 해석 실패).
  stderr 사유를 그대로 보여주고 **핫스팟 축 없이** 진행하되, 순위의 근거가 하나 빠졌다는 사실을
  밝힌다. exit 2는 사용법 오류다.
- `notices`의 마지막 두 줄(한계·해석 고지)은 보고에 승계한다. **임계값은 이 스크립트에 없다** —
  "몇 건부터 핫스팟인가"를 여기서 발명하지 않는다.

**두 번째 축은 관측으로 정한다.** 그 쌍을 끊을 때 건드려야 할 곳이 적을수록 안전하다.
**두 번 돌린다 — 쌍은 방향이 없으므로 한 방향만 재면 얽힘을 절반만 본다.**

```bash
grep -rln '<B의 패키지 접두>' "<프로젝트 경로>" --include='*.kt' --include='*.java'   # A→B 후보
grep -rln '<A의 패키지 접두>' "<프로젝트 경로>" --include='*.kt' --include='*.java'   # B→A 후보
```

**두 수를 더해 쌍의 크기로 쓴다.** 한쪽만 세면 A→B 3건·B→A 40건인 쌍이 "얽힌 곳이 적다"로 읽혀
1순위를 잘못 권한다. `demoted[]`에서 그 쌍의 위반 건수와 그 위반이 걸린 파일 수도 방향별로 함께
센다 — 위 grep은 정당한 참조까지 세므로 둘을 나란히 놓아야 "이 쌍이 얼마나 깊이 얽혔는가"가 나온다.

두 축이 갈리면 **하나를 고르지 말고 표로 나란히 놓고 제안한다.** 둘 다 만족하는 클러스터가 있으면
그것이 1순위이고, 없으면 근거를 적어 하나를 권하되 **고르는 것은 사용자다.**

| 클러스터(쌍) | 항목/건수 | 핫스팟 | 참조 파일 수 | 근거 | 권고 |
|---|---|---|---|---|---|
| claim ↔ billing | 4 / 7 | `Claim.kt` 12커밋(1위) | 3 | 자주 바뀌고 얽힌 곳이 적다 | **1순위** |

## 4. 한 클러스터 계획 — 승인 게이트

**여기가 이 스킬의 유일한 진행 게이트다.** 계획에 담는 것은 아래 일곱이고, 전부 이번 클러스터의
것이다.

1. **대상 쌍과 baseline 항목** — `(rule, path)` 목록과 각 항목이 덮는 실제 위반 건수. 다른 쌍에도
   걸친 항목이 있으면 그 사실을 명시한다(6-a 1항이 걸린다).
2. **왜 이것이 먼저인가** — 3단계의 근거 두 줄.
3. **방법** — 경계를 넘는 참조를 무엇으로 대체하는가. 타입을 자기 컨텍스트 안에 번역해 두는가
   (부패 방지 계층), 이벤트로 갈라 비동기로 만드는가, 포트를 자기 쪽에 세우고 어댑터를 경계 밖으로
   내리는가, 애초에 잘못 놓인 코드를 제 컨텍스트로 되돌리는가. 고른 처방의 근거는
   `context-mapping.md`에서 읽어 인용한다. **"정리한다"는 방법이 아니다.**
4. **목표 자리** — 옮기거나 새로 만드는 타입이 어느 컨텍스트의 어느 패키지 아래 서는가. 자리는
   선언이 정한다(1단계의 `- 패키지:`). 손으로 조립하지 않는다.
5. **건드리는 파일과 예상 부수효과** — 공개 시그니처가 바뀌면 깨지는 호출자까지 세어 둔다.
6. **확인 방법** — 6단계의 두 실행(그리고 빌드 도구가 있으면 컴파일까지)을 그대로 적는다.
7. **하지 않는 것** — 이 클러스터 밖의 부채, 요청받지 않은 이름 정리·구조 개선.

규율:

- **두 번째 클러스터를 계획하지 않는다.** 남은 후보는 **목록까지**가 최대이고, 순서·방법·범위를
  적으면 그것이 빅뱅 계획이다.
- **"알아서 진행해 주세요"는 속도의 요청이지 전 클러스터 위임이 아니다**(정본:
  `skills/init/SKILL.md` 불변 1). 그 답을 받아도 클러스터 단위 승인은 그대로 받고, 대신 항목별
  확인을 빠르게 돈다.
- **계획이 커지면 쪼갠다.** 신호 셋: 파일 20개를 넘는다, 컴파일이 중간에 한 번도 초록이 될 수 없다,
  한 문장 요약이 나오지 않는다.
- 승인 없이는 **파일을 하나도 쓰지 않는다.**

## 5. 수행

### 5-a. 자리는 선언이 정한다

- 옮기거나 새로 세우는 타입은 그 컨텍스트의 `- 패키지:` 접두 **안**에 선다. 라벨이 없으면 규약
  기본값 `<기본 패키지>.<컨텍스트>..`가 그 자리다. 접두가 둘 이상이면 기존 타입이 어디 사는지
  관측해 **하나를 권하고 확정받는다.**
- 그 접두 아래에 하위 패키지를 새로 만드는 것은 이 클러스터의 일부다 — 파일을 옮기면 디렉터리가
  따라 생긴다.
- **컨텍스트 자체가 디스크에 없으면 이 스킬이 만들지 않는다.** 그것은 선언과 디스크의 드리프트이고
  처분은 `/superdomain:sync`다. 그쪽을 돌리고 오라고 안내한다.
- **새 컨텍스트를 세워 해결하는 처방은 상환이 아니라 `/superdomain:init`의 안건이다.** 경계·
  분류·패키지를 다시 정하는 인터뷰가 필요하다.

### 5-b. 코드 변경 — 위반을 없애는 변경만이 상환이다

- **참조를 그대로 데려가지 않는다.** 파일만 상대 컨텍스트로 옮기고 원래 컨텍스트의 타입을 계속
  import하면 방향만 뒤집힌 같은 위반이고, 그 파일은 새 경로에서 신규 위반이 된다(불변 3). 끊는
  방법은 4단계 3항에서 고른 처방이 정한다.
- **공개 시그니처를 바꿨으면 호출자를 맞추는 것까지가 이 클러스터다.** 범위는 **컴파일이 다시 서는
  데까지**이며, 그 김에 하는 리팩터링은 하지 않는다(`skills/apply/SKILL.md` 4-a와 같은 규율) —
  6-a의 "새 위반 0" 판정이 흐려진다.
- **여분 `package` 선언의 정리는 허용된다.** 대상 파일이 `ambiguous_package[]`에 올라 있으면 주석
  처리된 옛 선언이나 문자열 리터럴에 든 선언이 첫 매칭 자리를 차지하고 있다는 뜻이고, 그것을
  걷어내지 않으면 그 파일의 판정 자체가 서지 않는다(6-a 4항). 지우는 줄을 보여주고 확정받는다.
- **있는 파일을 확인 없이 덮지 않는다.** 목표 자리에 이미 파일이 있으면 `mktemp`로 새 내용을 만들어
  `diff -u`를 보여주고 확정받는다.
- **도메인 의미가 갈리는 자리에서는 멈춘다.** "이 두 타입은 같은 개념인가"는 이동으로 답할 문제가
  아니다. 그 자리에서 묻고, 즉답이 어려우면 그 부분을 클러스터에서 빼고 이유를 보고에 남긴다.
- **`DOMAIN.md`·domain 문서를 고치지 않는다.** 경계가 낡았다고 판단되면 그것은 상환이 아니라
  `/superdomain:adr`과 `/superdomain:init`의 안건이다.

### 5-c. 컴파일 초록을 먼저 본다

```bash
cd "<프로젝트 경로>" && ./gradlew build -x test        # 또는 그 프로젝트의 빌드 명령
```

`check_imports.py`는 import 방향과 이름만 본다 — **깨진 호출자는 그 검사를 통과하고 여기서만
잡힌다.** 돌리지 못했으면(빌드 스크립트 부재 등) 그 사실과 확인하지 못한 범위를 보고에 적는다.
돌린 척하지 않는다.

## 6. 해소 확인과 baseline 축소 — 순서가 뜻을 만든다

`check_imports.py`는 매칭 위반을 `[기존 부채]`로 강등해 exit 코드에서 뺀다. 그래서 **항목이 남아
있는 동안의 초록은 "갚았다"를 뜻하지 않는다.** 확인은 제거 앞뒤로 한 번씩, 순서대로 한다.

### 6-a. 제거 전 — 부재 확인

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_imports.py" docs/superdomain/DOMAIN.md --json
```

넷을 본다. 하나라도 어긋나면 **항목을 지우지 않고 5단계로 돌아간다.**

1. 대상 `(rule, path)`가 `baseline.demoted[]`에 **없어야** 한다. 남아 있으면 아직 위반이다.
   **여기서 보는 것은 쌍이 아니라 파일이다** — 그 파일이 다른 쌍의 위반도 갖고 있었다면 이번 쌍을
   다 갚아도 항목은 남고, 그것이 정상이다(매칭 키가 (규칙 id, 경로)뿐이라 항목을 지우는 순간 그
   파일의 **모든** 위반이 보호를 잃는다).
2. `violations[]`에 이번 변경이 만든 항목이 **0**이어야 한다. 있으면 위반을 옮긴 것이다(불변 3).
   1단계 스냅샷과 대조해 **이번에 생긴 것**만 센다.
3. 대상 규칙이 `skipped[]`·`zero_match[]`에 있거나 대상 경로가 `unreadable[]`에 있으면 **그 실행은
   판정하지 않았다.** "없다"가 "해소"가 아니라 "안 봤다"인 경우다 — 사유를 보고하고 멈춘다.
   항목의 `rule` 값이 `derived.context-isolation`이 아닐 때도 같다(1단계 다섯째 갈래).
4. **대상 경로가 `ambiguous_package[]`에 있으면 그 항목은 지우지 않는다.** 그 파일은 `package`
   선언이 2건 이상이라 **첫 선언으로 귀속**됐고, 검사가 스스로 "이 파일들의 판정은 믿을 수
   없습니다"라고 말한 상태다. 그러므로 `demoted[]`에 없다는 것이 "갚았다"가 아니라 **"엉뚱한
   컨텍스트로 귀속돼 위반이 나타나지 않았다"**일 수 있다 — 3항과 같은 부류(판정하지 않은 실행)이고,
   그 상태에서 지우면 이 스킬이 저지를 수 있는 가장 조용한 거짓 상환이 된다.
   **처방은 둘이고, 앞의 것이 기본이다.**
   ① **여분 선언을 걷어낸다** — 5-b가 허용한 대로 지우고 6-a를 다시 돌린다. 그 파일이 목록에서
   빠져야 1~3항의 판정이 비로소 성립한다.
   ② **걷어낼 수 없으면 원문을 읽고 귀속을 확정받는다.** 둘째 매칭이 실제 코드일 수 있다 —
   `RE_PACKAGE`는 `^\s*package\s+[\w.]+`라 raw string 안에서 줄머리에 놓인 `package …`(코드
   생성기 소스가 전형)도 잡는다. 그 파일과 **검사가 리포트에 찍은 첫 매칭 패키지**를 나란히
   보여주고 "이 파일이 그 컨텍스트 소유가 맞습니까"를 묻는다. **맞다고 확정받으면 1~3항의 판정이
   성립하므로 항목을 지울 수 있고**, 그 확정이 근거였다는 사실을 8단계에 적는다. 확정을 받지
   못하면 항목을 남기고 사유를 적는다. **이 갈래가 없으면 그런 파일의 항목은 영원히 지울 수 없어
   §7의 "남은 항목 0"이 서지 않는다.**

### 6-b. 축소 — 전체 재작성 (append 아님)

되돌릴 수단을 먼저 확보한다(`git status --short docs/superdomain/state/baseline.jsonl`로 커밋 여부를 확인하고,
커밋 전이면 `mktemp`로 사본을 뜬다). 그다음 파일을 **통째로 다시 쓴다.**

- 형식은 한 줄에 위반 하나, `{"rule": "<id>", "path": "<git 루트 상대>", "note": "<선택>"}`.
  정렬은 **(rule, path)**.
- **남길 줄은 원문 그대로 옮긴다** — `note`를 포함해 한 글자도 바꾸지 않는다.
- **지우는 것은 6-a에서 부재를 확인한 항목뿐이다.** 매칭되지 않았다는 이유만으로 지우지 않는다
  (1단계의 두 번째 어긋남).
- **항목을 새로 더하지 않는다.** 이번 작업이 만든 위반은 고칠 것이지 동결할 것이 아니다 — 동결은
  init의 권한이다.
- **`path`는 git 루트 기준 상대경로이고 구분자는 `/`다.** 로더는 그 값을 위반의 표시 경로와 글자
  그대로 대조하므로, 표기가 어긋난 줄은 아무것도 강등하지 못한 채 항목 수만 채운다.
- **남길 줄이 하나도 없으면 빈 파일을 쓰지 않는다.** 그대로 7단계로 간다.
- **건수를 인용한 파생물이 여기서 낡는다.** `docs/superdomain/summary.md`의 자유 서술이 동결 시점 건수를
  문장에 박아 두었으면 축소한 지금 그 문장은 거짓이고, 이 파일은 SessionStart 훅이 통째로 주입하는
  유일한 산출물이라 낡은 숫자가 매 세션 사실로 읽힌다. 불변 4에 따라 이 스킬이 고치지 않는다 —
  **`grep -n baseline docs/superdomain/summary.md`로 확인해 걸리면 새 건수와 함께 8단계 4항에 고지하고
  `/superdomain:sync`를 권한다**(자유 서술이라 sync도 기계 대조는 하지 않고 사용자 확인으로
  넘긴다: sync 3-d).

### 6-c. 제거 후 — 보호가 걷힌 상태에서 다시 본다

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/check_imports.py" docs/superdomain/DOMAIN.md
```

이제 그 항목들은 보호받지 않는다. **대상이 신규 위반으로 살아나면 6-a가 착시였다는 뜻이므로
baseline을 되돌리고 5단계로 간다.** exit 2가 나면 재작성이 파일을 깨뜨린 것이다 — 지목된 줄을
고친다. 남은 부채의 푸터 건수(`기존 부채 N건 …`)가 예상만큼 줄었는지도 여기서 읽는다.

- **여기서 처음 드러나는 위반이 있다.** 항목 하나가 그 파일의 모든 위반을 덮고 있었으므로, 지운
  순간 이번에 손대지 않은 참조까지 함께 보호를 잃는다. **그것은 이번 변경이 만든 것이 아니다** —
  6-a 1항이 걸렀어야 할 경우이므로, 나타났다면 그 파일이 `demoted[]`에 남아 있었는데 놓친 것이거나
  귀속이 흔들린 것이다(4항). 되돌리고 사유를 찾는다.
- **이 검사가 보지 못하는 위반은 여전히 보지 못한다** — 같은 패키지 안의 참조와 import 없이 쓰는
  완전 수식 이름(FQN)이다. 푸터의 한계 줄을 그대로 승계한다. **부채가 줄었다는 주장은 이 검사가
  보는 범위 안에서만 참이다.**

## 7. baseline이 비었다 — 상환 종료는 두 개가 한 묶음이다

남은 항목이 0이면 아래 둘을 **함께** 한다. 하나만 하면 상태가 어긋난다: 파일만 지우고 ADR을 쓰지
않으면 왜 부채가 사라졌는지 근거가 남지 않고, ADR만 쓰고 파일을 두면 `check_imports.py`가 계속
강등한다(그 파일의 존재가 곧 부채 선언이다).

**둘을 한 묶음으로 먼저 확정받는다.** 7-a의 `git rm`이 앞에 오지만 확정은 여기서 한 번에 받는다 —
파일 삭제와 상환 완료 ADR을 나란히 보여주고 "이 둘을 지금 함께 진행합니까"를 묻는다.

### 7-a. 파일을 지운다 — 빈 파일로 두지 않는다

```bash
git rm docs/superdomain/state/baseline.jsonl     # 커밋 전이면 rm
```

빈 baseline은 래칫이 있는 척하는 상태다. `check_imports.py`는 **파일 존재만으로** 강등 채널과
푸터의 매칭 한계 고지를 켜므로, 아무것도 강등하지 않는 파일 하나 때문에 매 실행 리포트에 읽는
사람이 확인할 수 없는 줄이 붙는다.

**`DOMAIN.md`에서 지울 것은 없다.** 부채를 가리키는 라벨이 선언에 없기 때문이다 — 이 스킬이 SSOT를
건드리지 않는 이유이자(불변 4), 활성 조건을 파일 존재 하나로 둔 이유다.

### 7-b. 상환 완료 ADR — `/superdomain:adr` 경유

**이 스킬이 ADR을 직접 쓰지 않는다.** 파일명(날짜 + slug)·형식·상태 전이의 정본은 그 스킬과
`${CLAUDE_PLUGIN_ROOT}/references/governance/adr-template.md`다. 넘길 재료는 다섯이다.

- 갚은 컨텍스트 쌍 목록과 대상 프로젝트, 동결을 결정한 ADR이 있으면 그 파일명(`- 관련:`에 들어간다).
- 갚은 클러스터 수, 동결 당시 항목 수와 최종 0, 걸린 기간.
- 상환 중 실제로 내린 결정(부패 방지 계층 도입, 이벤트로의 분리, 포트 도입) — 그것 자체가 별도
  ADR감이면 그렇게 말한다. **관계를 열어 사라진 쌍이 있으면 그 사실과 해당 ADR 파일명을 함께**
  넘긴다(불변 2) — 갚은 것과 허용한 것은 다른 사실이다.
- 남은 사각: 이 검사가 보지 못하는 참조(같은 패키지 안의 참조·FQN), 돌리지 못한 게이트.
- **검토한 대안을 지어내지 않는다.** 상환 완료에는 보통 오간 대안이 없고, 그때 정답은 "검토한 대안
  없음"이다(`skills/adr/SKILL.md` 3-b). 없는 대안을 채우면 그것은 날조된 근거다.

## 8. 마무리 보고

1. **이번 클러스터** — 대상 쌍, 한 문장 요약, 승인받은 범위, 대상 항목 `(rule, path)` 목록.
2. **한 것 / 하지 않은 것** — 고친 파일, 맞춘 호출자, 그리고 **클러스터에서 뺀 것과 그 이유**.
   이 절을 비우지 않는다. 쌍을 쪼갰으면 **그 쌍이 아직 끝나지 않았다**는 사실도 여기 적는다.
3. **게이트 결과** — 5-c 컴파일, 6-a의 네 판정(부재·새 위반 0·미판정 채널·귀속 불신), 6-c 제거 후
   실행. 돌리지 못한 것은 그 사실과 확인 못 한 범위를 적는다.
4. **baseline 전후** — 항목 수와 `demoted` 건수를 각각, 지운 항목 목록, 남은 항목 수. **지운 근거를
   항목마다 셋 중 하나로 구분한다** — "코드로 갚음" / "관계를 열어 허용함"(불변 2) / "귀속을 사용자가
   확정해 판정이 성립함"(6-a 4항 ②). 승계할 고지는
   `check_imports` 푸터의 한계 두 줄과 `collect_signals`의 `notices` 마지막 두 줄이다. **건수를
   인용한 파생물이 낡았으면 그 사실과 `sync` 권유도 여기 적는다**(6-b).
5. **미판정으로 남긴 것** — `ambiguous_package` 때문에 지우지 못한 항목, 검사 대상이 아닌 규칙 id를
   가진 항목, `skipped`·`zero_match`에 걸린 컨텍스트. **이 절을 비우지 않는다.**
6. **남은 클러스터 후보** — **쌍 목록까지만.** 순서·방법·범위를 적으면 빅뱅 계획이다.
7. **커밋은 사용자가 한다.** 명령만 제안한다.

   ```bash
   git add <고친 파일들>       # 6-b에서 축소만 했으면 docs/superdomain/state/baseline.jsonl도 함께
   git commit -m "refactor: <컨텍스트 A> ↔ <컨텍스트 B> 직접 참조 제거 — baseline N건 해소"
   ```

   **7단계까지 갔으면 baseline 경로를 `git add`에 적지 않는다.** 7-a의 `git rm`이 삭제를 이미
   스테이징했고, 없는 경로를 `git add`에 넘기면 `fatal: pathspec … did not match any files`로
   **명령 전체가 실패해 고친 파일이 하나도 스테이징되지 않는다**(✅ 실측). 그 상태로 다음 줄을
   실행하면 **래칫 해제만 담긴 커밋**이 남고 상환 코드는 워킹트리에 남는다 — 그대로 push하면
   동결이 풀렸는데 해소가 없는 이력이 박힌다.

8. **다음 걸음** — 다음 클러스터는 **다시 불러야 시작된다.** 경계 자체가 낡아 보이면
   `/superdomain:evolve`, 의미론 검토는 `/superdomain:review`, 이번 변경으로 선언과 디스크가
   갈렸으면 `/superdomain:sync`다.

## 하지 말 것

- **한 번에 여러 클러스터를 계획하거나 수행하는 것.** 승인 하나에 클러스터 하나다. 끝냈다고 다음으로
  넘어가지 않는다.
- **빅뱅 리팩터링 계획을 제시하는 것.** 남은 후보는 쌍 목록까지이며 순서와 방법은 적지 않는다.
- **한 쌍을 방향별로 둘로 나누는 것.** 허용 단위가 쌍이라 A→B와 B→A는 한 줄로 열리고 한 줄로
  닫힌다 — 한쪽만 갚고 "그 쌍은 끝났다"고 적는 것이 그 실패의 결과다.
- **실측 없이 baseline 항목을 지우는 것.** 미매칭을 "해소됨"으로 읽는 것, 검사하지 않은 실행
  (`skipped`·`zero_match`·`unreadable`)의 침묵을 통과로 읽는 것, **`ambiguous_package`에 오른
  파일의 부재를 선언 정리도 사용자 확정도 없이 해소로 읽는 것** 전부 같은 실패다.
- **7단계까지 간 실행에서 `git add`에 baseline 경로를 남기는 것.** 명령 전체가 실패해 래칫 해제만
  담긴 커밋이 남는다(§8-7).
- **쌍의 한 방향만 재고 "얽힌 곳이 적다"고 권하는 것**, 프로젝트가 다른 두 컨텍스트를 한 클러스터로
  묶는 것.
- **이번 쌍을 갚았다는 이유로 다른 쌍의 위반이 남은 파일의 항목을 지우는 것.** 삭제 단위는
  `(rule, path)`이고 판정은 파일 전체에 대한 것이다.
- **관계를 열어 사라진 항목을 "코드로 갚았다"로 보고하는 것.** 두 사실은 다르다.
- **baseline에 항목을 더하는 것.** 이 스킬의 권한은 축소뿐이고 동결은 init이다.
- **위반을 새 경로로 옮겨 놓고 상환이라고 부르는 것.** 방향만 뒤집힌 위반은 진척이 아니라 후퇴다.
- **`DOMAIN.md`를 고치는 것** — `### 관계` 표의 행, 분류·패키지 라벨 전부. 쌍을 여는 결정은 adr,
  경계를 다시 긋는 것은 init이다.
- **domain 문서를 고쳐 검사를 통과시키는 것.**
- **선언에 없는 컨텍스트 자리를 손으로 만드는 것.** 그것은 sync의 드리프트 처분이고, 새 컨텍스트를
  세우는 것은 init이다.
- **요청받지 않은 리팩터링을 덤으로 하는 것.** 새 위반 판정이 흐려진다.
- **baseline 파일을 빈 채로 남기는 것**, 7단계의 둘 중 하나만 하는 것.
- **상환 완료 ADR의 대안을 지어내는 것**, ADR을 이 스킬이 직접 만들어 쓰는 것.
- **`knowledge/`를 통째로 또는 디렉터리 단위로 읽는 것.** 언제나 INDEX 경유 선별 로드다.
- **자동으로 커밋하는 것.**
