# 도메인 정의

`docs/superdomain/DOMAIN.md` 한 파일에 도메인마다 역할·기능·분류·코드 위치를 적고, 도메인 사이의 관계를 표로 적는다. 사람과 Claude가 같은 도메인 그림을 보게 하는 것이 목적이다.

**핵심 원칙:** 판단은 근거와 함께 적극적으로 제안하고, 확정은 사용자가 한다. 질문은 한 번에 하나만 한다(한꺼번에 물으면 답이 섞이거나 빠진다).

DOMAIN.md 형식과 경계·분류 판단 기준은 `${CLAUDE_SKILL_DIR}/domain-guide.md`에 있다.

## 체크리스트

작업 기준은 git 루트다(`git rev-parse --show-toplevel`). 아래 단계마다 할 일을 만들고 순서대로 끝낸다.

1. **맥락 파악**: 지침 파일(AGENTS.md·CLAUDE.md), README, 모듈·패키지 구조, 최근 커밋을 읽는다. `docs/superdomain/DOMAIN.md`가 있으면 그 파일도 읽고 아래 "수정 모드"로 간다. 코드가 없으면 제품이 무엇을 하는지부터 묻는다.
2. **기준 읽기**: `${CLAUDE_SKILL_DIR}/domain-guide.md`를 읽는다.
3. **질문**: 한 번에 하나씩 묻는다. 가능하면 선택지를 주고 추천을 맨 앞에 둔다. 목적은 도메인의 역할·기능·경계·관계와 외부 접점을 확정하는 것이다. 기능마다 정책도 정한다: 취소·환불 때 무엇을 되돌리는지, 수정·삭제가 되는지와 그 기한, 유효기간·한도, 중복·어뷰징을 어떻게 막는지. 정책은 기능마다 따로 묻지 않고, 도메인마다 초안을 먼저 제안해 한 번에 확인받는다(예: "주문을 취소하면 쿠폰과 포인트를 되돌린다 — 맞나요?"). 돈·상태·재화가 걸린 기능부터 다룬다. 정한 것 중 핵심은 `규칙`에, 정하지 못한 것은 `미정`에 적는다.
4. **도메인 목록 제안**: 후보마다 가이드의 경계 기준에 비춘 근거를 붙여 제안하고 확인받는다. 기존 코드가 있으면 패키지 구조에서 읽은 후보부터 보여 준다. 외부 시스템을 부르거나 외부에서 호출받는 코드(외부 API 클라이언트·SDK·웹훅 수신)도 찾아, 어느 후보가 외부 접점인지 함께 보여 준다. 중심 도메인 후보가 여럿이면(예: 상품 중심이냐 주문 중심이냐) 경계를 두세 가지로 그려 보여 주고, 이 제품에서 무엇이 더 중요한지로 고르게 한다.
5. **섹션별 작성**: 도메인마다 역할·기능·분류·코드(선택: 개념·외부·규칙·미정·하지 않는 것)를 보여 주고 확인받는다. 외부 시스템과 맞닿은 도메인이면 `외부`를 빠뜨리지 않는다. `개념`은 도메인 안에 개념이 여럿이라 알아야 할 것을 추려 둘 필요가 있을 때만 제안한다. 이어서 관계 표를 보여 주고 확인받는다.
   - 방향은 가이드의 "관계의 방향"대로 제안한다(중심·내부 도메인이 의존받고, 외부 접점 도메인과 흐름의 뒤 단계가 의존한다). 두 도메인이 서로 의존하면 한 방향을 정하고, 반대 흐름은 이벤트나 배치로 바꾸자고 제안한다.
   - 모든 도메인이 의존하는 것처럼 보이는 도메인이 있으면 정말 기반 도메인인지 사용자에게 묻는다. 맞다고 확인받은 뒤에만 `모든 도메인이 참조` 한 줄로 적는다.
6. **저장 후 자체 검토**: `docs/superdomain/DOMAIN.md`에 쓴 뒤 domain-reviewer를 정의 검토 모드로 호출한다(아래 "자체 검토 호출"). 지적 중 무엇을 반영할지 사용자와 정해 고친다.
7. **사용자 검토**: 파일을 검토해 달라고 요청하고, 고칠 곳이 있으면 반영한다.
8. **후속 제안**
   - 도메인 분리·병합이나 경계 변경처럼 비싸거나 중요한 결정이 있었으면 `/superdomain:adr`로 기록하자고 제안한다. 4단계에서 중심 도메인을 고른 이유도 여기에 든다.
   - 아래 포인터 줄 중 대상 지침 파일에 없는 줄을 추가할지 묻고, 동의하면 추가한다. 대상 지침 파일은 프로젝트 루트의 AGENTS.md다. 루트에 CLAUDE.md나 `.claude/CLAUDE.md`가 있으면 그 파일이다(그때 Claude Code는 AGENTS.md를 읽지 않는다). 대상 파일이 없으면 만들지 않고 줄을 제안만 한다. `@import`는 쓰지 않는다(매 세션 파일 전체를 불러온다).

     ```
     - 도메인 정의: docs/superdomain/DOMAIN.md (도메인의 역할·관계를 바꾸는 작업 전에 읽는다)
     - 결정 기록: docs/superdomain/adr/ (비싸거나 중요한 결정을 내린 작업을 마치면 /superdomain:adr로 기록할지 제안한다)
     ```

## 수정 모드

1. 무엇을 바꿀지 확인한다(추가·분리·병합·이름 변경·관계 변경·외부 접점 변경).
2. `${CLAUDE_SKILL_DIR}/domain-guide.md`를 읽고, 바뀌는 부분의 전·후를 나란히 보여 주고 확인받는다. 관계를 바꾸면 한 방향인지, 방향이 가이드의 기준과 맞는지 확인하고(양방향이면 이벤트·배치로 바꾸자고 제안한다), 외부 시스템과 맞닿게 되거나 떨어지면 `외부`도 함께 고친다.
3. 반영한다.
4. 도메인을 추가·분리·병합했거나 관계·`외부`를 바꿨으면 체크리스트 6단계의 자체 검토를 한다.
5. 체크리스트 8단계의 후속 제안을 한다.

## 자체 검토 호출

Agent 도구로 `superdomain:domain-reviewer`를 호출한다. `model`은 지정하지 않는다(에이전트 파일에 정해져 있다). 세션 대화는 넘기지 않고 아래만 넘긴다.

```
모드: 정의 검토
프로젝트 루트: <절대 경로>
DOMAIN.md: <절대 경로>
기준 문서: ${CLAUDE_SKILL_DIR}/domain-guide.md
```

## 하지 않는 것

- 사용자 확인 없이 DOMAIN.md를 쓰거나 고치지 않는다.
- 코드를 쓰거나 패키지·디렉터리를 만들지 않는다.
- "알아서 해 달라"는 요청에도 근거와 함께 하나를 제안하고, 동의를 받은 뒤에 적는다.
