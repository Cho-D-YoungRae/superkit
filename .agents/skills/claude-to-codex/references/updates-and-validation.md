# 갱신과 검증

전환은 원본 기준 단방향이다. Codex용 동작 설계는 재사용 가능한 기록으로 유지한다. 해시 비교는 변경을 찾을 뿐 충돌을 해결하거나 의미적 호환성을 증명하지 않는다.

## 기준 상태

사용자가 지정한 기존 구조를 우선한다. superkit 기본 기록 위치 `codex/porting/<name>/`는 배포 패키지 밖이며 다음 파일을 둔다:

- `decisions.md`: 원본/대상 경로와 ID·버전, 목표 클라이언트/배포 표면, 확인한 공식 URL·날짜, 컴포넌트 대응표, Codex 전용 수정의 이유, 한계, 검증 명령과 결과, 독립 리뷰 결과·지적별 조치·미검증 항목
- `source-state.json`: 완료 판단 후 확정한 원본 파일 상태
- `managed-paths.json`: 이 전환이 생성·관리하는 **대상 상대 파일 경로**의 JSON 배열
- `target-state.json`: 검증과 필요한 독립 리뷰를 마친 관리 파일 상태

Git commit ID도 기록할 수 있지만 dirty/untracked 변경은 파일 상태로 구별한다. 상태 파일에 원본의 본문·시크릿을 복사하지 않는다. 파일 해시와 실행 비트는 `scripts/tree_state.py`로 계산한다. 이 스크립트는 파일을 수정하지 않고 JSON만 stdout으로 출력한다. 파일 키는 루트 기준 상대 경로이며, 심볼릭 링크의 대상 문자열에는 절대 경로가 포함될 수 있으므로 공유 전 확인한다.

```bash
python3 <skill-dir>/scripts/tree_state.py snapshot <source-root>
python3 <skill-dir>/scripts/tree_state.py compare <records>/source-state.json <source-root>
python3 <skill-dir>/scripts/tree_state.py compare <records>/target-state.json <target-root>
python3 <skill-dir>/scripts/tree_state.py snapshot <target-root> --paths-file <records>/managed-paths.json
```

실행할 때 꺾쇠 자리를 실제 경로로 바꾸고 공백이 있는 경로를 인용한다. 결과를 해당 상태 파일에 저장한다. **비교 전에 기준 파일을 덮어쓰지 않는다.** 새 원본 상태는 작업 시작 때 임시 보관하고, 종료 때 다시 비교해 전환 도중 변경되지 않았는지 확인한다.

도구는 Python 표준 라이브러리만 사용한다. `.git`, `.venv`, `node_modules`, `__pycache__`, `.pytest_cache` 디렉터리는 제외한다. 별도 경로를 선택하지 않으면 그 외 파일을 모두 해시하므로 원본 **플러그인** 루트를 지정한다. 링크는 대상 문자열만 기록하며 따라가지 않는다. 기록된 링크가 외부를 가리키거나 생성물에서 깨지면 별도로 해결한다. 특수 파일·읽기 실패·잘못된 상태는 exit 2로 처리한다. 차이가 있어도 정상 비교는 exit 0이다.

대상 비교는 관리 파일 기준과 **현재 전체 대상**을 대조하므로 사용자 추가 파일이 `added`에 반복해서 나올 수 있다. `managed-paths.json`과 대조해 관리 목록 밖 파일을 분리한다. 원본과 관리 파일에 변화가 없고 이런 사용자 파일만 `added`라면 재생성할 필요가 없다. 이 차이를 없애려고 사용자 파일을 관리 목록에 넣지 않는다.

기존 전환본에 기준 기록이 없다면 현재 파일들을 읽고 원본과의 대응을 먼저 파악한다. 기존 대상 디렉터리를 통째로 생성 파일로 간주하거나 현재 상태를 무검토로 첫 기준에 편입하지 않는다.

## 변경 적용

대응표를 이용해 변경된 원본이 영향을 주는 대상 파일·호출자·템플릿을 결정한다. 본문, 이름, 트리거, 권한, 경로, 의존성, 생성 스키마 변경을 모두 본다.

| 비교 결과 | 처리 |
|---|---|
| 원본 변경 없음, 대상도 기준과 동일 | 재생성 불필요. 새 지원 환경이나 변환 규칙 변경이 요청된 경우만 재검토한다. |
| 원본 변경, 대상 기준과 동일 | 영향 있는 파일을 갱신하고 기존 Codex 전용 결정을 보존한다. |
| 대상만 수정/삭제됨 | 사용자 변경으로 취급한다. 보존하고 알린다. 임의로 복구하거나 새 기준으로 승인하지 않는다. |
| 원본과 대응 대상 둘 다 변경 | 구체적인 겹침을 검토한다. 명백히 독립적인 변경은 병합하되 의미가 충돌하면 선택을 묻는다. 관계없는 갱신은 계속한다. |
| 원본 파일 삭제 | 그 파일에만 의존하는 관리 대상인지, 현재 대상 해시가 기준과 같은지 확인한 뒤 제거한다. 수정된 파일은 보존하고 충돌로 보고한다. |
| 새 대상 파일과 기존 파일 충돌 | 기존 파일을 읽고 소유권·내용을 확인한다. 마커/기록 없는 파일을 자동 덮어쓰지 않는다. |
| 관리 목록에 없는 대상 파일 | 기본적으로 사용자 파일이다. 보존하며 관리 목록에 몰래 편입하지 않는다. |

해시에는 과거 본문이 없으므로 실제 3-way merge가 필요하면 기록한 Git revision이나 보관된 원본/대상 파일을 사용한다. 과거 본문이 없을 때 재생성한 결과를 과거 본문인 것처럼 쓰지 않는다. 대상을 통째로 지운 뒤 복사하는 방식은 사용하지 않는다.

충돌 미해결 상태에서는 이전 기준 파일을 유지한다. 부분 진행과 남은 충돌을 `decisions.md`에 기록하고, 전체 원본을 반영했다는 새 기준으로 덮어쓰지 않는다. [독립 리뷰와 완료 기준](reviewer.md)을 충족한 뒤 관리 목록과 두 상태를 갱신한다. 검토 중인 스냅샷은 임시 후보로 보관하며 기존 기준 파일과 구분한다. 날짜는 확인/검증이 실제로 바뀐 경우만 갱신한다.

## 검증 단계

### 파일과 패키지

- 원본 내용과 버전이 작업 전후 같은지 확인한다.
- JSON/YAML/TOML을 실제 파서로 검사하고, 대상 manifest 형식의 현재 스키마와 경로 규칙을 확인한다. 원본 `claude plugin validate` 결과는 Codex 유효성 검사가 아니다.
- 각 스킬의 frontmatter·이름·설명·호출 정책, 링크와 실행 파일의 존재, 실행 비트, 패키지 밖 링크를 확인한다.
- 남은 Claude 도구/변수/경로 참조는 **사용 맥락별로** 검토한다. 호환 훅 변수, 기존 데이터 경로, 출처 설명까지 무조건 금지하지 않는다.
- 새 패키지용 설치 설명은 그 패키지의 구조와 맞아야 한다. 루트 카탈로그가 없는 파일 경로를 설치 ID처럼 안내하지 않는다.

### 독립성·행동

임시 디렉터리에 대상 패키지만 복사하고 원본을 참조하지 않는 상태로 리소스 접근과 안전한 헬퍼 실행을 확인한다. 필요한 외부 런타임은 명시한다.

컴포넌트별로 실제로 관찰할 결과를 선택한다:

- 명시적 호출 스킬은 자동 선택되지 않고, 보조 스킬은 필요한 워크플로에서 사용되는가
- 별도 에이전트가 필요한 자료만 받고 정해진 결과를 돌려주는가; 필요한 제한이 실제 적용되는가
- 훅의 정상/실패/무관 이벤트 fixture에서 출력과 차단 여부가 맞는가
- 생성한 프로젝트 스킬이 발견되고, 플러그인 없이 필요한 작업을 수행할 수 있는가
- 원본 수정 후 갱신이 반영되고, 두 번째 실행이 불필요한 diff를 만들지 않는가
- 수정된 대상 파일·사용자 추가 파일·원본에서 삭제된 파일을 의도대로 처리하는가

외부 배포·인프라 변경·실제 시크릿을 사용하는 테스트는 이 전환 요청만으로 실행하지 않는다. 자동 발견·에이전트 등록·훅 신뢰는 실제 클라이언트에서 확인해야 한다. 실행할 수 없다면 미검증 항목과 재현 절차를 남긴다. 텍스트에 해당 지시가 존재한다는 검사는 런타임 검증을 대신하지 않는다.

이 스킬 자체의 보조 도구 검증:

```bash
python3 -m unittest discover -s <skill-dir>/tests -q
```

스킬 형식 검사는 사용 가능한 skill-creator의 `scripts/quick_validate.py`를 이용한다. 이 도구가 없다고 임의의 개인 설치 경로를 하드코딩하지 않는다. 도구가 없거나 의존성 누락으로 실행할 수 없으면, 사용 가능한 실제 YAML 파서와 링크·스캐폴드 잔여물 검사로 대체하고 방법을 보고한다.
