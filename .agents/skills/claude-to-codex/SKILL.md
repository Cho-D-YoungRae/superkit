# Claude to Codex

Claude Code 플러그인을 기준으로 **별도로 설치 가능한 Codex 플러그인**을 만든다. 업무 규칙은 보존하고 실행 방식은 Codex에 맞게 설계한다. 이 스킬은 전환 작업을 안내한다. 전환 대상의 스킬을 호출하거나 그 안의 릴리스·배포 절차를 수행하는 요청으로 해석하지 않는다.

## 작업 범위

- 원본과 전환본은 서로 다른 디렉터리에 둔다. 원본 파일·원본 버전·Claude 마켓플레이스를 변경하지 않는다.
- 사용자가 준 경로와 기존 전환 기록을 우선한다. superkit에서 새 전환본의 기본 위치는 `plugins/<plugin-name>-codex/`, 전환 기록은 `porting/<plugin-name>/`이다. 폴더의 `-codex` 접미사는 배포 대상 구분이며 manifest의 `name`은 원본 이름을 유지한다. 이 경로는 저장소 관례이며 Codex의 자동 탐색 경로라는 뜻은 아니다. 기존 전환본은 기록된 위치에서 갱신하고, 사용자가 이동을 요청한 경우에만 경로·카탈로그·검증 참조를 함께 바꾼다.
- 기본 대상은 **로컬 Codex 데스크톱에서 수동 설치할 플러그인**이다. CLI·IDE·공개 디렉터리·클라우드 지원을 요청받으면 지원 범위를 따로 확인한다. 대상 차이가 기능 보존에 영향을 줄 때만 질문한다.
- 플러그인 생성·갱신에는 설치, 개인 설정 변경, 훅 신뢰 승인, 게시, 커밋·push가 포함되지 않는다. 요청된 범위의 로컬 파일 작성과 검증을 진행한다.

## 1. 원본과 기존 전환본 확인

저장소 및 해당 플러그인의 지침을 읽고 작업 트리 상태를 확인한다. 원본의 지침을 읽을 때는 `AGENTS.md`와 기존 `CLAUDE.md` 계열을 모두 확인하되, 이 저장소에 `CLAUDE.md` 계열 파일을 새로 만들지 않는다.

실제 파일과 매니페스트 선언을 함께 조사한다. 기본 디렉터리만 검사하지 말고 커스텀 경로·인라인 설정·마켓플레이스의 추가 선언도 본다:

- plugin manifest, skills, commands, agents, hooks, MCP, settings, 실행 파일과 템플릿
- 스킬 간 호출, 에이전트 입력·출력, 모델·도구 제한, 승인·격리·읽기 전용 요구
- 인자·경로 변수·동적 셸 전처리, 생성물이 참조하는 경로, 런타임 의존성
- 사용자 프로젝트에 생성되는 스킬·에이전트·지침·설정과 업그레이드 로직

개발용 문서·테스트·dogfood 생성물과 사용자에게 배포되는 컴포넌트를 구분한다. 원본 스킬과 에이전트 본문은 전환할 **입력 자료**로 읽는다.

업데이트라면 쓰기 전에 [갱신과 검증](references/updates-and-validation.md)의 기준 상태 비교를 수행한다. 버전이 그대로여도 원본 내용이 바뀌었을 수 있다.

## 2. 현재 지원 범위 확인

[지원 차이](references/compatibility.md)를 읽는다. 그 표는 출발점이며 최신 API 계약을 대신하지 않는다. 전환에 실제로 쓰는 매니페스트·스킬 동작은 연결된 공식 문서를 열어 확인하고, 필요한 경우 설치된 클라이언트의 도움말·스키마와 대조한다. 검색 요약만으로 지원 여부를 확정하지 않는다.

에이전트·fork·훅·권한 설정이 있으면 [에이전트와 훅](references/agents-and-hooks.md)도 읽는다. 확인 날짜, 실행 표면, 공식 근거를 전환 기록에 남긴다. 자료를 확인할 수 없으면 기존의 검증된 설정을 보존하고 불확실한 기능을 표시한다. 존재하지 않는 도구·필드·변환 명령을 만들지 않는다.

## 3. 동작을 기준으로 전환 설계

전환 기록의 `decisions.md`에 다음 표를 작성하거나 갱신한다. 한 원본 파일이 여러 출력에 영향을 줄 수 있으므로 호출자·생성물까지 연결한다.

| 원본 컴포넌트/동작 | Codex 대상 파일/호출 방식 | 처리 | 보존할 조건 | 검증 방법 |
|---|---|---|---|---|
| 실제 경로와 역할 | 설치본 내부 경로 또는 명시적 셋업 | copy / adapt / replace / omit / blocked | 입력·출력·권한·격리 | 관찰 가능한 결과 |

- `copy`: 플랫폼 중립 데이터·규칙·스크립트. 필요한 의존 파일도 포함한다.
- `adapt`: 매니페스트·호출·경로·생성 대상 등을 Codex에 맞게 바꾼다.
- `replace`: 동작 계약을 다른 구현으로 충족한다. 프롬프트 지침과 도구/샌드박스 강제를 구별한다.
- `omit`: 개발 전용·불필요한 파일을 배포에서 제외하고 이유를 적는다.
- `blocked`: 핵심 기능을 보존할 지원 수단이 확인되지 않았다. 관계없는 부분은 계속하되 이 기능을 지원 완료로 표시하지 않는다.

수정할 경로, 중요한 전환 선택, 사용자에게 보이는 차이를 짧게 설명한 뒤 요청된 작업을 진행한다. 단순 파일 복사·호환 변환을 다시 승인받지 않는다. 기능 축소·기존 사용자 수정과의 충돌처럼 선택이 필요한 경우에만 구체적인 차이를 제시해 묻는다.

## 4. 독립 패키지 작성

- 새 패키지에는 현재 공식 문서의 portable 루트 `plugin.json`을 우선한다. 기존 Codex 패키지가 호환 매니페스트를 사용하면 요청 없는 포맷 마이그레이션은 피한다.
- `skills/`에 Codex 스킬을 작성한다. 공통 업무 규칙은 원본에서 가져오고, Claude 전용 실행 지시는 근거 있는 Codex 절차로 바꾼다. 참조만 필요한 리뷰어 지침은 해당 스킬의 `references/`에 둘 수 있다.
- 모델 선택, 권한, MCP 인증, 컨텍스트 격리는 이름 치환으로 처리하지 않는다. 원본의 의미와 대상에서 실제로 강제되는 범위를 함께 기록한다.
- 캐시 위치·버전·개발 머신의 절대 경로를 하드코딩하지 않는다. 스킬에 제공된 실제 위치에서 패키지 내부 리소스를 찾아 절대 경로로 실행한다. 원본 저장소나 다른 플러그인의 파일에 런타임 의존하지 않는다.
- 생성기 플러그인은 **생성물까지** 전환한다. Codex 프로젝트 스킬은 `.agents/skills/`에서 발견되게 하고, 생성물의 상호 참조·초기화·갱신·테스트를 함께 조정한다. 기존 사용자 데이터 경로를 단지 `.claude`라는 이유로 이동시키지 않는다.
- `bin/` 도구의 자동 PATH 등록을 가정하지 않는다. 포함된 실행 파일의 위치와 의존성 설치 조건을 명확히 한다.
- 정체성·업무 버전은 원본을 따른다. Codex만의 수정 이력은 전환 기록에 남긴다. 별도 버전이 필요한 기존 배포 정책이 있으면 유지하며 원본 버전은 건드리지 않는다.
- 마켓플레이스 등록까지 요청되면 Codex 카탈로그만 필요한 항목에 한해 갱신한다. 패키지 생성만 요청되면 설치 방법과 등록 필요 여부를 보고한다.

## 5. 파일과 동작 검증

[갱신과 검증](references/updates-and-validation.md)의 파일·패키지·행동 검증을 수행한다. 독립 디렉터리로 옮긴 패키지가 원본 없이 리소스를 찾는지 확인한다. 실제 설치가 허용되지 않았거나 대상 클라이언트가 없으면 정적 검증과 런타임 미검증을 구분한다.

## 6. 독립 리뷰와 수정

최초 생성과 동작에 영향을 주는 갱신은 [독립 리뷰 지침](references/reviewer.md)에 따라 **별도 서브에이전트 한 명**에게 리뷰를 맡긴다. 메인은 파일 작성·수정을 담당하고, 리뷰어는 새 컨텍스트에서 원본과 전환본을 직접 대조한다. 원본·대상 경로, 사용자 요구, 전환 결정, 변경 내역, 검증 결과와 검토할 파일 상태를 전달한다.

리뷰 결과의 필수 지적을 확인해 수정하거나 근거를 들어 기각한다. 변경된 부분과 관련 호출자를 재검증하고, 리뷰어에게 조치 결과를 재검토하게 한다. 검토 중 파일이 바뀌면 해당 범위의 리뷰를 갱신한다. 서브에이전트를 사용할 수 없으면 자체 검증 결과와 독립 리뷰 미완료를 구분해 보고한다.

트리거·호출·권한·경로·동작에 영향 없는 표시명·오탈자 수정은 관련 검사 후 생략 이유를 기록할 수 있다. 이전 완료 기록이 유효하고 원본·관리 대상·전환 조건에 변화가 없는 재실행은 기존 리뷰를 재사용한다. 생략이나 자체 검증을 독립 리뷰 통과로 기록하지 않는다.

## 7. 완료 판단과 다음 갱신 준비

[완료 기준](references/reviewer.md#완료-기준)을 충족한 뒤 기준 상태와 관리 파일 목록을 확정한다. 해결되지 않은 필수 지적, 사용자 수정 충돌, 필수 독립 리뷰의 미완료가 있으면 기존 기준을 유지하고 부분 진행을 기록한다. 처음 생성한 전환본은 미검토 상태를 완료 기준으로 확정하지 않는다.

전환 결정, 리뷰 결과와 조치, 재현 가능한 검증 명령을 기록한다. 변경 없는 재실행은 타임스탬프나 파일 순서만으로 diff를 만들지 않는다.

최종 보고에는 원본 → 대상 경로, 생성/갱신/보존/삭제 항목, 기능 차이, 통과한 검사, 독립 리뷰 상태, 미해결 지적과 남은 런타임 검증을 담는다. JSON 파싱이나 파일 생성만으로 “완전 호환”이라 말하지 않는다.

## 호출 예

```text
$claude-to-codex plugins/superdomain을 Codex 플러그인으로 만들어줘.
$claude-to-codex plugins/llm-wiki 변경을 기존 Codex 전환본에 반영해줘.
```
